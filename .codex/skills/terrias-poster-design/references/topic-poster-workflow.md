# Topic Poster Workflow

## Content and composition

Read current content and approved user copy before grouping poster topics.
A character, pack, mode or mechanic can be one coherent topic even when it spans
several documents. Select a stable series title and a topic-specific subtitle.
Verify names, effects, availability and feature claims against current sources.

Use exact Chinese copy in a concise hierarchy. Describe the intended placement,
reading order and relationship between text and imagery. Avoid filling the
poster with implementation details or unexplained internal IDs.

Reference images define recognizable characters, subjects or style. Label each
reference's role; do not ask for a collage or literal compositing unless that
is the requested design.

## Generation capability

Use the active imagegen skill/tool and its documented input mechanism.
Ordinary image generation uses the built-in capability when available and does
not require an API key. A named CLI/API/model or logged-in ChatGPT workflow
follows the user's existing choice and the current tool instructions.

Do not embed a local username, bundled CLI installation path, provider-specific
size flag or historical API parameter in the project workflow. Size and quality
are design requirements; verify which current capability can deliver them.

Use [the prompt template](poster-prompt-template.md) for requested content
and composition. The template does not select a provider.

## Review and delivery

Check every visible name and text block, subject identity, hierarchy, unintended
extra figures, unwanted UI artifacts and actual natural dimensions. If text
cannot be rendered accurately, propose or use an already-authorized composition
workflow that preserves exact copy; do not silently alter the wording.

Save the prompt and original generated image under docs/Terrias/Posters.
A delivery-size derivative must preserve the accepted composition; record any
resizing separately from generation. Preserve earlier accepted outputs unless
replacement was requested. Show the current result and state material remaining
visual issues.

A poster is complete when the requested content is legible, the design has been
visually inspected and the usable deliverables are saved in the workspace.
