# 自建卡牌编辑器

状态：首版实现已接入生产模块。自动化验证记录见文末；真实游戏和联机验收尚未执行。

## 产品约定

- 妙妙工具提供独立的设计稿库、可视化效果编辑、像素卡面和免费制作。
- 制作不消耗货币，不设原版效果点数预算。卡牌自身费用、类型、稀有度和标签属于作品属性。
- 效果使用纵向嵌套积木和参数表单：顺序、条件/否则、重复、逐个对象、数值/对象变量和原生效果。
- 数值位置支持常量、战斗数据、算术、取整、上下限；条件支持比较、存在、状态、与/或/非。
- 默认在步骤执行时读取数据；“记住”显式捕获当时的值。当前遍历对象只在所属子流程可用。
- 设计稿是编辑依据；生成的 Lua 可查看、导出，不把修改后的任意脚本反向当作可视化设计稿。
- 错误草稿可保存，错误阻止制作；错误消息定位到规则/积木。
- 制作产生独立原生 DataConfig/RawData 和独立卡面版本；以后编辑、删除设计稿不修改成品。
- 像素绘制沿用现有工坊操作，扩展画布尺寸和固定图案模板。模板修改可撤销。

## 首版入口与能力

入口为妙妙工具 → 游戏体验 → 自建卡牌。编辑器是按需打开的工具，没有影响成品执行的总开关。

- 基本属性、效果积木、像素卡面、卡牌预览、试算、生成脚本六页；宽窗口保留右侧实时预览，窄窗口自动换行。
- 三个直接时机：抽到、使用、丢弃；三个使用后本场监听：回合开始、回合结束、受到生命伤害。
- 监听按每次使用独立建立，可分别设置本场和每回合次数；触发条件失败不消耗次数。护盾完全抵挡的伤害不触发原生 Hurt。
- 12 种战斗数据，6 类积木，比较与布尔组合、四则运算、最值、取整及范围约束。
- 数值在步骤执行时读取；所有原生效果的最终数量向下取整，描述同步显示取整规则。重复次数必须为整数。
- 32/64/128 像素源画布，沿用 32 色色板；6 个像素模板，3 个原生固定卡面，底图导入转色板，撤销/重做和缩放。
- 卡面以像素数据随作品导出；原生卡牌 RawData 携带像素数据与模板回退，不携带作者机器绝对路径。
- 在 DataConfig.RestoreData / PreCompileScripts 边界生成内容哈希命名的 256×256 PNG，仅修改恢复后的本机 Icon；由原生仓库、保险箱、战斗和焚毁流程加载。
- 草稿库使用共享配置存储和修订检查；关闭编辑窗口自动保存有修改的草稿。保存失败时普通关闭保留窗口。

复杂度限制用于运行可用性：最多 12 组规则、256 个积木/表达式、12 层嵌套；重复最多 64 次，单次牌堆操作最多 64 张，一条执行流程最多 4096 步。这些不是效果点数或货币预算。

## 原生证据

对照 `开发参考资料/反编译文件夹v1.0.24831968`；Witch.dll SHA256
`CD829F84F5A52A6B53973C676BF3DF4618A15F479A23BBA35B82E6802C6CDC83`，
Witch.Core.dll SHA256 `EDE56686110573070F9E062C8EFC51AC9D60E2AFD9B436590A028B72FDC06295`，
均匹配当前仓库 Managed。

- CardEditorUI.GenerateCard：结构化属性和 Lua 脚本压缩进 Vars.RawData。
- DataConfig.RestoreData：从 RawData 恢复完整数据；InstanceID 标识成品实例。
- HouseManager.OnClickCardEditor：原生制作结果写入 GameRuntimeData.CardData，然后 Save。
- ScriptExecutor：Object/Target/status 为可变执行上下文；目标选择不能隐式泄露到下一个块。
- IStatusManager：CurHp/MaxHp/Defend/GetBuff 是对象数据；能量和手牌接口具有本地玩家归属。
- AddCardByDeck/GetDeckUIToAction：选牌异步完成，依赖其结果的步骤必须从完成回调继续。
- AddEvent：按对象身份注册，EventDispose.OnFightEnd 清理。事件功能必须明确激活时机、作用期限、次数和叠加规则。
- ICard：部分表面加载 Sprite，战斗表面可能加载 Texture；卡面验收覆盖两者。

## 正确性边界

1. 版本化的结构化文档通过类型、范围、作用域、资源依赖和复杂度检查后生成脚本。
2. 编译器只发出受支持的原生调用和受控 Lua 结构；名称和资源引用作为字符串转义。
3. 制作前使用游戏 Lua 环境加载检查全部生成脚本，不执行战斗效果来做预览。
4. 试算是可见的模拟数据输入和执行轨迹，不把试算结果冒充真实战斗验证。
5. 重复和嵌套执行具有运行预算；无效数值、缺失对象、异步取消必须具有明确结果，不能悄悄改用其他目标。
6. 保留原生伤害/状态路径；不能为试算或生成脚本绕过游戏联机权威。
7. 导入包含结构化稿件与卡面；不依赖作者机器上的绝对文件路径。

## 验收

- 条件两分支、短路逻辑、嵌套作用域、取整/除零、对象筛选、随机和重复。
- 生成 Lua 的解析及可执行语义测试；错误定位、资源缺失和未来文档版本。
- 图案模板、尺寸变化、描画/填充/吸色、撤销重做、关闭重开和导入导出。
- 妙妙工具真实入口、长内容、窄窗口、滚动/焦点和模态关闭。
- 制作不扣货币；保存失败不留下假成功；成品读档、取出、抽到/使用/丢弃。
- 监听与异步完成在死亡、战斗结束、再次使用和联机下正确清理。
- 自绘卡面在仓库/手牌/原生不同渲染表面和远端的显示。
