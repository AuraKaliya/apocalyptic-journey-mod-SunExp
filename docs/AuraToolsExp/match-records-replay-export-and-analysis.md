# AuraToolsExp 对局记录、导出与牌局分析

## 功能边界

- `对局记录` 是 DPT 统计、结构化对局回放、牌局分析和媒体回放的统一入口。
- 自动记录默认关闭；收藏对局不受自动记录数量上限影响。
- 对局记录设置中的 DPT 只提供总开关；展示方式、统计范围和统计阵营由冒险内 DPT 面板独立控制。回放演出节奏固定为 `Standard`，不再提供全局切换项。
- 结构化回放是权威数据。视频是派生媒体，不能替代结构化回放的数据完整性与可分析性。
- 牌局分析只陈述已观测事实，不生成缺少候选行动数据支撑的反事实决策建议。

## 数据存储

`MatchRecords.sqlite3` 使用以下独立数据面：

- `battle_records`：对局元数据、初始战斗状态和 DPT 快照。
- `replay_chunks`：按目标大小压缩的结构化回放事件。
- `match_analysis`：可重新生成、带校验值的事实分析报告。
- `replay_media`：视频路径、文件哈希、格式和回合时间轴，不保存视频二进制。

媒体文件位于数据库同级的 `Media/<record-id>/`。删除对局、清空分类或自动淘汰记录时，对应媒体目录会一并删除。

## 结构化回放协议 v8

v8 是只读的状态投影与表现编排协议，不保存、反序列化或重新执行战斗命令。播放时使用原生战斗场景作为视图载体，但不会重新运行卡牌脚本、Buff 脚本、AI、随机数、RPC 或战斗行动队列。

- `TurnFrame`：回合编号、当前行动者和该回合的完整状态基线。
- `ActionFrame`：一张卡牌、一个技能或一个敌方意图对应一个权威动作帧，包含最终状态增量、来源展示数据、按实例 ID 记录的卡牌迁移、动作/受击/数值等表现提示和分析语义。新录制会额外保存原生动作状态、效果名、效果延迟、表现持续时间以及逐目标的受击/防御状态；未声明 `enemy-intent-frames.v1` 或 `remote-player-actions.v1` 的旧 v8 记录继续以状态变化降级播放。
- `SeekCheckpoint`：周期性完整状态，用于从最近位置恢复；两次检查点之间只应用状态增量。
- 结果语义：伤害、治疗、护盾、Buff、能量与生死状态直接由动作前后的权威快照生成，不依赖命令钩子的覆盖率。
- 状态投影：生命、护盾、能量、Buff、手牌和卡堆由记录数据直接覆盖，不以当前运行环境重新计算。Buff 只绘制图标与层数，不创建会执行脚本的 `BuffItem`。
- 手牌投影：普通动作按稳定卡牌实例 ID 增量复用现有 `CardItem`；只有牌面内容变化的实例才重新绑定展示，未变化实例保留原对象和牌面。完整销毁重建只发生在首次加载和定位恢复。位置、间距和弧度复用原生 `CardContainer.UpdateCardItemPos`，底部回放工具栏闲置后自动收起并保留窄条唤出，不再反向挤压手牌位置。
- 卡牌表现：只有 `CardUse` 使用回放专用的短时卡牌展示与去向动画，不调用原生带固定等待尾部的出牌协程。
- 技能表现：`SkillUse` 只点亮并脉冲原生 `FightUI` 技能槽，不创建 `CardItem`，也不调用会执行 `InitScript` 或注册战斗输入的 `SkillItem.Init`。
- 敌方意图：录制以 `OtherObj.DoOneAction` 的单次敌方行动为边界，保存行动敌人、意图、原生图标槽、目标、动作和结果。播放只把已记录的意图计划投影到 `StatusManager.actionObj`，不会调用 `OtherObj.SetAction`、`ObjectAction.ActionExecute`、敌方 AI 或 `ObjectCard.UseCard`。多敌人和单敌人多意图按动作帧原顺序播放，意图不会进入中央卡牌或玩家手牌。
- 角色表现：录制在原生 `FightUI.CallActionAnimation` 消耗命中反应前，只读捕获它的表现输入与时序；播放按记录延迟效果、向原生动画队列提交 `AnimationData` 并调用 `DOActionAnimation`，不调用脚本执行器、目标选择、RPC 或 `FightManager` 行动事件。
- 联机队友动作：录制只观察游戏已解码的远端 `UseCard`、`ActionAnimation` 与后续权威状态同步，把公开卡牌、行动者、原生动作/目标和最终状态合并为同一个动作帧。不会发送额外战斗命令，也不会推断或保存队友未公开的手牌。

敌方动作先宣告并消耗当前意图，再启动原生 Attack/Skill 动作；生命、护盾、Buff 和手牌等结果在记录的结果提示偏移处投影，而不是在动作开始时立即跳变。定位恢复会取消未完成的宣告和动画，使用检查点中的敌方意图计划直接恢复对应图标槽。

拖动进度条会取消当前卡牌/角色表现、清理被动 HUD、恢复最近检查点、静默应用后续增量，再绘制目标帧；重复拖到同一位置必须得到相同状态。动作内的卡牌展示、角色动作、受击和 Buff/状态变化并行启动，固定间隔只存在于两个动作帧之间。顶部行动者提示随动作帧中的行动者切换，回合编号以记录中的 `TurnIndex` 为准。

进入回放前会先关闭资料库、`SettingUI` 和工具自有弹窗，并等待对应 GameObject 实际销毁；退出回放时则等待控制栏、战斗 UI、本地 Mirror Server/Client 和回放网络对象完成清理，再恢复 Lobby、菜单与输入状态。最终诊断同时记录网络状态和鼠标位置的顶层 Raycast 命中对象。关闭中的原生 UI 射线只做可恢复租借，不再永久禁用组件。

录制期间只在卡牌、技能和逐个敌方意图动作边界复制只读状态；不再挂接每条战斗命令，也不进行 JSON/GZip/SHA 分块工作。对局结束后，分块压缩、完整性校验、分析生成和 SQLite 写入由有界后台任务完成，避免影响战斗帧率。

分析界面的回合、卡牌和关键节点均保存事件序号，可直接跳转到结构化回放中的对应位置。

## `.aurareplay` 回放包

回放包是 ZIP 容器，包含清单、对局元数据、分析报告、分块索引和结构化回放块。导入时会验证：

- 格式与包版本。
- 元数据、分析和每个事件块的 SHA-256。
- 事件数量、块索引唯一性、入口路径与解压后总大小。

导入记录默认进入收藏对局；发生 ID 冲突时生成新的本地记录 ID。视频不会进入回放包，避免包体积随派生媒体膨胀。

## 视频导出

导出器会先完整关闭设置、对局资料库与分析界面，确认 `FightUI` 已稳定后才开始取帧。录制范围只包含战斗场景；“战斗 HUD”开关控制是否保留血条、手牌与回合按钮，不会把妙妙工具、设置界面、导出控制条或返回主菜单过程录入视频。

启用音频时，回放事件、画面取帧和音频统一使用 Unity DSP 实时时钟；渲染偶尔跟不上目标帧率时会补齐最新战斗帧，从而保持固定帧率和音画时长一致。关闭音频后仍使用固定时钟快速导出。取帧阶段按 Unity 截图纹理的 sRGB 标记匹配读写路径，避免对已经显示映射的画面再次做 gamma 编码；FFmpeg MP4 明确转换为 limited-range BT.709 `yuv420p`，避免播放器按错误色域或范围解释。内置编码器生成逐帧交织的 `MJPEG + PCM AVI`，配置 FFmpeg 时优先生成 MP4；两条路径都只保留最终视频，WAV 仅作为任务临时文件并在结束后清理。导出过程支持取消，并有准备、渲染、编码、完成、失败和取消状态。

生成视频会写入回合时间轴；模块内视频播放器因此支持上一回合和下一回合。手动导入的 mp4、avi、mov、m4v 或 webm 只有普通媒体控制，不伪造回合索引。

AVI 1.0 使用约 1.9 GB 的安全上限。超过上限时任务失败，但结构化回放和分析数据不受影响。

## 手工验证清单

1. 开启对局记录与自动回放，完成一场至少两回合、包含普通卡牌、攻击卡牌和角色技能的战斗；确认战斗过程没有可感知的周期卡顿。
2. 在对局记录中确认总览、回合、卡牌和关键节点数据，并从节点跳转回放；确认顶部行动者提示、回合编号、能量、生命、护盾、Buff 和完整手牌与记录一致。技能必须显示在左侧原生技能槽中，不能生成中央卡牌或进入手牌。
3. 导出 `.aurareplay`，删除原记录后重新导入，确认记录进入收藏并可分析、可回放。
4. 启动视频导出，确认进度条不进入画面；分别验证完成与取消路径。对比正常战斗与导出视频中的同一背景、角色和 UI 颜色，确认没有灰白、提亮或二次 gamma 痕迹；用媒体信息工具确认 MP4 为 BT.709 limited-range `yuv420p`。
5. 在媒体页播放 AVI，验证播放、暂停、拖动和回合跳转；再导入一个普通 mp4 验证无回合跳转状态。
6. 播放结束后反复拖到开头、中间动作和末尾，确认同一位置的状态哈希、手牌、Buff 与回合提示一致，且拖动不会重新启动战斗或新增脚本监听。
7. 删除视频、删除对局、清空自动记录，确认媒体文件随对应记录清理。
8. 在 16:9、16:10 和窗口化分辨率分别回放 1、6、10 张手牌的动作，确认手牌保持正常战斗的原生位置；底部工具栏无操作约 2.2 秒后自动收起，鼠标移入“回放控制”窄条后重新展开。
9. 对比同一段正常战斗与回放：检查角色的 Idle/Attack/Skill、敌人的 Hit/Defend、动作特效和声音时序；空 `Action` 的强化类技能必须保持 Idle，不得被默认改成攻击动作。
10. 从“妙妙工具”打开记录库并完成回放，返回游戏主界面后连续打开/关闭“妙妙工具”十次；确认界面正常弹出、鼠标可点击，并在日志中检查 `replay lifecycle terminal` 已显示 Server/Client 均关闭且没有回放控制栏残留。
11. 使用包含单敌人多意图和多敌人的战斗进行录制；确认玩家回合可见完整敌方意图，敌方回合依次出现意图宣告、敌人 Attack/Skill、目标 Hit/Defend、命中特效和结果变化，且生命值不会在命中前提前变化。
12. 回放敌方攻击后暂停、切换 0.5x/2x/4x 并反复定位到命中前后；确认意图槽、生命、护盾和 Buff 始终可重复恢复，分析页不会把敌方伤害归因给玩家上一张卡牌。
13. 双机联机时让主机与客机分别打出普通卡、攻击卡和角色技能，再分别导出两端记录；确认两份回放都按原顺序包含双方公开行动、角色动作、目标受击与最终状态，且没有生成或刷新队友私有手牌。
