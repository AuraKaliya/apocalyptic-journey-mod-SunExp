# AuraToolsExp 对局记录、导出与牌局分析

## 功能边界

- `对局记录` 是 DPT 统计、结构化对局回放、牌局分析和媒体回放的统一入口。
- 自动记录默认关闭；收藏对局不受自动记录数量上限影响。
- 结构化回放是权威数据。视频是派生媒体，不能替代结构化回放的数据完整性与可分析性。
- 牌局分析只陈述已观测事实，不生成缺少候选行动数据支撑的反事实决策建议。

## 数据存储

`MatchRecords.sqlite3` 使用以下独立数据面：

- `battle_records`：对局元数据、初始战斗状态和 DPT 快照。
- `replay_chunks`：按目标大小压缩的结构化回放事件。
- `match_analysis`：可重新生成、带校验值的事实分析报告。
- `replay_media`：视频路径、文件哈希、格式和回合时间轴，不保存视频二进制。

媒体文件位于数据库同级的 `Media/<record-id>/`。删除对局、清空分类或自动淘汰记录时，对应媒体目录会一并删除。

## 结构化回放协议 v2

每个原始命令事件保留可执行载荷，同时附带轻量语义：

- 出牌：行动者、卡牌 ID 和显示名。
- 伤害：来源、目标、伤害类型和数值。
- 目标命令：来源、目标和数据配置 ID。
- 状态快照：单位、生命、护盾和状态。

分析界面的回合、卡牌和关键节点均保存事件序号，可直接跳转到结构化回放中的对应位置。

## `.aurareplay` 回放包

回放包是 ZIP 容器，包含清单、对局元数据、分析报告、分块索引和原始回放块。导入时会验证：

- 格式与包版本。
- 元数据、分析和每个事件块的 SHA-256。
- 事件数量、块索引唯一性、入口路径与解压后总大小。

导入记录默认进入收藏对局；发生 ID 冲突时生成新的本地记录 ID。视频不会进入回放包，避免包体积随派生媒体膨胀。

## 视频导出

导出器以固定时钟重放结构化事件，录制 1280x720、30 FPS 的战斗 UI，并内置生成 `MJPEG + PCM AVI`，无需 FFmpeg。能够捕获全局音频时，同时保留一份 WAV。导出过程支持取消，并有准备、渲染、编码、完成、失败和取消状态。

生成视频会写入回合时间轴；模块内视频播放器因此支持上一回合和下一回合。手动导入的 mp4、avi、mov、m4v 或 webm 只有普通媒体控制，不伪造回合索引。

AVI 1.0 使用约 1.9 GB 的安全上限。超过上限时任务失败，但结构化回放和分析数据不受影响。

## 手工验证清单

1. 开启对局记录与自动回放，完成一场至少两回合且包含出牌和伤害的战斗。
2. 在对局记录中确认总览、回合、卡牌和关键节点数据，并从节点跳转回放。
3. 导出 `.aurareplay`，删除原记录后重新导入，确认记录进入收藏并可分析、可回放。
4. 启动视频导出，确认进度条不进入画面；分别验证完成与取消路径。
5. 在媒体页播放 AVI，验证播放、暂停、拖动和回合跳转；再导入一个普通 mp4 验证无回合跳转状态。
6. 删除视频、删除对局、清空自动记录，确认媒体文件随对应记录清理。
