注释报错的日志记录在 20:30:20.728。堆栈为 `CustomCardGraphEditor.Update → TextFocused → GameObject.GetComponentInParent`，异常来自 Unity 的原生对象空引用检查。当前 TextFocused 对 Unity 对象连续使用 `?.`；当原生 UI 对象已销毁而托管引用尚在时，这种检查不足以保护后续访问。Unity 官方文档明确解释了这种脱离原生对象的状态及 `?.` 的限制。[Unity Object 文档](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Object.html)

据此可以定位到焦点/视图销毁生命周期，而不能把错误归咎于注释的战斗逻辑。隔离检查也确认：在有效蓝图中增加注释，文档仍可编译，生成脚本不变。具体是哪个菜单控件留下焦点，需要在真实添加路径中复现确认。

下一次修复应覆盖：读取 EventSystem、选中对象和输入框之前使用 Unity 对象存活判断；销毁当前工具所属弹窗或视图前解除其焦点；完成后恢复到仍存活的画布或控件；取消拖拽时清理预览线和捕获。不能只吞异常，也不能无条件清空其他窗口的焦点。

生成脚本收进高级入口；节点参数随选择显示，不再把“参数”作为全局并列功能。作品库和蓝图库管理所有内容，另存副本和导出只作用于当前作品。撤销/重做属于当前编辑会话，应靠近被操作的工作区。

节点视觉采用明确的容器结构：标题栏、功能说明栏、执行接口区、数据接口区、状态区。系统名称为标题，类别用小标记，备注可单独显示。标题建议 16～18 像素，端口标签 14～16 像素，说明 12～14 像素；100% 缩放下先保证可读，低缩放逐级隐藏次要内容，不能依赖把所有文字一并缩小来显示全图。

画布使用低对比网格或点阵；节点必须有不透明且与画布区分的底板。保留工坊深蓝、金色的整体气质，节点内部以清晰的中性色正文和小面积类别色表达结构。普通、悬停、选中使用不同边界；选中不能伪装成“运行成功”。可以参考 [千星奇域官方编辑器指南](https://act.mihoyo.com/ys/ugc/tutorial) 的编辑器组织思路；本讨论稿不声称逐项复刻其节点和配色。

| 表达对象 | 建议表现 |
| --- | --- |
| 执行端口 | 明确方向的箭形标记；配执行标签 |
| 数值端口 | 圆形，附数量含义及单位 |

| 使用默认值 | 明示默认值，断线时也能看见实际来源 |
| 已连接输入 | 实心接口，默认编辑框退出当前输入来源；可查看来源节点 |
| 不允许连接 | 拖动预览与原因提示；不提交并破坏原连线 |

| 未接入流程 | 提示用途状态，保持文字可读 |
| 执行中/已经过 | 执行路径与节点状态提示，数据类型颜色保持稳定 |

注释是画布说明元素。它没有执行口、数据口、战斗效果和运行状态，不参与编译、执行排序或语义预算；可编辑文字、调整尺寸、移动和附着于一组节点。视觉采用独立注释样式，不能与“条件节点缺少输入”混为一谈。

连接合法性采用四层判断：端口类型兼容、节点语义允许、当前入口/作用域提供所需对象、数据来源确实先于使用点执行。基础类型相同不能代替后三项判断。数值转真假、单角色转集合、错误角色归属等转换不能悄悄发生。

每种节点都需要一张规范卡，至少记录：稳定类型身份、不可变系统名称、一句话功能、可出现的入口、执行输入及每个出口、数据输入及类型/单位/必填性/默认值、数据输出及作用域、何时读取或抽样、空对象和取消语义、副作用、数量上限、合法例子、非法例子、版本与迁移方式。界面说明、端口、属性面板、校验器和指导文档应来自同一份定义。

重点节点建议拆分如下；这是目标契约，尚未实施。

| 节点 | 执行接口 | 数据输入 | 数据输出 | 必须禁止 |
| --- | --- | --- | --- | --- |
| 随机选择一个敌人 | 执行 → 已选中 / 无可选目标 | 无对象输入；候选范围固定为合法敌方 | 选中的单个敌人，限成功分支 | 使用者或任意单角色覆盖候选范围 |
| 随机选择一个友方 | 执行 → 已选中 / 无可选目标 | 无任意对象输入；是否包括使用者必须明确标注 | 选中的单个友方 | 标题称友方、实际却改为随机敌人 |
| 从集合随机选择一个角色 | 执行 → 已选中 / 空集合 | 必填的角色集合 | 一个角色，限成功分支 | 单个角色直接接入集合口 |
| 记住对象 | 执行 → 完成 | 一个角色 | 本次执行中可复用的对象引用 | 把记住对象说成随机选择或冻结其全部属性 |
| 记住数值 | 执行 → 完成 | 一个数值 | 捕获时的数值 | 在捕获之前或另一入口引用 |

随机选择每执行一次抽样一次，多处读取同一结果不重复抽样；放在重复体内则每轮重新抽样。随机权威和结果应沿用经过验证的原生路径。没有合法候选时走明确的无目标分支，成功结果不允许在失败分支中使用。成功之后对象仍可能失效，后续操作要检查其有效性，不能换一个对象补执行。

“自己”建议显示为“使用者”，避免与卡牌本体混淆。使用者是固定输出的角色来源，不提供改变自身含义的对象选择器。使用时选中目标只对相应使用入口有效；抽到或丢弃流程不得引用它。所有敌人、所有友方、所有角色固定输出集合，属性面板不得显示单角色选项。集合被使用时读取，遍历开始后采用该次的集合快照。

数据读取按归属拆分。

| 读取能力 | 合理输入 | 输出与边界 |
| --- | --- | --- |
| 当前生命、上限、已损失生命、生命百分比、护盾 | 一个角色 | 步骤需要时读取；无效角色不假装读到零 |
| 指定状态层数 | 一个角色、有效状态资源 | 没有该状态为零层；资源不存在是错误 |
| 当前能量、能量上限 | 无任意角色口，明确属于使用者 | 数值 |
| 手牌、抽牌堆、弃牌堆数量 | 无任意角色口，明确属于使用者 | 整数数量 |
| 本牌基础费用 | 无角色口，明确属于本牌 | 基础费用，不冒充本次实际支付费用 |

效果节点的名字要与对象范围一致。泛用的护盾效果宜叫“给予护盾”或“增加护盾”，并提供目标；如果叫“使用者获得护盾”，则对象固定，不提供可替换角色口。造成伤害可以合法作用于自己，不能为纠正随机敌人节点而一概禁止自伤。

| 效果族 | 对象输入 | 其他输入与要求 |
| --- | --- | --- |
| 普通伤害、真实伤害、治疗、护盾、增加生命上限 | 一个角色；群体版本明确接受集合 | 非负数量，公开最终取整规则 |
| 施加已有状态 | 一个角色、已加载的状态引用 | 状态层数；不创建新 BUFF |
| 移除已有状态 | 一个角色、状态引用 | 明确移除整个状态，不暗示移除若干层 |
| 获得能量 | 固定使用者，无角色口 | 数量 |
| 抽牌、弃牌、焚毁手牌 | 固定使用者，无角色口 | 整数张数；涉及选择时有完成/取消语义 |
| 洗牌 | 固定使用者，无角色口 | 明确作用的牌堆 |
| 从抽牌堆/弃牌堆选牌入手 | 固定使用者，无角色口 | 整数张数、完成/取消；完成后才读取后续手牌数量 |
| 结束回合 | 固定使用者，无角色口 | 本次流程终止动作 |

数值与条件节点的参数名称应直接解释运算。加减乘除使用明确的操作数名称，除法标出除数；范围限制使用值/下限/上限；比较使用左值/比较值；与/或使用条件 A/条件 B。布尔组合短路执行，数字不隐式当作真假，动态除零定位到除法节点。

条件分支只执行一个子流程，完成出口在命中的子流程结束后执行一次。有限重复使用非负整数次数，零次直接完成；逐个对象输入集合，空集合直接完成，当前对象只在对应子流程可用。执行线和数据线都不允许任意环；所有循环及其空迭代也计入运行预算。

旧图迁移必须按实际行为识别。旧“随机选择一个敌人”如果接了外部对象，实际是对象捕获，应转为“记住对象”并解释旧命名问题；不能删除输入口后让原图突然变成随机选敌人。旧随机节点无外部输入时可迁向固定随机语义，但新增空目标分支可能改变后续流程，需要明确分析或提示修订。不得靠改显示名掩盖实际行为变化。

下一轮验收以逐节点契约矩阵为核心，不以累计断言数量代替覆盖说明。每项定义至少要验证正常输入、错误类型、错误语义对象、错误入口/作用域、未连接及默认值、空集合或失效对象、重复执行、异步完成/取消、复制与序列化、对应 UI 显示。固定随机节点、泛用随机节点、记住对象要分别有正反例。

界面验收还必须覆盖：实际游戏主题与预览一致；普通/选中/错误/执行状态；不同缩放下的可读性与端口命中；普通节点与注释从各合法入口添加；弹窗关闭后焦点；删除焦点对象；撤销重做；作品切换和关闭重开。首批视觉基准建议使用“使用时 → 随机敌人 → 伤害”和一条注释，先确认组件规范，再扩展到全部节点。
