文档：AuraToolsExp 自建卡牌蓝图迭代方案

日期：2026-09-17。状态：已据此实施 v2 蓝图迭代；本文保留设计背景与验收目标，实际实现及验证边界见 [自建卡牌编辑器](custom-card-editor-design.md)。真实游戏与联机验收尚未执行。

本轮将自建卡牌定义为：一个蓝图对应一张卡牌，由本牌的离散生命周期时点启动，完成一段有界的效果流程。编辑器、模板库、试算和制作使用同一份蓝图语义。

用户已经确认：支持抽到、使用、丢弃等本牌时点；不制作 BUFF、被动技能或持续监听逻辑；允许读取、施加和移除游戏已有状态，后续状态行为由原状态系统负责；采用节点蓝图并提供蓝图库。本文将“常用组合节点优先、允许展开为基础节点”作为设计默认，尚不视为用户对节点粒度的单独确认。

“一次性”指一次触发执行一次流程，不限制一张牌在不同次抽到、使用、丢弃时重新执行。生命读取和条件节点按执行需要求值，不主动检测生命变化。选牌、等待抽牌完成属于本次执行中的临时等待，不能演变为留在战斗中的常驻业务监听。

本轮的可观察完成条件是：玩家从模板或空白稿开始，能够连接本牌入口、对象、条件和效果；检查问题并定位；用模拟数据查看执行路径；保存、关闭、重开和导入导出；通过检查后制作原生卡牌；在游戏中按同样语义运行。设计稿编辑与已制作成品继续相互独立。

入口先开放【本牌使用时】【本牌抽到时】【本牌被丢弃时】。同一时点最多一个入口，入口之间不直接连接，各入口拥有自己的上下文和本次变量。一个入口内的多个效果有明确顺序。焚毁、保留继续作为已有原生属性处理，本轮不因此增加新的事件编程能力。

入口的名字必须与原生实际行为一致。实施第一步核对当前 Managed 对应的反编译调用链，再用游戏验证以下边界：普通抽牌、生成入手、从牌堆选入手是否属于同一个抽到入口；主动弃牌、效果弃牌、回合清理分别是否触发丢弃；使用脚本开始时是否已经支付费用、移出手牌、确定目标。界面说明显示核实后的语义，不凭名称推断宿主行为。

节点库按玩家要表达的事情分类，端口按真正的数据类型约束。

| 类别 | 首轮节点 | 约束 |
| --- | --- | --- |
| 触发入口 | 使用时、抽到时、丢弃时 | 每种入口至多一个；不提供受伤、回合开始、回合结束、生命跨阈值监听 |
| 对象与选择 | 使用者、使用时选中目标、所有敌人、所有友方、所有角色、随机选一个对象 | 自己明确指使用者；随机选择属于执行步骤，抽样一次后输出结果 |
| 读取数据 | 生命、生命上限、已损失生命、生命百分比、护盾、状态层数、能量及上限、手牌及牌堆数量、本牌基础费用 | 保留当前字段含义；玩家能量与牌堆能力不扩展到任意角色 |
| 数值与条件 | 常量、四则运算、最值、取整、范围限制、比较、与或非、对象存在 | 与或保持短路；存在判断可以保护后续对象读取 |
| 流程控制 | 条件分支、依次执行、有限重复、逐个对象执行、结束本次流程 | 控制结构有明确子流程和完成出口，不开放任意回边、While、定时器或递归 |
| 卡牌效果 | 普通及真实伤害、护盾、治疗、生命上限、能量、抽牌、弃牌、焚毁手牌、洗牌、从抽牌堆或弃牌堆选牌入手、施加及移除已有状态、结束回合 | 复用当前支持的原生调用；新增端口不得承诺未经验证的实际伤害或状态结算结果 |
| 本次变量 | 记住数值、记住对象，读取捕获结果 | 仅本次执行有效；捕获点必须早于使用点，不建立跨入口、跨回合的可变状态 |

状态使用资源选择器，展示实际可获得的名称、说明、来源和可用状态；没有可信来源元数据时不猜测 MOD 归属。文档保存稳定资源引用，制作前重新确认资源存在。状态不存在、目标没有状态、状态资源未加载是三种不同情况，后两者不能都显示成“层数为零”。移除节点首轮沿用已有的移除整个指定状态语义，不把它写成尚未实现的减少指定层数。

常量尽量放在输入口旁边直接编辑。例如伤害 12、重复 3 次、阈值 50% 都不要求额外拖出常量节点。生命百分比沿用当前 0～100 的表示，界面加百分号；“低于一半”明确对应 `< 50%`。效果数量继续有明确的最终取整规则；重复次数要求整数，不能隐式把小数当次数。

常用组合节点首先提供【生命低于阈值】【具有某状态】【对所有敌人造成伤害】【重复攻击】【按当前手牌数量获得护盾】。组合是基础节点组成的可展开片段，不另外实现一套计算逻辑。折叠、展开和改名不改变结果。选择范围、阈值、倍率等参数在组合表面编辑，展开后仍能看到这些参数的具体依赖。

执行线表示先后顺序，数据线表示参数依赖。建议执行端口采用方向明确的形状，数据端口使用类型形状、颜色和标签；节点分类主要放在节点标题上，避免类别颜色与数据类型颜色互相冲突。

| 连接对象 | 规则 | 失败时的解释示例 |
| --- | --- | --- |
| 普通执行输入 | 一个来源 | “这个步骤已有执行来源，请重新接入或使用控制结构。” |
| 普通执行输出 | 一个后续步骤 | “需要依次执行多个分支时，请使用依次执行。” |
| 数据输入 | 一个来源；允许节点定义的默认值 | “此处需要数值，目前连接的是条件结果。” |
| 数据输出 | 可供多个合法下游输入使用 | 每个消费者仍在自己的执行时点读取动态数据 |
| 角色与角色集合 | 明确区分 | “此处需要单个角色，请先逐个执行或选择一个角色。” |
| 不同入口 | 不直接互连 | “使用时的选中目标不能用于抽到时流程。” |
| 子流程局部值 | 仅在合法作用域及已执行路径中引用 | “当前遍历对象仅在这个遍历体内有效。” |
| 执行或数据回路 | 拒绝 | “该连接会形成循环，请使用有限重复节点。” |

类型至少包含数值、真假、角色、角色集合和状态资源。卡牌、卡牌集合仅在本牌信息和已验证选牌能力需要时开放相应端口，不顺带扩展成任意卡牌对象操作框架。数字不能隐式变成真假，资源也不能靠自由文本冒充有效引用。

控制流采用结构明确的子流程，保留经典蓝图的连接方式，同时让执行次序可以从图上直接看出。

- 条件分支有条件输入、成立子流程、不成立子流程、完成后出口。只执行命中的子流程，结束后进入完成出口。
- 有限重复和逐个对象执行有执行体及完成后出口；执行体结束即返回所属控制节点，不需要玩家把线接回去。
- 子流程中普通节点的空后续表示返回所属控制结构；根流程的空后续表示本次完成。界面显示相应的轻量结束提示，避免把两者混淆。
- 显式【结束本次流程】可以提前退出整个入口；【结束回合】为终止动作，不允许再接依赖本回合仍在进行的后续步骤。
- 首轮不提供任意多入汇合节点。条件后的公共步骤连接到条件节点的完成出口，循环后的步骤连接到循环完成出口。
- 子流程内定义的本次变量不自动泄漏到外层；外层已有捕获值可以被内部使用。首轮不引入跨分支合并变量和全局变量。

读取默认发生在当前步骤需要参数时。对一个效果步骤先确定其输入和对象，再调用原生效果；后续步骤重新读取动态状态。需要保留早先值时用【记住】。随机选择只在执行该选择节点时抽样，输出被多处引用时不重新抽样。遍历开始时确定对象集合及顺序，处理时重新确认对象仍有效，避免遍历过程新增对象改变次数。

不存在的对象不自动替换为另一个目标。空集合遍历执行零次后正常完成；已失效目标的作用类步骤跳过并记录原因；要求有效对象的读取必须通过存在判断保护，否则给出节点级运行错误并终止当前流程。普通伤害为零或状态层数为零不与连接错误混为一谈。

选牌及抽牌节点必须在操作完成后才继续后续流程。选牌取消按该节点公开的取消语义结束或进入取消子流程；战斗结束、使用者死亡、所属操作失效时终止本次执行。完成、取消、错误必须是明确的终态，同一个回调不能重复推进。临时订阅、回调句柄和界面引用在终态释放。当前抽牌等待回调使用 finished 标记并不等同于已退订，这一边界需要核对宿主可用接口后完成治理。

图校验和状态反馈分成三层。

| 层次 | 检查内容 | 运行时机 |
| --- | --- | --- |
| 即时连接检查 | 端口方向、类型、数量、入口归属、作用域和新增环 | 拖线悬停及落点时，落点前显示原因 |
| 完整蓝图检查 | 文档结构、节点和端口身份、执行可达性、数据依赖闭包、控制结构、变量定义、资源依赖、展开后复杂度 | 明确编辑提交后增量检查，制作前完整检查 |
| 场景试算 | 具体输入下的读数、分支、循环、随机结果、效果命令、选牌继续或取消 | 玩家主动运行，不读写真实战斗 |

完整检查不能只扫描执行线：沿合法入口找到执行步骤后，还必须纳入它们的数据依赖。未使用的草稿节点显示“未参与执行”，不生成运行代码；它们依然接受文档安全及大小检查。必需输入缺失、类型冲突、非法作用域、缺失资源等可执行图错误阻止制作，空默认输入和合法结束不算错误。至少存在一条有实际行为的有效入口流程才允许制作。

连接有效性、场景执行结果和作品保存状态分别显示。有效连线可以在本次试算中未经过；连线错误用文字及形状解释，不能只用红色。建议显示兼容落点、不可连接、有效连接、未参与执行、结构错误五类编辑反馈；试算另显示执行中、等待选择、已执行、未命中、取消和失败。

试算提供生命、护盾、能量、敌人、手牌及牌堆、已引用状态层数、选中目标、随机种子等输入。每次运行复制场景；输出结构化轨迹，至少包含节点 ID、执行序号、循环序号、实际输入、分支结果、状态差异与终止原因。参数变化或蓝图语义变化后，旧轨迹标为过期；布局变化不改变语义，仍可定位同一节点。

试算中的选牌从模拟牌堆选择，可测试确认、取消和空结果，不接真实游戏选牌 UI。模拟仅承诺支持范围内的基础数值和流程语义；已有状态的被动行为、原生伤害修正、其他 MOD 效果不在模型覆盖时明确显示“该部分未模拟”，不得把未覆盖结果显示成完整的实战预测。正式运行继续走原生调用和宿主权威路径。

编辑器按完整工作区组织，画布是主要空间。

| 区域 | 内容与交互 |
| --- | --- |
| 顶部 | 作品名、保存状态、撤销/重做、检查、试算、免费制作、作品库入口 |
| 左侧 | 节点分类与搜索、常用组合；拖线到空白时临时提供兼容节点菜单 |
| 中央 | 无限逻辑画布、有限视口、节点、端口、连线、框选、注释分组与折叠 |
| 右侧 | 卡牌属性、选中节点参数、卡牌预览；按上下文切换，避免三份信息同时挤占画布 |
| 底部 | 默认折叠的检查结果和试算轨迹；点击问题或步骤定位并选中对应节点 |

宽窗口可同时展示左右面板；在 960×720、760×640 等现有支持尺寸下，侧栏改为抽屉或互斥面板，优先保留画布与制作状态。卡面编辑沿用当前能力，通过明确入口打开。生成脚本保留在高级查看入口，不作为可回写的编辑源。

画布应具备以光标为中心的缩放、中键或空格拖动平移、框选、多选移动、复制粘贴、删除、撤销重做、定位选中、适配全图和显式自动整理。节点移动过程只更新位置及关联连线，不重新编译；拖动结束形成一个历史记录。自动整理只修改布局，不修改执行顺序。文本框获得焦点时，删除、复制和撤销首先作用于文本编辑。

连线应支持拖出、新接入、重新接入、断开、选中删除、悬停突出上下游，以及在兼容连线上插入节点。重接失败或按 Esc 取消时恢复原连接，不能先破坏原图。接入已占用的数据输入是一个可撤销的替换事务；连线断开后恢复节点的显式默认值，必填且无默认值的端口显示问题。交叉处不是连接点，连线只有在端口或明确的走线点上连接。

节点拖动、拉线、框选、平移、文本输入、弹出菜单使用互斥的交互状态。内容点击不能冒泡成关闭窗口，拖出画布、窗口关闭、失去焦点时必须清理拖拽捕获和预览连线。画布缩放不缩小实际点击容错区域到难以操作的程度。视口与节点稳定 ID 用于保留选择、位置和问题定位。

组件按责任落地，优先放在 CustomCards 所属目录，不因蓝图改版而先扩展共享公共框架。

| 拟新增组件责任 | 必须提供的能力 |
| --- | --- |
| GraphCanvas / Viewport | 坐标变换、平移缩放、裁剪、选择、视口恢复 |
| NodeView / PortView | 节点标题、参数、端口类型和可接状态、诊断标记 |
| EdgeLayer / EdgeHitTest | 连线绘制、命中测试、重接、走线点、路径高亮 |
| ConnectionController | 与正式校验器共享的连接判定，原子提交或取消 |
| Palette / ContextMenu | 搜索、分类、兼容筛选、拖线创建并自动接入 |
| Inspector / ResourcePicker | 节点参数、卡牌属性、状态引用和依赖提示 |
| GroupView / Layout | 注释分组、折叠片段、显式排列、缩略导航 |
| EditorHistory / Clipboard | 操作事务、撤销重做、复制时完整重映射内部引用 |
| Diagnostics / TrialTrace | 问题定位、单步轨迹、分支值和等待状态 |
| BlueprintLibrary | 模板、个人作品、常用片段及导入导出 |

蓝图库包含“内置模板”和“我的作品”，常用片段作为节点库的复用入口。首批模板采用明确示例值，覆盖直接伤害、低生命强化、先护盾后攻击、群体攻击、有限多段攻击、抽牌后按手牌数获得护盾、带状态条件的攻击、丢弃时产生效果，以及从牌堆选牌后继续执行。抽到和弃牌模板的具体行为须通过原生入口核对后定稿。引用外部状态的模板显示依赖，不随意绑定一个只在开发者机器存在的状态 ID。

使用模板会建立独立作品；插入片段会复制节点、边和捕获引用，完整重映射 ID。组合片段随作品保存其内容和版本，运行不依赖外部模板文件。修改模板不自动修改已有作品，编辑或删除设计稿也不修改成品。模板预览显示卡面、自然语言效果、蓝图结构和资源依赖，而不是只展示一张缩略图。

v2 图文档需要分开表达逻辑、布局和编辑器视图信息。

| 文档部分 | 内容 |
| --- | --- |
| 作品身份与属性 | 格式版本、作品 ID、修订、名称、费用、类型、标签、风味文字和卡面 |
| 逻辑图 | 稳定节点 ID、节点类型及版本、参数、类型化默认值、端口间连接、入口和子流程归属 |
| 组合片段 | 冻结的内部图、边界端口映射、来源信息和片段版本 |
| 布局 | 节点坐标、注释分组、折叠和走线点；不影响编译结果 |
| 编辑视图 | 视口、缩放、当前入口等恢复信息；与语义校验结果解耦 |
| 迁移记录 | 原版本、原稿备份引用、旧新节点对应和待修订事项 |

图文档是唯一可编辑的逻辑来源。经过类型及结构校验后，转换成统一的执行表示，供脚本生成、效果描述和试算消费。这个表示不是另一套可持久化编辑格式。UI 不直接拼 Lua，试算不解释连线的另一套规则，脚本也不反向覆盖蓝图。正常编译产物绑定语义哈希；相同逻辑不同布局应产生相同执行结果。

节点目录同时定义端口、默认值、参数范围、允许的上下文、资源需求、描述能力和编译映射。拖线预检和制作前检查调用相同规则。稳定节点 ID 贯穿文件、编译诊断、生成脚本和试算轨迹。异步返回的检查结果只能更新与其语义版本匹配的作品。

复杂度沿用当前受控执行思路，初始基线为展开后不超过 256 个语义节点/表达式、嵌套不超过 12 层、单次重复不超过 64 次、单次牌堆操作不超过 64 张、执行预算初始为 4096 步；最终计数契约在第一阶段固定。注释、走线点和卡面不计为语义节点，组合展开后计数。表达式求值、循环和异步继续都不能绕过预算。

跨卡牌的抽牌、弃牌连锁可能在各自图无环时仍形成无限触发，因此还要建立连锁总预算及深度限制。先核对宿主进入自建卡牌脚本和异步恢复的上下文边界，再确定预算如何传递；不能只给每张卡单独重置一个计数器就宣称已解决。超限必须终止相关链并给出可定位原因，已经完成的原生效果不假装能够全部回滚。

编辑器只在打开时持有画布和相关 UI 引用，关闭后释放。空闲画布不做每帧全图校验或布局；节点移动只重画关联连线，属性提交才触发语义检查，说明和预览按实际变化更新。性能验收在固定机器与分辨率上记录 50、128、256 个语义节点的平移、缩放、拖动、连接及检查耗时和分配，指标在基线测量后固定，不能仅凭节点数宣称流畅。

迁移分为设计稿和已制作成品两条，拟采用以下策略。

| 原内容 | 转换策略 | 完成状态 |
| --- | --- | --- |
| 仅三个直接入口、执行顺序与取值可证明等价的 v1 设计稿 | 转成 v2 节点、作用域和连线，保留属性、卡面、原规则顺序和变量引用；生成初始布局 | 等价场景比较通过后可制作 |
| 同一入口多组规则，较早规则含异步选择或等待 | 转为明确顺序的 v2 草稿，同时列出时序变化；不声称自动等价 | 待玩家修订并查看试算后才能制作 |
| 使用后回合开始、结束或受伤监听 | 保留原始内容，转换结果带不可执行的迁移提示，不自动改为使用时判断 | 必须明确删除或重写不支持部分后才能制作 |
| 随机重复求值、旧作用域等无法证明等价的稿件 | 保留原稿，尽量还原结构，列出无法等价的具体位置 | 待修订；不合并可能改变求值次数的表达式 |
| 缺少已有状态资源的稿件 | 允许作为草稿导入，保留引用并报告缺失 | 资源恢复或明确替换后再制作 |
| 未知较新格式 | 保留文件并报告不兼容 | 不覆盖、不按旧结构猜测读取 |
| 已制作的 v1 原生卡牌 | 保留它们的独立 RawData 和脚本，不自动重写仓库、存档、战斗内实例 | 作为明确支持的存量成品兼容，需独立读档与执行验收 |

旧版各直接规则由 Emitter.Rule 分别启动；某组等待异步回调时，随后规则可以继续被启动，因此迁移不能无条件把全部规则串成顺序图并标记等价。这是源码能确认的迁移风险，具体原生结果仍要用匹配宿主验证。

迁移先完整读取和备份，生成转换结果与报告，再通过现有共享配置存储和修订检查提交。失败不覆盖原库；成功迁移的作品只保存 v2，不双写 v1。v1 解析仅服务明确声明的旧格式导入和迁移，不保留旧编辑器或旧编译器作为并行生产入口。一个旧稿的读取路径在它成功迁移或被归档后退出；仍待修订的原始内容作为恢复资料保留。

存量成品兼容是对已有存档的明确例外：其自带旧脚本可能仍包含监听，不由新蓝图编辑器重新生成。兼容通过宿主继续执行成品自己的数据完成，不另建 v1 蓝图运行后端；只有玩家主动替换或删除该成品时，该实例的兼容需求才结束。如果要对存量成品也取消监听，必须作为另一个明确的存档迁移决策，不能混在 UI 改版中执行。

导入先检查文件大小、结构深度、格式、节点数量和引用结构等安全边界，再做语义检查。结构有效但尚不完整的稿件可进入作品库；制作仍严格要求语义和资源可用。导出保留蓝图、布局、卡面、片段及资源引用，不带作者机器绝对路径或任意用户脚本。导入为独立作品，粘贴为独立节点集合，分别处理身份和内部引用重映射。

保存继续使用已有 owner 配置路径、修订检查和模块通知。保存冲突不自动覆盖别人修改；关闭保存失败保留编辑窗口和未保存内容。制作检查重新读取有效资源，验证全部生成脚本可由游戏 Lua 环境加载，再使用现有原生仓库写入与保存失败回滚。免费制作和已有设计稿/成品分离契约保持一致。

实施按依赖安排成七个工作包，每一项都有可评审交付和退出条件。它们是同一最终方案的实施顺序，不意味着长期保留两套编辑器。

| 工作包 | 具体交付 | 退出条件 |
| --- | --- | --- |
| P0：语义及宿主边界 | 固定三个入口含义、选择完成和取消语义、状态引用、作用域、随机及计数契约；核对反编译和现有存量样本 | 关键原生调用链有匹配证据；无法等价迁移的类别明确；代表卡牌预期结果写定 |
| P1：文档与编译基础 | v2 图文档、节点目录、类型及结构校验、统一执行表示、Lua 生成、节点诊断；迁移器和旧稿预检 | 三个入口与核心控制结构可在无 UI 情况下编译执行；旧数据有可恢复路径；不再生成新监听入口 |
| P2：最小完整画布 | 节点/端口/连线、平移缩放、基础搜索、节点参数、重接、撤销重做、保存重开；接入真实生产目录 | 能从空白连接一张条件伤害卡，修正错误，保存重开并制作；窗口关闭无残留交互 |
| P3：完整节点与蓝图库 | 当前直接效果覆盖、有限循环、随机及本次变量、状态资源选择、组合折叠、内置模板、复制粘贴、导入导出 | 原有直接时点能力有明确对应；模板无需外部编辑即可完成制作；引用和 ID 不串卡 |
| P4：检查与试算体验 | 问题定位、入口场景、轨迹单步、选牌确认/取消、固定种子、过期结果标识、自动描述 | 代表场景的流程结果与生成 Lua 在相同模型条件下一致；未模拟内容清晰可见 |
| P5：迁移、清理与 UI 完整性 | 旧稿转换和报告、存量成品回归、旧积木编辑入口及新卡监听逻辑退出、三尺寸 UI 和性能优化 | 新作品只有 v2 编辑/编译路径；迁移不丢数据；布局、输入和资源释放通过验收 |
| P6：真实游戏验收与发布 | 制作/读档/战斗/取消/连锁/联机验证，更新使用说明、测试清单和产物 | 必要自动化及原生验收有证据；一次统一产品构建发布并完成打包核验 |

P1 的迁移工作应尽早验证真实旧稿，不能等画布完成后才发现结构不可转换。P2 就要形成从编辑到制作的完整链路；P3～P5 逐步补齐同一生产实现。P6 之前不能把“蓝图可画出来”称为迭代完成。

验证使用有实际行为意义的矩阵。

| 场景 | 必须证明的结果 |
| --- | --- |
| 生命为 49%、50%、51% | 仅 49% 命中“低于一半” |
| 先改变生命再判断；先记住生命再改变 | 动态读取与显式捕获产生各自正确的结果 |
| 抽到/丢弃入口引用使用目标 | 编辑预检及完整检查均拒绝，不能只靠 UI 隐藏 |
| 分支、重复、逐个执行嵌套 | 完成出口只推进一次；局部变量不能泄漏；空集合完成正确 |
| 数据环、执行环、错误类型、缺失必填口 | 报错能定位端口或边；合法默认值及结束不报错 |
| 一次随机结果供两个效果使用 | 两处使用同一结果；新一次选择才再次抽样 |
| 重复 0、1、上限和超限；动态除零 | 范围及运行错误行为一致，没有静默截断或假成功 |
| 选牌及抽牌后读取手牌数 | 后续步骤在实际完成后执行；重复回调不二次推进 |
| 取消、死亡、战斗结束、窗口关闭 | 相关本次流程到达终态，临时回调与 UI 引用释放 |
| 抽弃牌引发连锁 | 连锁共享总约束，不通过不断新建入口绕过预算 |
| 状态未施加与状态资源缺失 | 前者可以为零层，后者阻止制作；已存在状态行为走原生路径 |
| 迁移直接规则与需修订规则 | 可证明等价者比较结果；无法等价者保留原稿并明确阻断制作 |
| 保存冲突、导入失败和制作保存失败 | 不覆盖新修订，不丢原稿，不留下假成功或多余成品 |
| 移动、缩放、重接取消、剪贴板和撤销 | 不丢引用、不改变语义、不吞文本输入、不误关闭窗口 |
| 1280×900、960×720、760×640 | 核心编辑操作可达，侧栏不挤毁画布，长文本和问题提示可读 |
| 制作、读档、仓库取出、三入口及主客机 | 原生行为、权威及卡面按支持范围一致；无主客机重复执行 |

验证入口按现有项目约定选择：领域行为使用 `dotnet run --project AuraToolsExp-Dev.Tests -c Release -- --suite custom-cards`，其中执行真实生成 Lua；模块行为使用 `tools/Test-AuraToolsExp.ps1 -SkipBuild -SkipModelIntegration`；游戏内编辑器布局和交互使用更新后的 `tools/Test-CustomCardUnity.ps1`。Unity Preview 应加载同一节点目录与生产编辑组件，宿主适配不得伪造战斗或状态结算成功。

发布产品 C# 时，统一运行一次 `tools/Build-MainSharedConsumers.ps1` 事务，由 `tools/Publish-MainSharedConsumers.ps1` 作为唯一产物写入者，再核验共享 DLL 打包。共享输出命令串行执行。文档讨论稿本身不触发产品构建或训练工具维护。自动化通过、Unity 预览通过、真实游戏通过分开记录，缺少哪一类证据就明确列出。

首轮完成范围包括：三个离散入口、现有直接效果、已有状态引用、可编辑节点画布、连线和全图校验、常用组合与完整卡牌模板、场景试算及轨迹、草稿库与迁移、原生制作和必要真实游戏验收。远程蓝图市场、联机协同编辑、自定义 Lua/自定义节点插件、BUFF 编辑、被动监听、任意循环、跨卡全局变量不纳入这一轮。

当前最需要在 P0 消除的技术不确定性，是原生抽到/丢弃的实际范围、异步完成与退订接口、跨卡连锁预算传递，以及旧稿异步和随机时序的等价判定。组合节点默认粒度可以在首张“生命低于一半强化”蓝图的实际编辑评审中调整，不影响上述已确认的功能边界。
