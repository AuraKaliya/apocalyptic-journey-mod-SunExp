# AuraToolsExp 妙妙工具一级界面改版方案

> 实施状态（2026-08-18）：P0 至 P3 已完成。一级页已使用原生内容租借、
> 不透明工作区、左侧分类栏、紧凑 TMP 列表、图标按钮和 Switch；内置模块
> 已接入 `IconKey`，并新增 30 个可重复生成的图标/控件资源。所有二级 Overlay
> 统一使用 TMP 标题和图标关闭按钮。HTML + Playwright 快速预览宿主已经完成；
> 独立 Unity UI Preview Player 也已完成，并可在不启动游戏的情况下构建、
> 交互和生成十二张自动验证截图。

## 1. 结论

本轮不建议推翻现有模块架构，也不建议制作一张覆盖整窗的大背景图。

现有模块目录、状态投影、分类、搜索和二级设置页路由可以保留。需要重做的是：

1. 先把妙妙工具页改成真正独占原生设置内容区的页面，修复其它设置控件露出和潜在的底层点击。
2. 把横向八分类按钮改成左侧分类栏，释放垂直空间并消除低分辨率溢出。
3. 把 102 像素高的“大色块行”改成更紧凑的工具列表项，建立图标、标题、状态、设置入口和总开关的稳定层级。
4. 一级页迁到 `AuraUiShared` 的 TMP 渲染路径，由一个主题对象管理颜色、字号和间距。
5. 只新增必要的通用控件和小型图标图集，不再给每个按钮套高对比度金框。

目标不是让工具箱变成另一套独立游戏 UI，而是让它像原生设置窗口里一张完成度较高、具有 Aura 身份的工具管理页。

## 2. 调研范围

本方案核对了以下表面：

- 用户提供的 920 x 848 游戏截图。
- `AuraToolsSettingsRuntime` 的原生 `SettingUI` 注入、宿主解析和关闭流程。
- `ToolboxSettingsShell` 的分类、搜索、模块行和状态刷新。
- `AuraToolsUi`、`AuraToolsUiTheme` 与 `AuraUiShared` 的主题、TMP、滚动、焦点和模态能力。
- 当前三个 AuraToolsExp UI 位图资源及其九宫格使用方式。
- 游戏构建 `1.0.24605918` 的反编译 `SettingUI` 字段与生命周期。
- 当前工具箱架构文档和现有测试门禁。

## 3. 现状诊断

### 3.1 其它 UI 露出是页面生命周期问题

当前 `ShowAuraPanel()` 只做了三件事：激活面板、把它移到同级最后、开始构建内容。它没有停用或隐藏原生设置内容树。

原生标签页也只被附加了一个 `IPointerDownHandler`，点击时隐藏 Aura 面板；代码没有保存和恢复原生内容页的可见状态。

同时，一级页背景 alpha 为 `0.96`，模块行 alpha 为 `0.98`。因此当前实现依赖“半透明遮盖 + 同级排序”模拟切页。只要原生控件仍在活动，或者原生子树存在独立 Canvas，底层文字和控件就可能显示在工具箱间隙之中。

截图中的“模式 / 无边框 / 窗口”正好出现在工具箱顶部空隙和模块行间隙，符合这一实现特征。

单独把 alpha 改成 `1` 只能掩盖部分像素，不能解决：

- 底层控件继续接收导航或射线输入。
- 独立 Canvas 可能继续绘制在 Aura 面板之上。
- 关闭或切换标签时原生页状态无法精确恢复。

### 3.2 一级页同时存在三个导航层

截图中的视觉顺序是：

1. 原生顶层标签：音画、游戏、反馈、键位、妙妙工具。
2. 工具分类标签：全部、游戏体验、表现与资源等。
3. 搜索、数据目录和结果摘要。

第二层使用与顶层近似的金框按钮，七到八个入口同权并排，导致顶层与页内导航互相争夺注意力。当前固定宽度在全部分类出现时约需要 778 像素，还没有计算面板内边距，扩展分类出现后容易在较窄窗口溢出。

### 3.3 模块行空间利用率低

当前模块行固定高 102 像素，布局中还有：

- 6 像素金色竖条。
- 230 像素固定状态列。
- 82 像素“设置”文字按钮。
- 28 像素方形 Toggle。

结果是每屏只能稳定看到约五个工具；标题、说明和状态被拉到三个相距较远的区域。启用项整行变绿，但“可用、已配置、需要注意、当前运行”没有形成清晰的状态语义。

现有模块描述已经包含 `IconKey`，但内置模块没有赋值，一级页也没有消费它。也就是说，契约已经为图标留下位置，表现层尚未完成。

### 3.4 组件与主题存在两套来源

`AuraToolsUiTheme.Current` 已经从 `AuraUiShared` 派生主题，但一级页仍主要使用 `AuraToolsUi` 中另一组静态颜色、字号和旧 `UnityEngine.UI.Text` 工厂。

这带来三个问题：

- 修改主题不能完整改变一级页。
- 新的 TMP 字体、自适应字号和主题能力没有被一级页使用。
- 控件尺寸、颜色和反馈容易继续在各页面分叉。

### 3.5 视觉噪声主要来自重复装饰，而不是颜色本身

紫黑、暖金与游戏原生边框并不冲突。问题是金框被同时用于顶层标签、分类标签和每个“设置”按钮，所有可点击元素都在大声说话。

一级页更适合保留一个原生金框层级，把内部工作区改为安静的深色平面，只在选中、焦点、警告和关键操作上使用强调色。

## 4. 目标布局

建议保留原生“妙妙工具”顶层标签，内部改为左侧分类栏加右侧工具列表。

```text
┌──────────────────────────────────────────────────────────────┐
│ 妙妙工具                                                     │
├──────────────┬───────────────────────────────────────────────┤
│ 全部      15 │ 全部工具 · 15                  [搜索…] [目录] │
│ 游戏体验   4 │───────────────────────────────────────────────│
│ 表现资源   6 │ [图标] 开局卡组             [齿轮] [开关]    │
│ 对局记录   3 │        全局卡组 11 张                          │
│ 联机工具   1 │        为世界推演配置开局卡组                  │
│ 智能战斗   1 │───────────────────────────────────────────────│
│ 系统数据   1 │ [图标] 卡牌刷新                      [开关]    │
│ 扩展工具   0 │        战斗奖励选牌可刷新                      │
│              │        提供一次重新抽取                        │
│              │───────────────────────────────────────────────│
│              │ [图标] 一键美餐             [齿轮] [开关]    │
└──────────────┴───────────────────────────────────────────────┘
```

### 4.1 分类栏

- 建议宽度 132 至 148 像素。
- 每项高度 38 至 42 像素，显示分类名和数量。
- 选中项使用低亮度底色、左侧 3 像素金线和高亮文字；未选中项不使用完整金框。
- “扩展工具”没有内容时继续隐藏。
- 分类栏自身可以滚动，避免未来分类增加后重新挤压顶栏。

### 4.2 右侧页头

- 左侧显示当前分类名和工具数量，替代独立的结果摘要行。
- 右侧是搜索框、清空搜索图标和目录图标按钮。
- “数据目录”改为文件夹图标按钮，悬停提示名称；不再与分类标签争夺宽度。
- 搜索时结果跨分类，页头显示“搜索结果 · N”。

### 4.3 工具列表项

建议高度 80 至 86 像素，结构固定为：

- 32 至 36 像素图标。
- 标题与实验标签。
- 状态摘要，优先于功能说明显示。
- 一行弱化说明；较长文本截断，不改变行高。
- 有二级页时显示齿轮图标按钮；没有二级页时不占空的可见按钮位置。
- 总开关使用横向 Switch，不再使用无法立即辨认开关语义的方形 Checkbox。

启用状态不再把整行染成绿色。建议使用：

- 开启：Switch 与一个小状态点使用青绿色。
- 关闭：中性灰，行背景保持不变。
- 降级或需处理：状态文字与左侧细线使用琥珀色。
- 不可用：降低文字和图标明度，同时保留不可用原因。
- 忙碌：状态点做低频亮度变化，不改变列表尺寸。

### 4.4 视觉令牌

一级工作区必须完全不透明。建议基线：

| 用途 | 建议值 | 说明 |
|---|---|---|
| 工作区背景 | `#0B0A10`，alpha 1 | 阻止原生内容透出 |
| 分类栏 | `#111018`，alpha 1 | 与列表形成层级 |
| 列表项 | `#17161E`，alpha 1 | 不使用大面积彩色启用态 |
| 悬停项 | `#201E29`，alpha 1 | 只提升一级亮度 |
| 主文字 | `#F0EBDD` | 延续原生暖白 |
| 次文字 | `#B5AE9E` | 描述和非关键状态 |
| 原生金 | `#D5B36B` | 选中、焦点和关键边线 |
| Aura 紫 | `#AA92DC` | 品牌识别，只做次级强调 |
| 成功 | `#69C8A2` | 开启和健康状态 |
| 警告 | `#DDAA58` | 需要处理 |
| 错误 | `#D87373` | 失败和资源缺失 |

不使用渐变、发光球或大面积紫色填充。原生窗口外框已经足够表达游戏风格，内部只需要少量金色细节。

## 5. 其它 UI 露出的修复设计

### 5.1 增加原生内容租借

在 `AuraToolsSettingsRuntime` 增加一个 AuraToolsExp 自有的 `NativeSettingsContentLease`：

1. 注入时识别原生标签栏、永久窗口框、Aura 面板和原生内容页根节点。
2. 打开妙妙工具前，记录每个原生内容根的 `activeSelf`、CanvasGroup 可见性和射线状态。
3. 隐藏原生内容根，随后显示 Aura 面板。
4. 点击任一原生标签时，先释放租借并恢复精确快照，再让原生按钮事件执行切页。
5. 在 `Close`、`Hide`、`OnDestroy`、回放切换、构建异常和重复注入时都幂等释放。

不要停用整个 `SettingUI`、标签栏、窗口边框或返回按钮，也不要依赖每帧轮询修正状态。

### 5.2 宿主识别先做一次实际层级探针

当前宿主解析会按名称和矩形尺寸猜测内容节点。实现租借前，建议在开发构建中输出一次：

- `SettingUI` 从根到标签栏、内容页、永久边框的完整路径。
- 各节点的 activeSelf、Canvas、sortingOrder、GraphicRaycaster 和矩形范围。
- 原生标签按钮点击前后的激活状态变化。

根据当前游戏构建建立优先的稳定路径或组件规则；几何重叠只作为版本兼容回退，并在回退时写一次警告日志。

### 5.3 增加两层防御

- Aura 工作区背景使用 alpha 1，作为视觉防线。
- Aura 面板根使用明确的 CanvasGroup 交互状态；隐藏时 `interactable=false`、`blocksRaycasts=false`，显示时同时恢复。

`SetAsLastSibling()` 可以保留，但只作为普通排序，不再承担页面隔离职责。

## 6. 新组件建议

### 6.1 放入 AuraUiShared 的无语义组件

只有确实可被多个消费者复用的控件进入共享层：

- `AuraUiIconButton`：图标、悬停提示、焦点、禁用态和点击反馈。
- `AuraUiSwitch`：开关轨道、滑块、键盘/手柄导航和状态反馈。
- `AuraUiEllipsizedText` 或 TMP 截断配置：固定高度下安全显示长文本。

### 6.2 留在 AuraToolsExp 的产品组件

- `ToolboxCategoryRail`：分类、数量、选中状态和分类滚动快照。
- `ToolboxModuleListItem`：模块图标、状态、说明、设置入口和开关。
- `AuraToolsIconRegistry`：把内置 `IconKey` 映射到本地资源，并为外部扩展提供安全回退。
- `NativeSettingsContentLease`：它绑定游戏 `SettingUI` 语义，先留在原生注入适配器附近。

不要让 AuraToolsExp 读取 Terrias 私有 UI 资源，也不要把“开局卡组”等工具语义放进 AuraUiShared。

## 7. 图标与位图资源

建议制作一张小型、可审查的 UI 图标图集，而不是生成整张界面背景。

第一批图标包括：

- 分类：全部、游戏体验、表现资源、对局记录、联机、智能战斗、系统、扩展。
- 工具：日志、皮肤、音乐、音效、卡组、刷新、美餐、保险箱、表情、自动战斗、同步、伤害统计、回放、技能 CG、卡牌 CG。
- 操作：搜索、清空、文件夹、设置、警告。

资源规则：

- 24 或 32 像素基准，2 倍图集输出，Point 或 Bilinear 由最终风格统一决定。
- 使用单色浅金/暖白线面图标，状态颜色由 Image tint 提供。
- 图标轮廓保持在小尺寸下可读，不使用文字或复杂插画。
- 外部模块的 `IconKey` 无法解析时使用分类图标或模块名称首字，不显示空白框。
- 当前保险箱图标可以重新绘入统一图集；现有 128 像素图标不直接决定其它工具的风格。

当前 `background-九宫格.png` 和 `button-九宫格.png` 可以继续服务旧二级页，但一级页不应再把同一金框按钮用于所有层级。

## 9. 实施顺序

### P0：正确性

1. 输出实际 `SettingUI` 层级探针。
2. 实现并测试原生内容租借。
3. 把一级工作区改为完全不透明。
4. 验证关闭、原生标签切换、回放切换和重复打开。

P0 可以独立发布，即使视觉改版尚未完成，也必须先消除露底和底层点击。

### P1：布局

1. 分类改为左侧栏。
2. 合并搜索、目录和结果摘要。
3. 重做紧凑模块列表项。
4. 对全部、单分类、搜索、空结果和扩展模块做响应式验证。

### P2：视觉与组件

1. 迁移一级页到 TMP 和单一主题。
2. 增加 Switch、图标按钮和提示。
3. 接入 `IconKey` 与新图标图集。
4. 完成悬停、焦点、禁用、忙碌、警告和错误状态。

### P3：二级页一致性

只调整最常进入的二级页外壳、标题栏、返回/关闭方式和内容边距。具体功能控件继续由各 Feature 所有，不重新集中回一级设置 Runtime。

## 10. 验收清单

### 页面隔离

- 妙妙工具内容区内看不到任何原生音画、游戏、反馈或键位控件像素。
- 妙妙工具打开时，内容区中心、行间隙和空白处的顶层 Raycast 不命中原生设置控件。
- 切回任一原生标签后，该标签应显示的原生页准确恢复。
- 连续打开、切换和关闭十次，不残留 Aura 面板、Overlay 或不可见射线层。
- 回放进入和退出后再次打开 SettingUI，页面状态仍正确。

### 布局与输入

- 1280 x 720、1600 x 900、1920 x 1080、16:10 和窗口化均无横向溢出。
- 全部八个分类存在时仍能操作，不压缩工具列表文本。
- 中文长状态、两行 Attention 和外部模块长名称不改变列表行高。
- 鼠标、键盘和手柄都能到达分类、搜索、设置和开关。
- 打开并关闭二级页后，焦点回到原工具的设置按钮。
- 分类切换、开关变化和模块状态刷新不改变当前滚动锚点。

### 视觉

- 一级页只保留一个主要金框层级。
- 开启、关闭、不可用、忙碌、警告和错误无需只靠颜色即可区分。
- 同屏至少稳定显示六个完整工具项。
- 搜索、目录、设置和开关的语义无需阅读额外说明即可识别。

## 11. 不建议的方案

- 只把背景 alpha 从 `0.96` 改成 `1`：不能解决输入和 Canvas 排序。
- 给现有所有按钮换一套更华丽九宫格：会继续放大层级混乱。
- 把 15 个工具改成卡片网格：状态、说明和设置入口的扫描效率更差。
- 为整个界面生成一张 AI 背景图：难以九宫格缩放，也会降低文本可读性。
- 重写模块架构或把二级页重新集中回 Settings Runtime：与已经完成的所有权拆分相冲突。

本方案推荐的是“先修页面协议，再换信息布局，最后做轻量资产”的渐进改版。

## 12. HTML + Playwright 快速预览

无需启动实际游戏即可运行：

```powershell
tools\Preview-AuraToolsToolbox.ps1
```

交互页面位于 `tools/AuraToolsUiPreview/index.html`，自动化输出位于
`output/playwright/aura-tools-toolbox/`。当前覆盖：

- 920 x 848、1280 x 720、1280 x 800、1600 x 900、1920 x 1080 和 1024 x 640；
- 默认、长文本、警告/错误、空结果和外部扩展场景；
- 工作区完全不透明和底层探针不可命中；
- 分类与模块文本不溢出、模块行固定 84 像素；
- 搜索跨分类、设置 Overlay 打开/关闭与焦点恢复；
- Switch 原地更新和分类方向键导航；
- 15 个预览模块 ID 与生产模块清单一致。
