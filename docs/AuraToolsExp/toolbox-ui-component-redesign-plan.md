# AuraToolsExp 妙妙工具组件视觉重构方案

> 实施状态（2026-08-18）：P0 至 P4 已完成。五个 Toolbox V2 资源、
> `ToolboxVisualSpec`、V2 分类/搜索/图标按钮/复选框/模块行已经同时接入
> AuraToolsExp、HTML 预览和独立 Unity Player。920 x 848、长文本、异常、
> 空结果、扩展和 Overlay 截图门禁均已通过。

> 最终更新（2026-08-22）：组件族已覆盖全部二/三级管理页。普通模块行删除
> Summary 与 Description，压缩为 78 像素；玩家展示投影负责内容名称、选项
> 类型和必要状态文本。HTML 预览覆盖 22 个模块，Unity Preview 已通过 15 张截图。

## 1. 调研结论

当前界面的问题不是单纯配色错误，也不是“原生资源使用得还不够多”。真正问题是：

1. 把少量原生装饰图当成通用 UI 组件，在不适合的尺寸和语义上反复拉伸。
2. 金框同时出现在标签、分类、页头、搜索、目录、设置和开关，失去层级意义。
3. 920 x 848 下所有组件经过非整数 Canvas 缩放，低分辨率原生图又被强制 Point 采样，边缘容易碎裂。
4. 为了同屏展示更多模块，把分类、标题、状态和说明压得过小；原生外壳很响，真正需要阅读的内容反而很弱。
5. 仅仅“换成原生靛蓝和金框”产生了另一种过度校准：形式更像游戏，但操作区仍然缺少清晰、安静的工作层级。

因此下一轮不应继续给现有控件换图，而应采用：

> 原生外壳保留，工具箱内部重新设计一套原生启发、低装饰密度、可响应缩放的新组件。

## 2. 当前资源审计

### 2.1 原生按钮图集

`native-button.png` 原图只有 169 x 81。运行时实际裁切区域为 135 x 49，当前同时用于：

- 五个顶层标签；
- 左侧选中分类；
- 页头目录和清空按钮；
- 每行设置按钮；
- 原生选择器两端；
- 返回和关闭按钮。

同一装饰轮廓在一个页面出现十余次，且尺寸从 32 到 128 不等。这会造成重复纹理、边框粗细不一致和视觉噪声。

### 2.2 小面板图

`native-panel-small.png` 只有 93 x 34，目前被拉伸到：

- 整个工具箱页头；
- 220 像素搜索框；
- 多行反馈输入；
- 方形复选框。

这是最明显的资源语义错配。一个 93 x 34 的细边框不能同时承担长页头、输入框和 32 x 32 状态控件。

### 2.3 大面板图

`native-panel-large.png` 为 1367 x 368，具有非常强的四角装饰。它适合单个重要看板或模态窗口，但当前也被用于设置主窗口和普通 Overlay。

当目标容器纵横比远离原图时，即使九宫格不拉伸四角，装饰重量仍然过高，且会与内部页头、按钮的金框争夺注意力。

### 2.4 采样方式

Unity Builder 当前把所有原生资源统一设置为：

- `FilterMode.Point`；
- NPOT 不缩放；
- 无压缩；
- Clamp。

NPOT 和无压缩是正确的；统一 Point 则不正确。当前 CanvasScaler 在 920 x 848 下的缩放不是整数，Point 会让斜角、细金线和文字邻近边缘产生明显跳变。

资源需要按用途分组：

| 资源 | 建议 Filter | 原因 |
|---|---|---|
| 顶层原生标签 | Bilinear | 经常发生非整数缩放 |
| 大型原生面板 | Bilinear | 斜角和高分辨率金线需要平滑 |
| 新工具箱九宫格 | Bilinear | 新资源按 2x/4x 输出 |
| 线性工具图标 | Bilinear | 当前并非像素画 |
| 明确的像素表情/像素素材 | Point | 只有这类资源要求像素对齐 |

## 3. 视觉层级问题

### 3.1 金色使用过量

金色应该表示：

- 游戏原生窗口边界；
- 当前顶层标签；
- 当前焦点或重要确认；
- 警告。

它不应该同时包围搜索框、文件夹、每个齿轮和每个复选框。当前所有交互目标都带金边，导致没有主次。

### 3.2 内容密度过高

当前基准指标：

- 分类栏 144；
- 页头 52；
- 模块行 84；
- 标题 18；
- 状态 15；
- 说明 13。

在 920 x 848 下，Canvas 缩放后分类和说明接近小字极限，页面可显示九至十行。数量很多，但扫描和辨认成本过高。

### 3.3 操作语义不足

模块行最右侧只有一个齿轮和一个方框。即使方框符合游戏视觉，也无法一眼判断它表示“启用”、选择还是确认。

应显示简短的“启用”标签，或者把标题行与复选框组成一个明确的启停区域，而不是留下两个漂浮小方块。

### 3.4 单一靛蓝层级

外壳、分类栏、页头、模块行和空白区都落在很接近的靛蓝范围内。缺少明度分层后，只能继续依赖金框分隔，进一步加剧装饰过量。

## 4. 目标视觉方向

### 4.1 保留的原生部分

以下位置继续使用游戏原生资源：

- 五个顶层设置标签；
- 设置窗口最外层金色边界；
- 原生“开启 / 关闭”设置行；
- 原生横向选择器；
- 返回、退出和高优先级确认按钮。

### 4.2 重做的工具箱内部

以下位置停止直接使用 `native-button.png` 或 `native-panel-small.png`：

- 工具分类项；
- 工具箱页头；
- 搜索框；
- 数据目录图标；
- 模块设置按钮；
- 模块启用复选框；
- 模块列表项；
- 空状态和二级设置页标题栏。

这些组件使用新建的“Aura Toolbox”资源族。资源继续使用游戏靛蓝、暖白和金色，但减少装饰复杂度。

## 5. 新组件资源

建议创作五个基础位图资源，不制作整张界面背景：

### 5.1 `toolbox-surface-9slice.png`

- 96 x 96 或 128 x 128，2x/4x 输出；
- 深靛蓝填充；
- 1 至 2 像素内亮边；
- 只有四角保留极小金色节点；
- 用于页头、分类栏、模块列表背景和二级页。

### 5.2 `toolbox-control-9slice.png`

- 64 x 64；
- 无完整金框；
- 默认态只显示低对比度蓝灰边；
- Hover/Focus 由 tint 或 Outline 提升为金色；
- 用于搜索、图标按钮和普通命令按钮。

### 5.3 `toolbox-category-selected-9slice.png`

- 64 x 64；
- 左侧 3 像素金线；
- 背景只提升一个明度层级；
- 不使用完整按钮四边框。

### 5.4 `toolbox-checkbox-atlas.png`

至少包含：

- Off；
- On；
- Hover Off；
- Hover On；
- Disabled。

尺寸按 32 x 32 单元制作，蓝紫勾选沿用游戏语义，但边框比原生设置页复选框更轻。

### 5.5 `toolbox-icon-button-atlas.png`

- Normal、Hover、Pressed、Disabled；
- 40 x 40 或 48 x 48 单元；
- 默认无金框；
- Hover/Focus 才出现细金边；
- 图标继续使用现有 28 枚线性图标。

## 6. 新组件代码

新组件先留在 AuraToolsExp，不立即进入 `AuraUiShared`：

| 组件 | 职责 |
|---|---|
| `ToolboxSurface` | 统一工具箱面板、分区和裁切 |
| `ToolboxCategoryItemV2` | 图标、标签、数量、选中和焦点 |
| `ToolboxSearchFieldV2` | 搜索图标、输入、清空和焦点边框 |
| `ToolboxIconButtonV2` | 设置、目录、清空等图标命令 |
| `ToolboxCheckboxV2` | 模块启用、禁用和焦点状态 |
| `ToolboxModuleRowV2` | 固定行高、文本层级和操作区域 |
| `ToolboxVisualSpec` | 颜色、字号、间距、资源键和响应式断点 |

只有当 Terrias 或第二个工具 MOD 也使用同类组件时，再把无语义部分提升到 `AuraUiShared`。

## 7. 新布局指标

建议基准：

| 元素 | 当前 | 建议 |
|---|---:|---:|
| 分类栏 | 144 | 164 至 172 |
| 分类项 | 42 | 46 至 48 |
| 页头 | 52 | 58 至 60 |
| 模块行 | 84 | 92 至 96 |
| 模块图标 | 42 | 44 至 48 |
| 标题 | 18 | 19 至 20 |
| 状态 | 15 | 15 至 16 |
| 说明 | 13 | 13 至 14 |
| 行间距 | 8 | 7 至 8 |

920 x 848 下目标是稳定显示六至七个完整模块，而不是九至十个小字模块。

### 7.1 模块行结构

```text
[状态线] [图标]  功能名称
                 当前状态
                 一句话说明              [设置]  启用 [□]
```

约束：

- 设置按钮默认无金框，Hover/Focus 才显示；
- “启用”文字与复选框组成一个完整语义单元；
- 未启用不改变整行背景色；
- 警告使用琥珀状态线和文字，不再增加外框；
- 行本身不做 Button。

### 7.2 分类栏

- 选中项仅使用左侧金线和轻背景；
- 未选中项没有边框；
- 数量右对齐但降低亮度；
- 当前搜索跨分类时，投影到“全部”状态；
- 图标保持 20 至 22 像素，不缩小到难以辨认。

### 7.3 页头

- 标题无完整金框，只保留底部分隔线；
- 搜索框使用低对比度控件资源；
- 搜索聚焦时才显示金色边；
- 数据目录按钮使用同类轻量图标按钮；
- 页头不再同时嵌套三层九宫格。

## 8. 响应式与采样

### 8.1 两档布局

宽度充足：

- 分类栏 172；
- 搜索框 250 至 280；
- 模块行 78；普通状态不显示摘要或说明。

紧凑宽度：

- 分类栏 152；
- 搜索框 200 至 220；
- 模块行 92；
- 说明允许截断，但标题和状态不得缩小到 12 像素以下的实际屏幕尺寸。

### 8.2 资源导入

- 新 2x/4x 工具组件使用 Bilinear；
- 原生大面板和原生标签使用 Bilinear；
- 线性图标使用 Bilinear；
- 只有像素表情等真正像素素材使用 Point；
- 继续禁止 NPOT 自动缩放和有损压缩。

## 9. 实施顺序

### P0：视觉基准冻结

1. 保存用户提供的真实游戏截图作为原生基准。
2. 保存当前工具箱截图作为反例基准。
3. 定义 `ToolboxVisualSpec`，停止在组件内散写尺寸和颜色。

### P1：资源样板

1. 创作五个新资源。
2. 输出 100%、75%、50% 三档联系表。
3. 在空页面中只展示组件状态，不先接业务数据。
4. 批准后才能进入生产壳层。

### P2：Unity Preview 接入

1. 替换分类栏、页头、图标按钮和复选框。
2. 模块行改为 92 至 96 高。
3. 保留原生顶层标签和窗口边界。
4. 重新生成默认、长文本、异常、空结果和扩展截图。

### P3：AuraToolsExp 生产接入

1. 将同一资源和 `ToolboxVisualSpec` 接入生产 UI。
2. 不改模块目录、配置、状态投影和二级页所有权。
3. 重建 `Entry.dll` 并运行现有行为、架构和资源门禁。

### P4：视觉门禁

增加以下断言：

- 工具箱内部不得直接使用 `NativeButton`；
- `NativePanelLarge` 只允许用于顶层窗口或重要 Overlay；
- 页面默认可见金框组件数量受限；
- 分类标签全部可见；
- 920 x 848 下至少六行完整模块，说明文字实际字号不低于约 11 至 12 像素；
- 设置按钮默认态无完整金框；
- 所有截图外框不触边、底层探针为零；
- 15 张截图保持唯一哈希且无空白。

## 10. 验收标准

- 第一眼仍然属于游戏原生设置窗口，但内部不再像金框组件拼贴。
- 顶层标签最响，页头次之，模块标题再次，说明最弱。
- 金色只出现在外框、选中、焦点和警告。
- 左侧分类名、模块标题和状态在 920 x 848 下不需要眯眼辨认。
- 设置与启用操作语义明确，不依赖猜测方框含义。
- 原生资源在其原本语义和接近原始尺寸处使用；其它位置使用新组件。
- HTML 和 Unity Preview 使用同一视觉规格，不再各自手写一套近似值。

## 11. 不建议继续采用的方案

- 继续给更多内部控件套原生按钮九宫格；
- 只提高当前文字亮度而不调整密度；
- 只把 Point 改成 Bilinear，而不解决资源语义错配；
- 用一张整页 AI 背景遮盖组件问题；
- 退回完全现代化灰黑 UI；
- 直接修改玩法模块或重新集中二级页所有权。

本方案需要创作新的 UI 组件，但创作范围应限制在五个可复用基础资源和七个工具箱组件，不制作大面积装饰插画。
