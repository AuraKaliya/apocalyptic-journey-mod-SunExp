# AuraToolsExp 事件CG：立绘海报运行合同

日期：2026-09-06。此合同替代队伍舞台v2；当前使用`team-poster.v3`与处理后队伍场景协议v2。

## 展示行为

事件CG以真实队伍的角色立绘组合成一个场景，支持1—8人。角色按面部锚点和面部尺寸定位，宽翅膀、衣摆和帽檐不参与面部大小归一化；原有按Idle小人落脚线排队、舞台、个人姓名牌和肖像面板回退已移除。

角色使用没有底板的柔边裁切窗口，控制宽体装饰横向覆盖；5—8人时，前排的最高可见位置同时受后排面部保留区约束。当前布局始终不主动镜像，避免翻转不对称的服装与饰件。标题与全队署名由同一渲染器排版，不显示布局类型或参与者计数等实现信息。

七个场景分别使用开场、普通胜利、点金、仪式、诅咒、失败、冒险结算的插画背景。画布保持用户配置的逻辑比例，在窄窗口中适配显示。轻动态包括有界推镜、前景位移和小幅光效明暗；每个场景可以关闭轻动态，原有时长和画布覆盖继续生效。

## 素材范围与选择

生产目录：`AuraToolsExp/SharedResources/EventCg/event-cg.art.json`。当前包含15套形象、6张事件专用姿势、7个主题与32个逻辑资源条目。

- 精确匹配的角色/皮肤事件姿势优先。
- 自定义皮肤没有匹配姿势时，先读取该皮肤的`Character`或`CareerImage`。
- 缺少专用姿势时使用相同角色的中性立绘。
- 目录之外的角色可以使用职业注册的`Character`或`CareerImage`；不读取`Animation/Idle`。
- 无法解析必要立绘时不展示残缺队伍，当前CG失败并保留原生界面；错误进入诊断。

普通与异色分别注册。素材中的候选角色身份由实际RoleId匹配；当前目录也保留同形象的显式状态别名。预览默认优先展示已确认的四人样张角色，可切换人数和“换一组”，嵌入预览与全屏预览使用相同参数与同一共享渲染器。

六张姿势分别是：卡洛琳普通胜利/失败，可可普通胜利/仪式胜利，阿米莉娅普通胜利，乌娜普通胜利。其余角色与事件使用中性立绘，这是明确的素材覆盖策略；本轮没有声称完成全部105张姿势。

## 所有权与资源加载

AuraToolsExp拥有目录、场景选择、玩家配置和角色资源适配。共享CG拥有规划、渲染、媒体缓存、网络校验和释放。内容MOD不新增主动播放入口。

每个资源声明包内相对路径、面部位置/大小及最多四个关联资源。路径解析必须留在EventCg目录内，角色图与附属图使用相同的源画布坐标。前伸手部、掌上火焰、前景和光尘都使用owner-qualified逻辑ID，并经现有媒体仓库加载。

`AuraCgScenePresentation`持有一次加载和展示所需的媒体保留句柄。媒体仓库复用既有引用计数账本，保护仍在预览或播放的资源；即使资源被LRU移出缓存，也要等最后一个场景释放后才进入实际销毁。预览替换、窗口关闭、加载取消、播放结束和全局组件销毁都释放句柄。渲染器Hide清空池内Sprite引用，Dispose清理自己的遮罩/渐变资源。

关闭一个预览不会清空其他CG的媒体仓库。全局CG组件销毁时先关闭仍存活的预览与主覆盖层，再释放媒体仓库。

## 协议与兼容

队伍场景协议升级到v2，位置和宽高代表面部构图区域，增加`MotionEnabled`。`LayoutId`必须是`team-poster.v3`。旧v1场景不能被当作新布局播放；本地注册的旧舞台模板在规划前单向归一化为当前布局。

外层CG信号协议没有改变。事件CG兼容声明升级到版本2，能力包括`processed-team-scene.v2`和`portrait-artwork.v1`；角色CG与卡牌CG继续使用原有信号链路。

面部标注、附属层详情、路径、图片字节与缓存键均留在本地资源解析阶段。RPC仍只携带经过校验的角色身份、逻辑资源ID和有界场景计划，不加入伤害排名或历史记录。

本轮公开API变化为：场景版本/布局/build id常量更新；新增局部立绘与附属层元数据类型；`AuraCgResolvedSceneAsset.Artwork`及`AuraCgScenePlan.MotionEnabled`。没有向共享层引入AuraTools内部类型。

## 配置迁移

现有背景、时长、逻辑画布、场景开关和战斗范围保持可读。背景为空表示使用主题默认插画；自定义背景失效时退回对应主题背景并诊断。恢复默认删除玩家表现覆盖，并恢复轻动态默认开启。旧配置缺少`motionEnabled`时使用true。

原来的角色Idle解析器与专用动画配置辅助类已从事件CG运行路径移除。历史HTML舞台原型保留为档案，不参与当前验收。

本地关闭轻动态会在本地资源元数据中关闭推镜、位移和脉动，即使主机发送的计划启用了动态也尊重接收端的关闭偏好。

## 验证入口与限制

- `tools/Test-AuraCgShared.ps1`：信号/网络行为、布局、面部归一化、媒体保留和释放。
- `tools/Test-AuraToolsExp.ps1`：配置往返、目录选择、包内资源引用、工具模块内容。
- `tools/Preview-EventCgPoster.ps1`：将正式CG规划器/渲染器源码编入隔离Unity验收播放器，覆盖人数、主题、窄画面、轻动态关闭、输入穿透、Hide后复用与父节点销毁后Dispose。
- `tools/Test-SharedRuntimeCompatibility.ps1`与主消费者构建/发布：核对公开API切换和包内DLL一致性。

Unity验收仅替换游戏字体查询，使用相同绘制与布局源码；画面通过离屏摄像机读取，同时检查非空内容与不同场景截图差异。这属于Unity渲染证据，不等于真实游戏的事件触发和联机验收。

真实游戏仍需检查：胜利/逃跑原因、失败与冒险结算衔接、实际皮肤绑定、远端v1场景拒绝、设置页反复开关，以及CG关闭后下一原生界面可点击。发布结果和本次已执行检查应在任务报告中分别说明。
