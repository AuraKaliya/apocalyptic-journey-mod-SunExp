# 卡牌工坊界面改版

日期：2026-09-19。依据本次确认的深紫与克制金色工作台方案实施。责任属于 AuraToolsExp 的 CustomCards 功能。当前为作品文档 v4、节点版本 2、运行库修订 5；历次验收记录按版本保留。

## 实机反馈后的设计一致性修正

首轮实现未充分还原已确认的布局。它保留了旧式流式行、文字工具按钮和偏高的侧栏阈值：节点库 1120、参数栏 900、卡面侧览 1080、试算双栏 1000。在用户所用窗口下，界面退化为隐藏侧栏和上下堆叠，与设计稿不同。费用行的固定首选宽度也会把稀有度挤到下一行。

首轮隔离环境使用 Unity 2022，并在 PreviewAdapter 中另行实现文本、输入框和滚动区域。生产文本工厂在设置首选宽度后会清除伸缩宽度，输入框也有不同的最小尺寸；这些行为没有进入当时的界面验收。原检查覆盖交互可达性，但没有证明设计排布一致、初始节点完整可见或网格各象限的实际像素输出。

修正后的 `CustomCardUi` 统一生产和隔离环境中的文字、输入、布局与滚动几何；宿主只负责字体、窗口关闭路由及游戏资源。工坊挂载到宿主根 Canvas，避免继承工具箱内部窗口的可用范围和滚动遮罩。顶部历史操作改为图标并与导航分开，属性使用等宽双列表单和连体分段选择，卡面保留侧览与独立工具行，试算保留左右两栏。节点采用统一紫色框体、点阵背景和布局完成后的首次适配。

边框采用原生 Image 边条，像素网格与透明棋盘使用原生 RawImage；原自绘边框、网格四边形生产路径已移除。验收升级至游戏相同的 Unity 6000.0.46f1 / URP 17.0.4，并从安装文件提取游戏随附的中文后备字体用于预览。新增检查包含费用与稀有度同排、分段控件等宽、试算双栏、初始节点不被裁切，以及缩放和嵌套遮罩下四个网格象限的像素回读。

安装检查另发现 AuraToolsExp 与 Terrias 目录中的 Aura.Shared.dll 不同；这不作为已证实的布局问题根因。发布部署必须统一两个消费者的完整产物。

游戏进程进一步确认默认窗口为 1600×900，根 Canvas 缩放为 0.8333333。原来的 1 单位描边小于一个物理像素，回读图中出现缺边。工坊现在补偿小于 1 的宿主缩放，维持参考控件尺寸；边条依据实际层级缩放至少覆盖 1.25 个物理像素，图缩放和窗口尺寸改变时重新计算。

隐藏窗口的 ScreenCapture 首次返回黑帧，不能算视觉验收。游戏验收改用当前游戏资源、生产 UI 层级和 URP SingleCameraRequest 离屏回读，并拒绝没有有效 UI 像素的结果。捕获期间临时使用离屏相机，随后恢复原 Canvas 相机和模式；报告与图像应称为游戏进程内渲染回读，不混同于桌面截图。

## 现行界面

- 主窗口默认铺满游戏窗口，四周保留 12 个物理像素安全边距；工坊和其他内置详细设置统一使用 `AuraToolsWindowHost`。顶部包含返回、作品名、保存状态、作品库、保存、制作和更多操作，取消单独占一行的作品名。效果蓝图、卡牌属性、卡面三个页签与撤销操作使用不同视觉层级。
- 属性包含名称、能量步进输入、稀有度、类型分段选择、焚毁/保留复选框和可选风味文字。费用与稀有度保持双列，完整表单与原生预览并排。
- 卡面页直接嵌入生产画板，保留尺寸、模板、导入、四种工具、真实色板、缩放、平移和网格。画板使用工坊统一撤销历史；提交笔画后刷新预览，未完成笔画的像素仍在当前作品中。
- 蓝图优先保证画布空间；宽窗口显示可折叠分类节点库与选中节点参数，窄窗口通过节点/参数入口打开。节点不再重复展示整段说明与“就绪”文字，错误、未接入流程和端口类型仍可见。节点说明在对应入口查看。
- 试算页面、模拟器、场景模型、执行轨迹及专用布局已移除；制作前保留蓝图和输入检查。
- 作品库合并我的作品和生产清单中的内置模板，以原生卡牌缩略图辅助识别。副本、导入导出、脚本、指南使用作品菜单。
- 删除侧栏、底栏和制作成功提示中的货币说明。保存失败、资源缺失和制作错误保留。

## 原生展示契约

`CustomCardPreviewHost` 从游戏 `UI/DictionaryUI` 的 `TempList` 取得 `DictionaryShowItem`，由其 `Init` 和 `ICard` 处理原生卡框、费用、说明与关键词。没有保留旧的 RawImage 加文本卡牌预览作为另一条生产路径。

`CustomCardPresentationData` 为制作与预览提供同一套展示字段。预览建立独立 `DataConfig`，不写账号仓库、不生成 RawData、不预编译玩法脚本，并将原生 `SetCardMsg` 必须调用的 `InitScript` 绑定为无操作。无效草稿显示“效果尚未完成”，具体错误留在编辑界面，不把未完成效果伪装成可制作成品。

效果正文按触发时机组织为自然语句。无条件位于入口末尾的停止节点不再显示；分支、循环内的提前结束仍说明“不再执行此次触发的后续效果”。节点目录和成品说明不再机械拼接“使用者 · 使用者抽牌”。`CardBlueprintDescriptionCompatibility` 对带已知编译器标识的自建成品执行一次性描述更新，同时更新运行数据和可携带的 RawData；版本字段为 `AuraToolsCustomCardDescription=2`，效果脚本与卡牌身份保留。沿用加载、重置、预编译和启动时账号卡牌恢复入口，启动批量更新后保存账号数据。未知来源的描述不推断重写。

节点在 80% 及以上显示接口与参数，55%～80% 显示标题和关键摘要，低于 55% 显示标题、连线与错误标记。摘要使用节点实际剩余高度，删除每个节点重复的“放大查看接口”；标题在节点内部省略显示，完整内容可通过悬浮底栏和右侧参数栏查看。节点库和参数栏可分别收起，大窗口宽度分别为 212 和 304；属性和卡面的预览侧栏可收起。

自绘卡面只在当前视图中持有纹理和 Sprite，并同步原生关键词展示的图标；不会为每个编辑笔画写入永久卡面文件。换稿、切页、关闭和失败时释放视图、脚本上下文与自有资源；材质只在原生确定的卡面节点上创建并由该预览实例释放。原生展示生命周期仍通过 Aura.Shared 的 reset 边界处理。

原生依据为仓库 Managed 对应的 v1.0.24831968 反编译。Witch.dll 与该快照的 SHA256 相同：`CD829F84F5A52A6B53973C676BF3DF4618A15F479A23BBA35B82E6802C6CDC83`。源码和现有 Terrias 图鉴消费实例证明调用路径；实际渲染结果以对应的游戏验收记录为准。

## 最终交付证据

### 工具箱入口的层级修正

用户随后报告工具箱覆盖工坊。根因是工具箱的 `AuraToolsSettingsPanel` 使用 `Canvas.overrideSorting`，工坊改为根 Canvas 上的窗口后仅改变同级顺序，没有保留打开者的排序层。原先直接从主菜单 Canvas 打开工坊的验收没有覆盖此入口。

`AuraToolsWindowHost` 按打开者的有效 Canvas 排序和当前工具弹窗栈分配更高层级，同时配置对应 GraphicRaycaster。放大预览、确认框等子弹窗记录其逻辑所有者，所有者关闭时一并释放，避免透明遮挡残留。原工坊专用的 `CustomCardModalLayer` 和尺寸控制器已移除，布局与排序由公共容器管理。

### 状态选择与分段指南（前一版本）

本轮修复的边界是节点参数展示：数据、编译与运行时早已使用 `ResourceId`，但画布没有显示状态选择，折叠组合只显示数字，游戏内指南又只遍历标题和端口。保留原有文档 v4 / 运行库修订 5 和状态执行语义；不迁移或重写旧稿状态标识。

- `CardNodeCatalog.RequiresState` 统一单体／群体施加、单体／群体移除、读取状态层数五类节点的状态字段。画布有名称、图标与选择入口，参数栏有来源和操作含义，折叠组合也暴露各成员参数与定位入口。读取属性切换后仅展示相关字段。
- 状态选择器读取宿主有效资源目录，不实例化 BUFF 或执行状态脚本。全窗口显示搜索、来源筛选、完整分页列表与详情，按稳定 ID 选取并标记当前选择。原生加载行的来源优先采用游戏 `TryGetModDataConfigOwner` 记录；共享目录的 `BaseGame` 默认值不作为原生归属证据，没有明确归属时显示“来源未标注”。已登记的 MOD 名称与标识用于搜索和筛选。移除状态明确为整个状态；未持有时读取层数为 0。

### 初始蓝图不再自动入库（当前版本）

根因是首次布局后的 `Fit()` 与节点布局编辑共用 `changed(false)`，工坊把它们都设为 `dirty=true`；普通关闭的 `SaveBeforeClose` 和中断销毁的 `OnDestroy` 因而保存没有被用户编辑过的初始蓝图。此前验收为保护真实作品数据会主动清除测试控制器的 dirty 标记，遗漏了初始草稿的正常关闭路径。

改动通知现在明确区分内容、节点布局和视口浏览。自动适配、缩放、平移、定位、总览移动只更新视口；节点移动、尺寸、组合、整理等布局编辑仍进入撤销和自动保存。保存器不按名称或是否长得像默认蓝图筛掉作品，用户明确保存初始蓝图仍然有效。

回归用例先在旧实现上复现首次打开变 dirty，再验证连续三次打开、切页和浏览后以普通关闭及强制销毁退出，作品库保持不变；真实编辑关闭只保存一次、已保存作品仅浏览不增加版本、明确保存初始蓝图有效、节点布局编辑在中断销毁时仍保存。历史条目没有来源标记，无法可靠区分误存与主动保存，保留现有作品数据，不做按默认名称批量删除。
