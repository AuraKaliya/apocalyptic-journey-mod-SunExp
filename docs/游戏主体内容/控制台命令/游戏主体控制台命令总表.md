# 游戏主体控制台命令总表

适用版本：Steam 构建 `1.0.24605918`。本表依据该构建的控制台输入、命令实现和输入绑定代码整理，不包含 `Terrias`、`AuraToolsExp` 等 MOD 自己注册的调试入口。

## 使用方法与解析规则

- 按键盘反引号键 `` ` `` 打开或关闭控制台；它是 `Esc` 下方、通常与 `~` 共用的键。游戏实际绑定为 `<Keyboard>/backquote`。
- 输入命令后按 `Enter` 执行；`↑`、`↓` 可浏览本次进程内的命令历史。
- 命令名大小写敏感。大多数命令为全小写，但 `setId`、`Log`、`LogWarning`、`LogError`、`ShowReward` 等必须保持表中的大小写。
- 解析器直接按单个空格拆分，不支持引号和带空格参数。连续空格也会产生空参数，因此建议每段之间只留一个空格。
- 下文用 `<参数>` 表示必填，用 `[参数]` 表示可选；`<占位>` 表示实现没有使用该值，但解析器仍要求输入一个词。
- 控制台没有撤销或事务机制。`give`、`remove`、`variable set`、解锁类和切换流程类命令可能污染当前局内或后续存档，使用前应备份存档，联机局中不要随意执行。

解析器的固定错误包括：命令名找不到时显示“命令不存在”，实参数量超出签名时显示“参数过多”，缺少无默认值参数时显示“参数缺失”。方法内部还可能返回更具体的参数、数据 ID 或加载错误。

## `give` 二级命令

`give` 的公开签名固定要求两个参数，所以即使某个分支不读取第二个参数，也必须提供一个占位值。例如强制胜利应写成 `give win 1`，而不是 `give win`。

| 类型或别名 | 值 | 行为与前置条件 |
| --- | --- | --- |
| `maxsan` | 整数增量 | 增加最大理智。 |
| `card` | 卡牌 ID 或 `all` | 发放单张卡牌或卡牌表全部条目。单张优先进入主牌组，主牌组满后进入备用牌组；战斗中还会加入战斗牌表。`all` 不检查牌组容量或锁定。 |
| `time` | 整数增量 | 给角色 `SkillTime` 中每个既有技能计时项增加该值。 |
| `relic` | 遗物 ID 或 `all` | 发放单个或全部遗物；装备栏满足条件且少于 6 个时进入装备栏，否则进入未装备遗物列表。 |
| `bless` | 祝福 ID 或 `all` | 发放单个或全部祝福。 |
| `money` | 整数增量 | 增加金币。 |
| `san` | 整数增量 | 增加当前理智。 |
| `power` | 整数增量 | 战斗中增加当前能量；未开战时只返回警告。 |
| `timecount` | 整数增量 | 增加全局时间流 `GameRuntimeData.Time`。 |
| `true`、`truth` | 整数增量 | 增加真理之晶并刷新顶栏。 |
| `win` | 任意占位 | 调用战斗界面的可胜利流程；战斗界面未加载时失败。 |
| `str`、`strength` | 整数增量 | 增加力量，并同步已有的战斗临时属性。 |
| `luc`、`lucky` | 整数增量 | 增加幸运，并同步已有的战斗临时属性。 |
| `per`、`perceive` | 整数增量 | 增加感知，并同步已有的战斗临时属性。 |
| `wis`、`wisdom` | 整数增量 | 增加精神，并同步已有的战斗临时属性。 |
| `level` | 整数增量 | 将当前地图层数设置为“存档层数 + 增量”。 |
| `randomcard` | 数量 | 从当前卡包可用、非诅咒卡池按稀有度抽取；优先放入备用牌组，战斗中也加入战斗牌表。 |
| `randomcardbydeck` | 数量 | 与 `randomcard` 使用同类卡池，但优先放入主牌组，满后才放备用牌组。 |
| `draw` | 数量 | 战斗中立即抽牌；战斗 UI 未加载时通常会进入通用失败分支。 |
| `randombless` | 数量 | 从当前卡包可用且 `Weight <= 5` 的祝福池随机发放。 |
| `goodbless` | 数量 | 从正面、未锁定、当前卡包可用且 `Weight <= 5` 的祝福池随机发放。 |
| `randomrelic` | 数量 | 从未锁定、当前卡包可用且 `Rarity <= 3` 的遗物池按稀有度随机发放到未装备列表。 |
| `randomrelicByRarity` | 稀有度原始值 | 从指定 `Rarity` 的未锁定遗物中发放 1 个到未装备列表。大小写必须完全一致。 |
| `randomcardByRarity` | 稀有度原始值 | 从指定 `Rarity` 的未锁定、非诅咒卡牌中发放 1 张到主牌组。大小写必须完全一致。 |
| `def` | 整数增量 | 战斗中增加玩家防御；没有战斗玩家对象时仍会返回成功，但不会产生效果。 |
| `live`、`Live` | 任意占位 | 将角色死亡标志设为否，并把当前理智设为 10。 |
| `AllBuff` | 任意占位 | 战斗中把 Buff 表全部条目以 1 层添加给玩家；大小写必须完全一致。 |
| `ench` | 火漆／镶嵌 ID | 打开牌组选择界面，从主牌组选择 1 张牌并附加该火漆标签。 |
| `exp` | 整数增量 | 增加全局经验，每满 100 转为 1 级。 |
| `randomtest` | 任意占位 | 内部随机分布压力测试，执行大量抽样并写 Unity 日志；不建议正常游玩时使用。 |
| `slot` | 整数增量 | 仅老虎机模式且已有存档时，增加 `SlotChipReserve`。 |
| `escape` | 任意占位 | 将当前战斗状态切到 `Escape`。 |
| `unlimitsafe` | 任意占位 | 把安全箱卡牌和遗物次数都设为 `-999`，实现内部所称的无限次数。 |

补充注意：

- 数值分支普遍使用 `int.Parse`，允许负数但不做合理区间校验；无效数字会进入“给予物品失败”的通用异常分支。
- `give card/relic/bless all` 直接遍历完整配置表，可能包含内部、特殊或锁定内容，并可能产生大量重复对象。
- `give win/live/AllBuff/randomtest/escape/unlimitsafe` 虽不读取第二个值，仍必须带占位参数。

## `copy` 与 `remove`

### `copy`

| 语法 | 行为 |
| --- | --- |
| `copy card <InstanceID>` | 只在主牌组按实例 ID 查找并克隆卡牌；若原卡有火漆，也克隆火漆配置。 |
| `copy bless <InstanceID>` | 按实例 ID 克隆当前祝福。 |
| `copy relic <InstanceID>` | 只在已装备遗物列表按实例 ID 查找并克隆。 |
| `copy item <InstanceID>` | 当前返回“未实现的方法”。 |

这里要求的是运行时对象的 `InstanceID`，不是卡牌、祝福或遗物的数据表 ID。

### `remove`

| 语法 | 行为与已知边界 |
| --- | --- |
| `remove card <数据ID/InstanceID>` | 从主牌组或备用牌组移除第一个匹配项；带 `Eternal` 标签的卡不会移除。 |
| `remove card all` | 清空主牌组，并在战斗中清空战斗牌表；不会清空备用牌组。也接受 `All`。 |
| `remove relic <数据ID>` | 只从已装备遗物列表查找第一个匹配项，再同时尝试从两个遗物列表移除。 |
| `remove relic all` | 只清空已装备遗物列表，不清空未装备遗物列表。也接受 `All`。 |
| `remove bless <数据ID>` | 移除第一个匹配祝福。 |
| `remove bless all` | 清空全部祝福。也接受 `All`。 |
| `remove randomcard <数量>` | 从主牌组随机执行指定次数的移除；战斗中同步移除战斗牌表条目。 |
| `remove randombless <数量>` | 随机移除祝福。 |
| `remove randomrelic <数量>` | 随机移除已装备遗物。 |
| `remove all <占位>` | 清空主牌组、备用牌组、祝福、已装备遗物和未装备遗物，是最危险的清空命令。 |
| `remove item <占位>` | 当前返回“未实现的方法”。 |

## 流程、数据和内部命令详解

### `load`

| 语法 | 行为 |
| --- | --- |
| `load event` | 从未锁定且 ID 不含 `Sub` 的事件中随机选择并打开。 |
| `load event <EventID>` | 关闭当前事件／地图界面并直接打开指定事件。 |
| `load fight [common/elite/boss/LevelID]` | 启动真实战斗。不给参数时在当前层级池随机；三种类型按关卡 `Note` 过滤；其他值按关卡 ID 处理。`Fight` 也可作为首参数。 |
| `load fakefight [common/elite/boss/LevelID]` | 与 `fight` 选关逻辑相同，但调用虚拟战斗入口。`FakeFight` 也可作为首参数。 |
| `load build shop` | 打开商店。 |
| `load build tree` / `load build destiny` | 打开命运树。 |
| `load build break` / `breaks` / `Breaks` | 进入休息点。 |
| `load build ench` | 打开卡牌附魔界面。 |
| `load build random` | 在商店、命运树和休息点之间随机。 |
| `load reward [rewardType]` | 把奖励类型交给当前模式并打开奖励界面；普通模式通常忽略类型，老虎机模式会保存该字符串。`Reward` 也可作为首参数。 |

这些入口会直接关闭或替换当前 UI，并不保证当前事件、战斗或地图状态完成正常结算。

### 对话、数据和变量

- `dialogue show <DialogueID>`：显示指定对话。
- `dialogue next`：推进当前对话。
- `dialogue end`：结束当前对话。
- `check <ID>`：去掉查询 ID 中的 `*` 后，通过全局 ID 索引查找数据，并逐字段打印原始行；适合核对卡牌、遗物、Buff 等 ID。
- `variable show <key>`：读取一个运行时变量；`variable show all` 按键名排序打印全部变量，`all` 不区分大小写。
- `variable set <key> <value>`：写入字符串值并立即调用 `GameRuntimeData.Save()`。键和值都不能含空格，也不能使用字面占位值 `null`。
- `setId <player_id>`：更新 `GameConfigManager.PlayerId`，并在玩家对象存在时同步 `playerInfo.Id`；当前命令本身不调用保存。

### 场景、界面、日志和联网

- `updateback <SceneType>` 接受的命名值为 `Road`、`Castle`、`PuppetTheater`、`Forest`、`Chessboard`、`Courtyard`、`SlotMachScene`、`Curia`、`DollFairyTale`、`BalancedHolySee`、`DemonKing`。枚举解析区分大小写。
- `Log`、`LogWarning`、`LogError` 是供程序和调试使用的控制台输出入口。由于不支持引号，来源和内容各自只能是单个无空格词。
- `showack`、`showann` 分别打开致谢和公告界面。
- `ShowReward <占位>` 只打开奖励界面，不设置奖励类型。
- `connect <地址>` 会在本机正作为服务器时先停止主机，随后切换 KCP 传输、设置网络地址并启动客户端。源码的帮助文本也要求尽量只在游戏开始前使用。

### 解锁与事件中心

- `unlock`、`lockitem` 都会先去除 ID 中的 `*`。它们只处理已经存在于 `GameConfigManager.LockedIds` 的内容。
- `unlockall` 遍历所有锁定 ID 并加入运行时解锁列表。
- 三个命令本身都没有显式调用保存；是否落盘取决于之后的正常保存流程。
- `eventtrigger <event_key>` 直接触发一个无参数内部事件。错误事件名通常无效果，但正确事件名可能绕过剧情或战斗前置条件，应只用于明确知道订阅者的调试场景。

### 自动战斗

- `auto on` 仅在战斗中有效：先增加 999 能量、立即抽 10 张牌，再把战斗 UI 的 `autoCard` 设为真。
- `auto off` 仅关闭 `autoCard`，不会回收已经增加的能量或抽到的牌。
- 该命令返回 `void`，成功和失败说明写入 Unity 日志，不会作为普通返回文本显示在控制台。

## 战斗数值调试规则

倍率使用英文小数点并要求大于等于 0，例如 `0`、`0.5`、`1`、`2.5`；逗号小数不会通过解析。`1` 表示正常倍率。

### 敌人倍率

- `enemyall` 的字段还接受 `life`、`maxhp` 作为 `hp` 的别名，接受 `attack` 作为 `atk` 的别名。
- `enemytype` 的类型还接受：`normal`、`普通` → `common`；`精英` → `elite`；`领主`、`首领`、`无名` → `boss`。
- 全局倍率、类型倍率和单体倍率相乘。命令会立即重算当前敌人的攻击、防御、最大生命，并按原生命百分比换算当前生命，最低保留 1 点生命。
- `enemyone` 的目标可为当前敌人列表索引、数据 ID、实例 ID 或完整名称。索引优先按 1 开始处理，同时 `0` 也会指向第一名敌人；敌人名称含空格时应改用 ID 或索引。
- `enemygrow x` 只调整第一档之后的额外成长：当成长计数大于 1 时使用 `1 + (原计数 - 1) × x`。因此 `0` 去掉后续额外成长，`1` 为原值。

示例：

```text
enemyall hp 2
enemytype elite atk 1.5
enemyone 1 all 0.5
enemygrow 0
```

### 敌人 Buff

- `enemybuff` 的敌人目标规则与 `enemyone` 相同。
- Buff 目标可以是数据 ID、原始／本地化名称或配置表索引；名称含空格时应使用 ID。索引同样优先按 1 开始，`0` 也表示第一条。
- `enemylayerbuff` 的“层区”按 `MapManager.Level / 6 + 1` 的整数除法计算。若指定的是当前层区，会立即给现有敌人加 Buff；规则还会在该层区后续敌人初始化时应用。重复登记会重复添加。

示例：

```text
enemybuff 1 buff_10001 3
enemylayerbuff 2 buff_10001 5
```

### 玩家倍率与重置

- `debugmoney x` 把 `RoleTable.MoneyMultiplier` 设为四舍五入后的 `100 × x`；`1` 对应正常值 `100`。
- `debugmaxhp x` 只影响后续由脚本 `ChangeMaxHp` 施加给战斗玩家的最大理智增量，不会追溯修改已有最大理智，也不会影响 `give maxsan` 的直接写入。
- `debugheal x` 影响后续施加给战斗玩家的治疗量。
- `debugdef x` 影响后续为战斗玩家计算的基础防御／护盾收益。
- `debugcleardef on` 在每次玩家回合开始时，把战斗状态表中所有单位的当前防御设为 0；也接受 `true`、`1`，关闭值可用 `off`、`false`、`0`。
- `debugreset` 把全局、类型、单体和玩家倍率恢复为 `1`，金币倍率恢复为 `100`，关闭自动清盾，清空层区 Buff 登记，并重算当前敌人。它不会撤销已经获得的金币、最大理智、治疗、护盾或已经添加到敌人身上的 Buff。

这些调试值主要保存在静态运行时字段中，除 `debugmoney` 直接改写当前 `RoleTable` 外，源码没有为它们提供独立持久化；退出进程后不要假设仍然有效。

## 已知实现边界

- 控制台通过反射按方法名直接查找 `Commands` 的公共方法，并没有单独的白名单或命令注册表。
- `Commands` 中还存在供战斗代码调用的公共属性、`DebugGet...`、`DebugApplyEnemyBuffs`、`DebugClearAllShields` 等辅助 API。部分方法理论上可被反射命中，但参数类型并非控制台支持的字符串，或本来就是引擎回调，因此不计入上述 36 个可用命令，也不应作为稳定命令使用。
- `help` 只对带 `HelpText` 特性的命令有效；`setId`、日志、界面、解锁和事件中心等内部入口即使可执行，`help <命令>` 也会报告参数异常。
- 使用数据 ID 时优先采用去掉原始 `*` 标记后的运行时 ID。可从[卡牌总表](../卡牌内容/游戏主体卡牌总表.md)、[遗物总表](../遗物内容/游戏主体遗物总表.md)、[Buff 总表](../BUFF内容/游戏主体BUFF总表.md)或[当前数据快照](../combat-knowledge/table-exports/witch-tables-20260810-135440.json)核对。
