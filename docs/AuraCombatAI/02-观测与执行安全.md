# 观测与执行安全

## 玩家等价信息

AI 可使用：

- 当前公开生命、护盾、能量、手牌、牌库计数和公开状态；
- 已公开的卡牌、技能、遗物、祝福、敌人意图和战斗历史；
- 完整游戏规则以及由公开历史唯一推导出的状态；
- 规则允许玩家在当前界面查看的目标和交互选项。

AI 不可使用：

- 未公开牌序、未发生的随机结果或敌方隐藏选择；
- 运行时对象中存在但玩家界面和公开历史无法确定的字段；
- 用完整模拟状态反推隐藏身份的特征；
- 未来帧、结算后对象或训练标签。

`CombatPublicFeaturePolicy` 是状态和动作特征进入模型前的最后过滤层。策略价值编码、在线样本和长期轨迹都必须经过相同边界。

## 根抽样信念

不完全信息不是通过“取一个最可能隐藏状态”解决。每次搜索模拟在根部按公开信息和可行集合抽取一个隐藏状态假设，随后在该模拟内保持一致。这样可避免树中途随意改变牌序或随机结果，同时近似边缘化不可见状态。

根抽样不允许引入真实宿主隐藏数据；抽样器只能从公开约束构造可能世界。

## 候选合法性

候选进入搜索前必须满足：

- 当前处于玩家行动窗口；
- 卡牌或技能实例仍存在；
- 费用可支付；
- 目标存活且目标类型正确；
- 冷却、使用次数和同实例重复使用限制满足；
- 所有注册的 `ICombatSimulationRule` 返回合法。

搜索中的模拟状态会重复检查费用、目标和使用组。最终提交前，动作事务还会用真实当前状态再检查一次。

## 事务状态机

动作事务遵循：

```text
Idle -> ExecutingRoot -> AwaitingPrompt -> Selecting -> AwaitingSettlement -> Completed
                    \-----------------------------------------------> HandedOff
                    \-----------------------------------------------> Failed
                    \-----------------------------------------------> TimedOut / Cancelled
```

事务绑定 `BattleSessionId`、状态指纹、候选 ID 和目标。后台结果回到主线程后，先以新的公开观测执行指纹绑定，再调用原生执行接口；因此 `ExecutePrepared` 不需要为结束回合做第三次完整采集。会话变化、状态前进、目标消失或 UI 切换会使旧回执失效。只有原生执行已接受且公开状态出现因果进展，才记为 `Completed`。

卡牌和技能进展通过 `AuraCardActionTransactionRouter` / `AuraSkillActionTransactionRouter` 观察。战斗终局不调用敌人对象的 `StopAllCoroutines()`；其他 MOD 和表现层拥有的协程不属于自动战斗的清理范围。

## 决策取消与结算探测

- 在线搜索不使用通用 CPU FIFO，而由一个专用线程串行执行；新执行请求会取消影子、预测、教师或过期执行请求。
- 取消 token 在候选循环、根动作覆盖、每次模拟、每层展开、叶估值和模型调用边界检查；硬截止会产出 `DeadlineExceeded` 回执，而不是只在主线程丢弃迟到结果。
- 结算等待先用行动窗口和 UI busy 做轻量判断，完整观测按 `0.1s -> 0.25s -> 0.5s` 级别退避，直到事务截止或原生事务信号提前唤醒。
- `OutcomeEntering` 停止新生产者，`BattleSettling` 尝试保留最后公开状态，`BattleFinalized` 才写终局结果和释放记录器会话。

## 未知动作策略

- `conservative`：未知语义动作不能凭高规则分强行执行，优先已知安全动作。
- `allow`：允许进入候选，但仍受合法性、风险和事务门禁控制。
- `handoff`：遇到未知动作时停止自动决策，交还玩家。

未知动作不得静默当作零风险或零收益。知识覆盖报告必须列出缺失定义和来源。

## 失败安全

以下情况立即停止本次自动动作：

- 无合法候选；
- 公开状态投影失败；
- 模型产生非有限值；
- 搜索未得到根动作证据；
- 动作事务超时或结算不一致（交还玩家，不把它误报为模型能力故障）；
- 规则集、模型、样本或轨迹协议不匹配；
- 权威覆盖或模拟门禁未通过。

停止动作不等于自动选择结束回合。只有结束回合本身是合法候选并通过搜索时才会执行。
