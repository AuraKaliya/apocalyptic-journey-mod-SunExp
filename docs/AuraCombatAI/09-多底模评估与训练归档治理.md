# 多底模评估与训练归档治理

## 多底模的用途

独立训练出的多个底模用于降低随机初始化和训练样本波动带来的误判。运行时仍只启用一个通过评估的底模；当前不对独立初始化的网络直接做参数平均，也不会由评估工具自动替换游戏中的启用模型。

多模型比较必须复用同一规则集、原生程序包、训练语义、特征协议、验证战役和冻结种子。使用以下入口运行两到八个模型的全配对锦标赛：

```powershell
tools\Run-AuraFoundationFrozenTournament.ps1 `
  -ResultPath @(
    "D:\results\model-a\foundation-worker-result.json",
    "D:\results\model-b\foundation-worker-result.json",
    "D:\results\model-c\foundation-worker-result.json") `
  -JobPath "D:\results\model-b\foundation-worker-job.json" `
  -OutputDirectory "D:\results\frozen-tournament" `
  -CampaignsPerDifficulty 64 `
  -SeedStart 3000000 `
  -Parallelism 16 `
  -ReuseCompletedPairs
```

工具先验证模型兼容键，再对每一对模型使用完全相同的 Normal/Advanced 种子。输出包含逐对 Wilson 区间、独占胜场、胜率、平均战斗深度和总排名。排名第一只表示“候选优胜者”，模型导入和启用仍需显式操作，并应继续完成游戏内普通难度冒险测试。

冻结锦标赛只在完整战役边界并行；原生脚本兼容层的当前模拟上下文按线程隔离，禁止多个战役共享上下文指针。报告会记录无效战役的终止原因，并以 `InvalidPairs = 0` 和 `Deterministic = true` 作为有效结果的硬门槛。外层任务被中断后可使用 `-ReuseCompletedPairs` 复用参数、模型路径、种子范围和并发度完全匹配的已完成配对，不会重复计算。

## 成功案例归档

归档协议仍为 `success-case-archive-worker-v4`，以保持现有可训练案例可读。存储规则调整如下：

- `o/` 保存轻量战役观察，用于策略统计和奖励残差训练；每个兼容键最多接纳 8192 项。
- `c/` 只保存确实携带训练 episode 的专家案例，不再保存仅用于验证统计的完整战役对象。
- `e/` 保存指向 `c/` 的小型引用；每个兼容键最多接纳 2048 项。
- 新写入的观察和专家案例使用 `.json.gz`；读取器同时兼容旧 `.json` 和新 `.json.gz`。
- 达到容量上限后停止接纳新项，不在训练进程中自动删除历史文件。

旧归档可先执行只读盘点：

```powershell
tools\Optimize-AuraFoundationCaseArchive.ps1 `
  -ArchiveRoot "D:\path\foundation-success-cases"
```

确认报告后再显式执行整理：

```powershell
tools\Optimize-AuraFoundationCaseArchive.ps1 `
  -ArchiveRoot "D:\path\foundation-success-cases" `
  -Apply
```

整理器只处理归档根目录下的 `v4/<compatibility>/e|c|o`：保留受容量约束的专家引用和观察，移除没有专家引用的完整案例，并将保留的旧 JSON 原子压缩。`-Apply` 会删除被判定为冗余的归档文件，应先检查 dry-run 报告。

## 指标与困难种子分流

所有候选 epoch 在进入调优竞技场前都会继承完整训练指标清单，再覆盖自身的校准指标。因此，无论最终选中最佳 epoch 还是保留候选 epoch，Champion 都应保留训练、验证、测试、优化器、碰撞率、温度和 frame 分层指标。

困难种子按反事实可解性分流：

- `action-solvable`、`action-sensitive` 和尚未定性的 `unknown` 可进入战斗策略困难种子课程。
- `build-limited-provisional` 与 `build-limited` 不再消耗战斗动作训练配额。
- Worker 输出 `foundation-build-limited-seeds-v1.jsonl`，供后续牌组构筑、奖励权重或专门课程使用。
- 每轮结果分别记录正式和暂定的构筑受限分流数量，便于判断问题究竟来自战斗决策还是战前构筑。
