# 阶段 1.4：本地上下文残差与预测框修订

## 本轮结论

本轮把训练应用闭环收进 AuraToolsExp MOD 环境，同时修复了旧线性残差无法学习
“同一动作在不同战况下价值不同”的结构性问题。

模型是本机文件，不参与联机同步。模型不按当前加载的 MOD 列表启停，也不把
MOD id、卡牌 id 或 Unity instance id 当作决策输入。原版与 MOD 内容只要被解析成
相同的统一战斗语义，就可以复用已学习的上下文偏好；未识别语义、训练未覆盖的
动作类别或明显超出训练范围的特征会自动把残差缩小到零，回退到规则底模。

## 为什么旧模型会错误压低护盾

旧训练使用“人工动作特征减 AI 预选动作特征”的成对排序。如果特征只有
`defend`、`damage` 等动作静态值，模型只能学到“护盾整体较差”，无法表达：

- 敌方本回合有可格挡伤害时，护盾有用；
- 敌方没有攻击意图时，同一张护盾可能浪费；
- 已有护盾覆盖伤害后，额外护盾的边际价值下降。

v4 为每个候选增加动作与状态的交叉上下文：

- `requiredDefend`、`usefulDefend`、`wastedDefend`；
- `effectiveDamage`、`overkill`、`lethal`；
- `effectiveHeal`、`overheal`；
- `effectiveDraw`、`overdraw`；
- 能量稀缺度、零费有效动作、各效用分项和动作语义类别。

训练只学习这些稳定、可解释的上下文特征。

## 适用性门控

残差实际修正为：

```text
appliedResidual = boundedRawResidual × applicability
applicability = min(语义可信度, 动作类别样本支持度, 特征范围支持度)
```

因此模型不能绕过合法性、目标有效性、费用和事务控制，也不会对完全未知的 MOD
机制强行外推。日志会同时记录 `base`、`residualRaw`、`residualSupport`、
`residualApplied` 和 `final`，便于定位模型是否真正生效。

## 游戏内训练和应用

1. 开启“记录训练样本”。
2. 选择“人工示范采集”或“全部轨迹采集”。
3. 关闭自动接管，正常人工出牌；黄/红/绿提示是否可见会写入样本。
4. 累积人工选择与 AI 预选不一致的已完成动作。
5. 在当前决策风格下点击“生成候选”。C# 训练任务在后台执行，不要求玩家安装
   Python，也不阻塞 Unity 主线程。
6. 查看日志中的样本数、偏好对数、权重数和候选文件路径。
7. 点击“导入候选”。
8. 先选择“影子评估”：实际仍执行规则底模，日志比较底模与模型建议。
9. 回归确认后选择“受限应用”；任何适用性不足的候选仍自动使用底模分数。

三个采集模式的中文含义：

- `auto`：自动轨迹采集；
- `shadow`：人工示范采集；
- `hybrid`：全部轨迹采集。

三个模型运行模式彼此独立：

- `off`：关闭；
- `shadow`：影子评估，不改变实际动作；
- `active`：受限应用有界残差。

模型按决策风格保存，避免把“激进/均衡/稳健”的人工偏好混为一组；这不是
MOD 环境隔离。

## 预测黄框

卡牌黄框不再把旋转卡牌压成轴对齐矩形。运行时直接读取
`CardItem.uiElement.GetWorldCorners`，将四个实际角点变换到 FightUI 坐标系，再用
四条非交互 UI 边组成随卡牌扇形旋转、位移和缩放的四边形。该方案不创建 Shader
或材质实例，开销固定为四个 `Image` 和每帧少量向量计算。
