# 阶段 1.2：事务、策略与训练数据修订

> 本文保留阶段 1.2 历史合同。当前威胁规划和训练协议已经由
> [阶段 1.3](09-阶段1.3威胁规划与训练闭环.md) 升级到 v3。

## 修订目标

本轮针对 2026-07-23 实战日志中暴露的问题完成四项修订：

1. 接入游戏原生强制弃牌和烧牌流程；
2. 统一根行动、交互和结算的事务截止时间；
3. 用边际价值替代固定的攻击/防御/辅助牌优先级；
4. 将训练采集升级为可审计的 v2 JSONL。

代码完成不等于游戏内验证完成。强制弃牌、烧牌、动画时序和不同
`Type` 参数仍需在真实对局中回归。

## 原生交互

自动战斗现在监听：

- `DeckUI.CreateDeckMenuForSelect`；
- `FightUI.SelectCardToAction`；
- `FightUI.ThrowCardScript`；
- `FightUI.Burning`。

手牌交互按以下步骤执行：

1. 等待原生选择 UI 真正打开；
2. 过滤失效、禁用、已使用、无选择容器的牌；
3. 弃牌和烧牌额外排除 `Froze`；
4. 每次只调用一次原生 `HandleSelectModeClick`；
5. 验证 `SelectedCard.Count` 增长后才选择下一张；
6. 等待选牌动画重新启用卡牌；
7. 达到精确数量后只触发一次确认；
8. 等待原生 UI 关闭后才把交互标记为完成。

单次选择在 0.8 秒内没有产生数量变化时，交互失败并交还玩家。不会
直接调用 `InternalThrow`、`BurnCard` 或业务回调。

## 根行动事务

事务状态包括：

```text
Idle
ExecutingRoot
AwaitingPrompt
Selecting
AwaitingSettlement
Completed
HandedOff
Failed
TimedOut
Cancelled
```

从根行动提交开始，只创建一个截止时间。结束回合、敌方行动、强制选择、
动画和最终结算不再分别续期，也不再给结束回合强制增加 60 秒。

处理规则：

- 重复帧不能再次提交同一根行动；
- `Pending` 继续等待，但不能绕过截止时间；
- `Failed` 和失效目标停止自动战斗，不自动重试；
- `HandedOff`、关闭自动战斗和配置关闭保留当前原生 UI；
- 战斗结束从任意中间状态取消事务；
- 训练样本对一次根行动最多写入一次。

## 相对价值策略底模

新底模使用以下信息：

- 有效伤害和确定斩杀；
- 低生命或预计伤害下的有效防御、治疗；
- 抽牌空间、能量、减费和生成牌；
- 增益、减益、净化和持续效果；
- 能量稀缺产生的机会成本；
- 技能冷却机会成本；
- 过量伤害、溢出防御、随机性、交互和未知语义风险；
- 已知正收益 0 费行动的小幅顺序加分。

0 费不是无条件使用条件。随机、未知或纯负面的 0 费行动不会仅凭费用获得
高优先级。技能也不等同于免费牌；长冷却技能会承担额外保留成本。

当前仍是单步规则评分。两步有限前瞻应在真实卡池语义覆盖率验证后再加入。

## 训练数据 v2

新文件：

```text
Logs/AuraToolsExp/auto-battle-training-v2.jsonl
```

每个根行动一行，协议为 `aura.combat-ai.sample.v2`，主要包含：

- `battleSessionId`、`decisionIndex`、`transactionId`；
- 动作前后状态指纹；
- 全部候选的稳定 `sourceId`；
- 合法性、拒绝原因、语义、数值特征、效用分项和规则分数；
- 选择结果、配置和版本；
- `Completed`、`Failed`、`TimedOut`、`HandedOff` 或 `Cancelled`；
- 分项奖励、终局奖励和战斗结果。

所有非有限数值会在写入前归零。失败、超时和接管样本仍会记录，但离线训练
必须隔离或单独分析，不能当作正常结算样本。

“记录训练样本”仍然只是采集开关，不会在游戏进程内训练或更新模型。

## 自动化覆盖

共享纯逻辑测试覆盖：

- 根行动单次提交；
- 统一截止时间；
- 玩家接管和战斗结束取消；
- 逐张选择、无进展超时和单次确认；
- 0 费辅助行动的顺序价值；
- 未知 0 费行动不被强制使用；
- 技能冷却机会成本；
- v2 全候选、终局奖励和非有限数值清洗。

游戏 API 适配器通过当前仓库 `Managed/Witch.dll` 编译验证。发布前还需运行
所有共享消费者构建、共享发布门禁和 DLL 哈希一致性检查。
