# 测试策略与场景矩阵

## 测试层次

| 层次 | 目的 | 运行位置 |
| --- | --- | --- |
| 纯逻辑测试 | 决策图、效用、多选、注册和交互状态 | 任意开发机 |
| 编译测试 | 验证 `Managed/` 签名与 `net472` 消费者 | 任意准备完整的开发机 |
| 架构测试 | 验证共享边界、写入入口、网络权限 | 任意开发机 |
| 打包测试 | 验证三个 `Aura.Shared.dll` 一致 | 任意开发机 |
| 游戏内烟雾测试 | 验证真实 UI、动画、输入和时序 | 外部游戏测试机 |
| 长时与组合回归 | 验证不同 MOD、角色、敌人与长战斗 | 外部游戏测试机 |
| 模型离线评估 | 验证样本、特征和模型收益 | 后续训练机 |

## P0 场景

P0 失败必须停止发布。

| 编号 | 场景 | 操作 | 通过条件 |
| --- | --- | --- | --- |
| P0-01 | 普通牌只执行一次 | 开启自动战斗并观察扣费、手牌和事件 | 只扣一次费用，只移除一次手牌 |
| P0-02 | 定向攻击牌 | 多个敌人存活时自动出牌 | 目标有效，未攻击死亡目标或错误单位 |
| P0-03 | 无目标技能 | 使用角色基础主动技能 | 技能只触发一次，冷却和 UI 正常 |
| P0-04 | 目标技能 | 技能允许敌方或自身目标 | 目标符合技能语义，不遗留瞄准线 |
| P0-05 | 结束回合 | 没有正收益动作 | 只结束本地玩家回合，不重复点击 |
| P0-06 | 关闭接管 | 动作间关闭自动战斗 | 不再提交新动作，玩家可立即操作 |
| P0-07 | 必选 UI 中关闭 | DeckUI/FightUI 打开时关闭 | UI 不被关闭，玩家可以手动完成 |
| P0-08 | 动作异常 | 制造无效目标或失效对象 | 自动战斗停止，不继续重复提交 |
| P0-09 | 联机本地性 | 联机对局开启功能 | 不控制远端玩家或绕过 authority |
| P0-10 | 共享 DLL | 完成全部消费者构建 | 三份 `Aura.Shared.dll` 哈希一致 |

## P2 质量场景

- 16:9、16:10、21:9 和常见窗口化分辨率的按钮布局；
- 简体中文、繁体中文和英文 UI 下按钮文本；
- 每种决策风格至少完成 5 局；
- 低生命、高护盾、零能量、满手牌和多个敌人的边界情况；
- 只有未知卡、只有技能、空手牌和无敌敌人的行为；
- 连续 20 局不重启游戏的对象清理和内存趋势；
- 同时加载 Terrias、AuraToolsExp 和 SanGuoShaExp；
- 中途重新加载配置或返回主菜单后的状态恢复。

## 运行时证据

每个失败至少保存：

1. 测试编号和日期；
2. Git commit、游戏版本、加载 MOD 及版本；
3. 角色、牌组、敌人和回合；
4. 自动战斗配置；
5. 复现步骤；
6. 预期结果与实际结果；
7. 完整日志；
8. 截图或从动作前开始的录像；
9. 是否可稳定复现；
10. 临时处理和建议责任层。

## 性能采样

阶段 1.1 至少记录：

- 单次观察耗时；
- 候选数量；
- 决策耗时；
- 动作到稳定状态的等待时间；
- 每回合 GC 分配趋势；
- 超时次数；
- 未知动作数；
- 交还玩家次数。

首轮建议门槛：

- 普通决策 P95 小于 5 ms；
- 普通候选不超过 64；
- 无持续每帧日志；
- 无连续重复提交同一失效动作；
- 20 局测试中事务超时为 0。

门槛应根据测试机数据调整，但任何放宽都必须记录原因。
