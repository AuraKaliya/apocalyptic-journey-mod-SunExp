# 阶段 1.3 选择轨迹与训练数据分层

## 目标

训练样本必须把“AI 在同状态预选的动作”和“最终实际执行的动作”分开记录。
人工教师数据用于表达偏好，自动策略数据用于记录策略轨迹和结果，两者不得被
当成同一种监督信号。

## 选择轨迹协议

样本协议仍为 `aura.combat-ai.sample.v3`，新增向后兼容的子协议：

```json
"Selection": {
  "Protocol": "aura.combat-ai.selection.v1",
  "ExecutedBy": "human",
  "LabelKind": "human-preference",
  "ExecutedCandidateId": "attack:1",
  "ExecutedDisplayName": "攻击",
  "PolicyPreselectedCandidateId": "shield:2",
  "PolicyPreselectedDisplayName": "护盾",
  "PolicyWasExecuted": false,
  "HumanPolicyAgreement": false,
  "PolicyVisibleToHuman": true
}
```

自动样本的 `ExecutedBy` 为 `policy`，`LabelKind` 为
`policy-trajectory`。正常执行时，实际动作和 AI 预选动作相同。

旧顶层字段 `CandidateId`、`Demonstrator` 和 `RecommendedCandidateId` 继续
写入，供旧审计工具兼容读取。新工具优先读取 `Selection`。

## 候选动作观察标记

每个候选动作增加：

- `IsExecutedAction`：最终是否实际执行；
- `IsHumanSelection`：是否为人工实际选择；
- `IsPolicyPreselection`：是否为 AI 同状态预选。

人工覆盖 AI 时，这三个标记会分布在两个候选上；自动执行或人工同意 AI 时，
执行标记和预选标记位于同一候选上。

运行日志使用以下摘要：

```text
[AutoBattle][Training] actor=human executed=... policyPreselected=... agreement=False visibleToHuman=True label=human-preference
```

## 数据用途

### 人工分歧

当人工动作和 AI 预选不同时，生成唯一的成对偏好：

```text
人工实际动作 > AI 预选动作
```

该样本直接修正当前策略发生分歧的决策边界。隐藏 AI 预测时权重为 2；玩家
已经看到预测标记时，为降低锚定效应，权重降为 0.5。不会再自动假设人工动作
优于同状态下所有其他合法候选。

### 人工一致

人工和 AI 选择相同时没有新的排序边界，因此不生成偏好对。它仍进入报告，
用于一致率、动作分布和结算结果校准。

### 自动策略轨迹

自动策略选择不是独立教师。自动样本不生成偏好对，无论回报正负都不反推
未执行动作的优劣。它保留以下用途：

- 观察策略实际访问的状态分布；
- 统计攻击、防御、辅助、技能和结束回合比例；
- 计算即时奖励与整场折扣回报；
- 为后续动作价值模型提供已执行动作结果；
- 检查策略坍缩和类别失衡。

## 数据报告

运行：

```powershell
tools\Train-AuraCombatAi.ps1 -ReportOnly
```

生成：

```text
Logs/AuraToolsExp/auto-battle-training-report.json
```

报告协议为 `aura.combat-ai.training-report.v1`，主要字段包括：

- `ActorCounts`；
- `SelectionV1Count` 与旧样本回退数；
- `HumanPolicyAgreementCount`、分歧数及一致率；
- 可见/隐藏 AI 预测的人工样本数与各自一致率；
- `ExecutedActionDistribution`；
- `PolicyPreselectionDistribution`；
- `HumanOverrideTransitions`；
- `PolicyTrajectory` 奖励与折扣回报摘要；
- 实际可用于排序训练的偏好对数量。

## 训练安全边界

- 只读取完成结算的 v3 样本；
- 只用人工/AI 分歧建立排序标签；
- 自动失败不等于所有未执行动作更优；
- 按整场战斗划分训练和测试，避免会话泄漏；
- 学习结果仍为 `[-2,+2]` 的有界规则分数残差；
- 模型不能绕过合法性、目标、事务或交互规则。
