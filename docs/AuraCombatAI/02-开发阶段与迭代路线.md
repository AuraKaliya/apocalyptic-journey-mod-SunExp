## 阶段 0：宿主研究

已确认：

- `CommonCardItem.TryUse` 不是纯检查，不能用于候选展开；
- `TrueUse` 是最终原生提交入口；
- DeckUI 通过 `CreateDeckMenuForSelect` 创建选项，并通过原生按钮关闭；
- FightUI 通过 `SelectCardToAction`、SelectedCard 和确认按钮完成手牌选择；
- 技能和攻击牌需要在最终提交前写入目标；
- 额外 UI 必须属于根动作事务，不能被误判为自动战斗卡死。

退出条件已经满足，后续不得重新引入“调用 TryUse 探测是否合法”的实现。

## 阶段 1：规则型首版

交付物：

- `AuraDecisionShared` 和 `AuraCombatAiShared`；
- Witch 观察、预检、执行和交互适配；
- AuraToolsExp 自动战斗设置、按钮与控制器；
- Terrias 复杂交互提示与精灵牌合法性规则；
- 纯逻辑测试、共享发布门禁和一致性打包；
- 本文档套件。

剩余退出条件：

- 外部测试机完成阶段 1.1 的所有 P0/P1 场景；
- 没有重复扣费、重复出牌、错误关闭 UI 或远端角色被控制；
- 按钮在目标分辨率下无重叠；
- 20 局以上对局没有出现无法恢复的事务超时。

## 阶段 1.1：游戏内验证

进入条件：

- 使用与 `Managed/` 对应的游戏版本；
- 三个主要消费者重新构建；
- `Test-SharedReleaseGate.ps1` 和 Terrias C# 测试通过；
- 测试配置、日志目录和录像方案已准备。

交付物：

- 场景测试报告；
- 每个失败场景的日志、截图或录像、卡牌/角色/敌方组合和复现步骤；
- 按钮布局截图；
- 训练样本格式审计结果；
- 明确的 P0/P1 缺陷列表。

禁止在这个阶段引入学习模型。先证明规则型执行链稳定。

## 阶段 1.2：事务与策略修订

首轮实战验证确认强制弃牌走 `FightUI.ThrowCardScript`，并非
`FightUI.SelectCardToAction`。本阶段已经补充弃牌和烧牌入口、逐张选择验证、
单次确认、统一根事务截止时间、失败/接管/战斗结束终止态、相对价值策略底模
和训练样本 v2。

详细合同见 [阶段 1.2 修订说明](08-阶段1.2事务策略与训练数据修订.md)。

退出条件：

- 强制弃牌和烧牌在真实对局中无需玩家点击；
- 不会选中 `Froze`、禁用或失效卡牌；
- 超时、关闭自动战斗和失败都保留原生 UI；
- 日志中一个根事务只有一次提交和一次训练样本；
- `auto-battle-training-v2.jsonl` 可被标准逐行解析器读取；
- 共享发布门禁及所有消费者 DLL 一致性检查通过。

## 阶段 2：语义覆盖

阶段 1.3 已提前交付通用威胁协议、Witch 当前意图适配、有界 Beam Search、
人工教师采集、`selection.v1` 数据分层、黄/红/绿预测标记和线性残差基础。详细合同见
[阶段 1.3 威胁规划与训练闭环](09-阶段1.3威胁规划与训练闭环.md)与
[选择轨迹与训练数据分层](10-阶段1.3选择轨迹与训练数据分层.md)、
[AI 预测标记](11-阶段1.3AI预测标记.md)。

主要工作：

1. 建立卡牌与技能语义覆盖率统计。
2. 为内容 MOD 提供语义注册清单和缺失诊断。
3. 扩大敌方意图池概率、易伤/无敌/反伤等状态特征覆盖。
4. 区分“对敌伤害”“对友治疗”“自身代价”和“牌组长期价值”。
5. 为决策结果提供可选诊断记录：候选、拒绝原因、效用分量和最终分数。
6. 对现有有界束搜索进行性能、随机结果和内容语义校准。

退出条件：

- 核心卡池和重点 MOD 卡池的动作语义覆盖率达到约定目标；
- 未知动作不会在默认策略下造成明显危险行为；
- 诊断日志可以解释主要选择；
- 运行时平均决策耗时和峰值分配满足预算。

## 阶段 3：数据基线

主要工作：

- 固定 `featureSchemaVersion` 和样本字段；
- 按整场战斗划分训练集、验证集、测试集；
- 建立启发式模型的离线重放分数；
- 清理重复、无结算、超时和版本不匹配样本；
- 建立胜负、回合数、受伤、资源浪费和非法动作率指标；
- 在“影子模式”中记录模型建议，但仍执行规则模型。

退出条件：

- 数据能够从采集到离线评估完整重放；
- 不同机器、不同 MOD 组合的样本可识别；
- 没有把同一场战斗拆到训练集和测试集造成泄漏；
- 启发式基线可重复。

## 阶段 4：学习残差

推荐顺序：

1. 线性残差模型。
2. 小型两层 MLP。
3. 只有在前两者明显不足时，才评估树模型或外部推理运行库。

学习模型只对规则模型分数做有限残差修正。必须保留：

- 硬合法性规则；
- 分数修正幅度上限；
- 模型大小上限；
- 协议、特征和校验和验证；
- 一键禁用和启发式回退；
- 影子模式与逐步放量。

## 阶段 5：友方 AI

友方 AI 不复用玩家 FightUI 适配器，而是复用共享协议：

- 友方单位提供自己的 `ICombatObservationProvider`；
- 只展开该单位拥有的卡组、技能和合法目标；
- 由友方单位执行器实现 `ICombatActionExecutor`；
- 增加行动权、队伍资源和联机权威检查；
- 共享语义提供器可以继续复用；
- UI 交互应改为数据级选择，不能伪造玩家点击。

退出条件包括多人 authority 测试、单位隔离测试和队伍协同回归。

## 阶段 6：高级规划

候选方向：

- 两到三步有限前瞻；
- 随机结果的采样估计；
- 友方单位之间的协同效用；
- 基于角色或牌组的策略配置；
- 受控的战斗间在线适应。

这一阶段只有在执行链、语义覆盖和离线评估稳定后才能进入。
