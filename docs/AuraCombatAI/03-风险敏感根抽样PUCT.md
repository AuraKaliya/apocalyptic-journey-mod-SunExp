# 风险敏感根抽样 PUCT

## 搜索对象

生产规划器为 `CombatRiskAwareRootSamplingPuctPlanner`。它是面向回合内多步动作的风险敏感 MCTS：

- 根部覆盖全部合法动作；
- PUCT 分配后续模拟；
- 每次模拟执行根抽样；
- 前向模型展开卡牌、技能、状态和机会结果；
- 转置表按公开模拟状态哈希复用节点；
- 基础/影子路径在叶节点结合规则估值、搜索引导和策略价值网络；模型应用路径只使用策略价值网络的策略、价值与风险输出；
- 输出当前动作及代表性主变化。

游戏内默认每个决策只运行一棵树。过去的 `inferenceParallelism=2` 实际启动两套完整 PUCT、两份模型调用和两套 arena，并不是廉价的“双路推理”；该配置已经从生产 schema 移除，旧字段只消费不回写。复杂局面依靠动态增加同一棵树的模拟/节点/深度预算，不复制整棵树。

同一规则 worker 与同一模型 worker 在战斗内持久存在，搜索状态、节点、动作模型和转置容器按搜索边界清空并复用容量；战斗终局调用 `ReleaseRetainedMemory` 收缩高水位。全局弱引用目录会在内存收缩时移除失效规划器，不再永久积累已回收 worker 的引用壳。

## PUCT 选择

对边 `a` 使用：

```text
score(a) = Qrisk(a)
         + c_puct * prior(a) * sqrt(parentVisits) / (1 + visits(a))
```

基础/影子路径的 `prior` 来自三类信号的同尺度组合：

1. 根候选规则分在当前动作集合内做 z-score 标准化，并截断到 `[-3, 3]`；
2. 搜索引导 logit 截断到 `[-4, 4]`；
3. 策略价值网络 logit 截断到 `[-4, 4]`。

随后统一 softmax。模型应用路径则仅对策略网络 logit 做 softmax，不叠加规则分、搜索引导或延续动作先验；最终按访问量、模型先验和模型估值选根动作。

## 风险统计

每条根边维护：

- 样本数；
- Welford 在线均值和方差；
- 标准误；
- 死亡风险均值；
- 最多 2048 个回报样本；
- 下尾均值及尾部样本置信度。

下尾均值使用最差 `alpha` 比例回报。尾部样本少于 8 个时，不直接把单个坏样本当成稳定 CVaR，而是向总体均值收缩：

```text
tailConfidence = clamp((tailCount - 1) / 7, 0, 1)
effectiveTail = mean
              + tailConfidence * (rawLowerTailMean - mean)
```

单样本标准误采用保守下限，防止首次幸运样本看起来“零不确定性”。

## 统一风险效用

树内 exploitation、根排序、稳定性检查和主变化都使用同一个效用：

```text
Qrisk = 0.65 * mean
      + 0.35 * effectiveLowerTailMean
      - tailRiskPenalty * meanDeathRisk
      - uncertaintyPenalty * standardError
```

`RiskPreference=0.5` 保持上式。向 0 调整会提高下尾权重、死亡惩罚和不确定性惩罚；向 1 调整会更偏向均值，但不会绕过 `DeathRiskLimit` 硬约束。运行档默认 defensive=0.2、balanced=0.5、aggressive=0.8，也可以由配置显式覆盖。

最终选择先应用生存约束：

1. 若存在 `meanDeathRisk <= DeathRiskLimit` 的动作，只在这些动作中排序；
2. 若所有动作都越界，只保留风险不高于最小风险 `+ 0.01` 的动作；
3. 再按 `Qrisk`、访问量、先验和稳定候选 ID 排序。

这避免了“先按原始 CVaR 排序”导致高均值、合理尾部风险的动作被极少尾部样本错误压制。

## 机会节点与代表子节点

一次动作可能产生多个机会结果。边按子状态哈希累计证据，不再用最后一次模拟覆盖 `Child`。主变化选择访问量最多的代表子状态；访问量相同时按稳定哈希决定，因此日志和调试结果可复现。

## 早停

搜索只有同时满足以下条件才提前停止：

- 已达到最小模拟数；
- 根候选覆盖完成；
- 最佳动作至少 2 次访问，第二名至少 1 次；
- 最佳动作保持足够访问领先；
- 风险效用领先超过由双方标准误计算的不确定性阈值；
- 最佳动作和代表图结构在稳定窗口内未变化。

仅有访问量领先但价值仍在误差范围内时，不会早停。

## 动态预算

`CombatSearchBudgetPolicy` 将状态分为：

- `forced`：只有一个合法动作；
- `simple`：低分支、低威胁、无复杂链；
- `normal`：常规战斗；
- `difficult`：Boss、高威胁或高价值分歧；
- `complex`：随机链、生成链、零费循环或假循环风险。

质量档缩放预算：

| 质量档 | 模拟量 | 节点量 | 深度 |
|---|---:|---:|---:|
| `fast` | 0.65 倍 | 0.75 倍 | 基线减 2 |
| `balanced` | 1.0 倍 | 1.0 倍 | 基线 |
| `deep` | 1.75 倍 | 2.0 倍 | 基线加 4 |

强制动作始终只做最小验证。生产不接受手填固定搜索数字；固定模式仅供确定性测试。

## Anytime、模型预算与治理

部署默认墙钟截止来自 `decisionTimeBudgetMs`，并同时限制 `searchModelEvaluationBudget`。搜索先覆盖全部保留的根动作，每完成一次模拟都保留当前证据；达到时间、模型调用、节点或模拟预算时返回当前结果和结构化停止原因。模型缓存命中不消耗模型调用预算。

正常 anytime 截止之外还有实时通道硬截止，默认至少 500 ms 且约为搜索预算的四倍，AuraTools 生产请求限制在 2–10 秒范围内。执行请求优先于机会任务；取消会在根覆盖、外层模拟、每个 ply、叶估值和策略价值评估入口抛出，并形成恰好一个 `Cancelled / Superseded / DeadlineExceeded / Faulted` 终态回执。技术看门狗不再仅丢弃结果而让旧树继续占用唯一 CPU 槽。

基础/影子路径中，`CombatDecisionGovernance` 在执行前复核搜索置信度、结束回合安全和死亡风险。模型应用路径中，治理层只确认搜索提案仍对应一个机制上合法、可绑定的候选，不再因低置信、规则低分、结束回合风险或模型预算耗尽而替换动作。推理硬看门狗、执行事务超时和连续无进展由游戏端可用性状态机处理，并只在这些技术故障发生时调度一次应急规则决策；同一战斗连续三次技术失败后隔离模型。

Actor 候选裁剪由 `enableActorCandidatePruning` 控制，默认关闭。开启时仍强制保留动作来源族、结束回合安全替代以及训练/教师/Shadow 的全候选；`actorCandidateTopK` 和累计概率质量只用于已经通过候选召回门禁的部署模型。裁剪前后数量、模型调用、缓存、决策耗时和预算停止都进入 Episode 与训练遥测。
