# 训练数据与模型演进

## 原则

“自主训练”不应在首版中解释为游戏进程内持续反向传播。推荐路线是：

1. 游戏内受控采样；
2. 游戏外训练与评估；
3. 加载小型、只读、可校验的模型；
4. 影子模式对比；
5. 逐步启用；
6. 最后才评估受限在线适应。

执行安全、合法性和回退能力优先于模型复杂度。

## 当前样本

协议：`aura.combat-ai.sample.v1`

当前字段包括：

- 战斗会话和动作序号；
- 状态指纹；
- 候选 id；
- 送入决策器的数值特征；
- 启发式预测分数；
- 动作结算后的短期奖励；
- 是否检测到终局。

当前奖励主要来自：

- 敌方生命下降；
- 玩家生命变化；
- 玩家护盾变化；
- 能量变化。

这只是启动数据，不等同于整局价值。抽牌质量、状态持续时间、未来伤害、胜负和回合效率需要在后续协议中补充。

## 特征版本

引入模型前应新增明确字段：

```text
modelProtocol
featureSchemaVersion
gameBuild
sharedBuild
ownerModSetHash
decisionProfile
battleOutcome
```

特征要求：

- 名称稳定；
- 数值有限，不允许 NaN 或 Infinity；
- 缺失值有固定默认值；
- 训练和运行时使用同一归一化参数；
- 不能使用动作之后才知道的信息；
- 不直接使用不稳定的 Unity instance id 作为可学习语义。

## 数据拆分

必须按整场战斗拆分，不按单个动作随机拆分：

- 训练集：约 70%；
- 验证集：约 15%；
- 测试集：约 15%。

同一 seed、同一场录像或重放派生的样本必须落在同一分组。还应按角色、牌组、敌人、游戏版本和 MOD 组合观察分布偏差。

## 第一模型建议

### 线性残差

优点：

- 参数量小；
- 可解释；
- 手写推理简单；
- 模型通常只有数 KB；
- 容易限制输出范围。

用途：验证特征与训练管线是否真的优于启发式基线。

### 小型 MLP

建议起点：

- 输入为固定特征向量；
- 两个隐藏层，每层 16 到 32 个单元；
- ReLU 或 tanh；
- 单一标量残差输出；
- 输出裁剪到有限范围。

这种模型通常可控制在几十 KB，运行时可以用简单数组推理，不必引入大型神经网络运行库。

### 暂缓方案

以下方案必须有明确收益证据后再评估：

- ONNX Runtime 等大型原生依赖；
- 大型 Transformer；
- 游戏内持续训练；
- 无界 Monte Carlo 搜索；
- 每张卡独立携带模型。

它们会显著增加包体、平台兼容、加载时间和诊断成本。

## 模型文件合同

模型至少包含：

- model id；
- model protocol；
- feature schema version；
- 输入维度；
- 层结构；
- 权重数据；
- 归一化参数；
- 训练数据摘要；
- 校验和；
- 创建时间和工具版本。

建议首轮限制：

- 单模型不超过 256 KB；
- 只允许已知层类型；
- 所有权重必须为有限数值；
- 输入维度必须精确匹配；
- 校验失败立即拒绝；
- 不允许模型文件声明任意类型或执行代码。

## 评估指标

离线指标：

- 候选排序一致率；
- 与人工选择的 top-1/top-3 一致率；
- 非法动作建议率；
- 相对启发式模型的累计回报；
- 不同角色和 MOD 的最差分组表现。

游戏内影子指标：

- 模型建议与实际规则选择的差异；
- 假设采用模型建议时的短期奖励；
- 推理耗时 P50/P95/P99；
- 模型加载失败和回退次数。

最终对局指标：

- 胜率；
- 平均受伤；
- 平均回合；
- 资源浪费；
- 玩家接管率；
- 超时和异常率。

## 上线顺序

1. `capture only`：只采样。
2. `offline replay`：只离线评估。
3. `shadow`：游戏内推理但不影响动作。
4. `bounded residual`：只允许小幅修正。
5. `profile opt-in`：玩家显式选择学习模型。
6. `default candidate`：长期验证后才考虑默认启用。

任何阶段发现非法动作率、异常率或最差分组明显恶化，应立即回退到启发式模型。
