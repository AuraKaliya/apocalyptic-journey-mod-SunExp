# 训练与游戏主体验证分离

## 管线边界

自动战斗 AI 现在使用两条职责明确的管线：

1. 外部训练与模拟校准在独立 `.NET 8` Worker 中运行。它负责大规模课程训练、分层回放、同种子底模对照和普通/高级难度统计。
2. 游戏主体验证在 Witch 进程中运行。它只负责确认候选模型能够在真实 `FightManager`、`RoleTable`、`FightUI` 交互入口和本体卡牌脚本上完成关键战斗。

外部模拟结果不能替代游戏主体回执，游戏主体回执也不回流训练集。这样可以防止验证数据污染训练，同时把耗时的大样本工作留在可并行的外部进程。

## 外部训练控制台

`AuraFoundationTrainer.ControlCenter.exe` 是独立的 `.NET 8` WPF 调度器。它和 Worker 一同以框架依赖单文件发布到 `AuraToolsExp/TrainingWorker/`，从游戏外运行。首次使用应双击 `Start-AuraFoundationTrainer.cmd`；启动器会检查 Windows x64 的 `.NET 8 Desktop Runtime`，缺失时可调用 `Install-AuraDotNetDesktopRuntime.cmd` 通过 `winget` 安装，无法自动安装时回退到微软官方下载页。Desktop Runtime 已包含 Worker 所需的普通 .NET Runtime，不需要重复安装。AuraToolsExp 的游戏内设置页不再提供底模训练或控制台启动入口。

独立查看器通过 `Start-AuraFoundationSimulationViewer.cmd` 启动并复用同一前置检查。直接运行 EXE 仍可用于诊断，但正式发布和用户说明以两个启动器为入口；安装 Runtime 后不需要把任何 .NET 运行时文件复制进 MOD 目录。

控制台默认以自身 EXE 所在的 `TrainingWorker/` 为锚点，自动定位上一级 `AuraToolsExp/` 和同级运行环境的 `ModsData/`。仓库或游戏目录整体移动后不需要修改本机绝对路径；`--mod-root` 与 `--data-root` 仅保留为诊断时的显式覆盖参数。

控制台负责：

- 编辑基础参数和高级参数，并在启动前显示估算战役数；
- 从冻结 campaign、ruleset、内容集合、内容 MOD 权威 Episode 和原生程序包生成 schema 14 任务；
- 启动或重新连接 Worker，轮询阶段、进度、吞吐、剩余时间和诊断；
- 通过取消文件请求安全取消，保留满足协议的恢复点；
- 从已接纳 Champion、`training-experimental-resumable` 实验底模，或带完整检查点的 `training-rejected-resumable` 工作模型发起下一轮谱系训练；
- 在控制台关闭后让 Worker 继续运行，稍后可重新连接；
- 任务结束时自动切换到“运行监控”，通过完成弹窗、提示音和任务栏闪烁明确反馈结果；
- 在“训练配置”页持续保留最近任务的验收状态、胜场和恢复点摘要。

同一个成功案例库只允许一个训练 Worker 持有写租约，独立控制台在启动或续接任务时检查该租约，避免多个 Worker 并发修改案例库。控制台中的“迭代数”表示单次任务内部迭代；继续训练时，正式 Champion 与尚未过门禁但可恢复的 `WorkingChampion` 分开保存。后者可以继续学习，却不会被包装或展示成已验收底模。

续训兼容指纹冻结角色/使魔/卡包主体、规则与原生程序、网络和特征协议、学习策略及验收语义，但不冻结本轮迭代预算和新请求种子。有效恢复始终沿用检查点中的原始运行种子、难度分区和模型种子，保证一条训练谱系不会因点击“继续”而悄悄换题；只有检查点不兼容时才使用新请求的种子从头开始。

## 工件与门禁

游戏主体验证请求和回执遵循 `CombatGameValidationProtocol`。回执同时绑定：

- 决策风格与模型 ID；
- 模型包 SHA-256；
- Witch 游戏程序集版本；
- 固定世界推演包 ID 与版本；
- 冻结规则集哈希；
- 当前权威预编译程序包哈希。

其中任一项变化，旧回执立即失效。候选发布需要依次通过：

1. 模型自身的分组验证；
2. Normal/Advanced 绝对胜率线与离线多头、策略配额、特征碰撞硬门禁；
3. 全部合格模型的数据排序与规则基线能力探针门禁；
4. 游戏主体最终首领验证回执。

规则基线能力探针继续报告 Normal/Advanced 回归、总胜场和平均完成深度。`pass` 可以取得正式
质量认证；`inconclusive` 表示证据不足，不表示非劣；`fail` 表示检测到相对基线回退。三者都
属于质量证据，不是文件兼容性门禁。当前训练器只有在满足正式或实验发布合同时才自动输出
游戏加载包；游戏侧对人工选择的兼容工件仍允许入库，并把缺失、失败或无法绑定的证据显示为
“未验证”。

当前控制台设置使用 schema 16。旧 schema 不再迁移，加载时直接恢复当前默认训练配置；默认 CPU 执行合同为 `auto`，控制台不再提供冒险或模型训练 CPU 并行度输入。Worker 以本机逻辑处理器数为上限，自动测量 50%/75%/100% 三个规范化并发点并选择稳定吞吐最高者；该标定值保持为硬件上限，每轮内存容量预测只临时收紧当轮并发，不能反向污染标定值。选中的推理模式、Lane、Batch 会写回有效执行计划，模型训练自动使用可用逻辑处理器。

Worker 在 `training-accepted` 和 `training-experimental[-resumable]` 时都生成同名的 `foundation-model-package-v5.json` 与 `foundation-model-weights-v5.bin`，并放入 `training-artifacts-v1/deployment/`。JSON 用 `DeploymentTier=formal|experimental` 区分正式认证与实验准入，同时记录质量认证、同模型证据绑定和能力状态；全部可训练权重按 little-endian FP32 紧凑写入二进制文件。写出前后都会按生产读取路径复载并校验长度、SHA-256、有限值、维度、运行安全和等级证明。`diagnostic` 只保留 `model/candidate-*` 与分析数据库，不能被游戏加载。

设置页“选择模型文件”先把外部包复制到隔离的导入暂存区，并写入 `evaluationModelId`。它不会替换当前实战模型，也不会自动加入模型库。外部模型加入本地模型库前只需要通过硬兼容门禁：

1. JSON/工件协议、模型版本与稳定模型 ID；
2. 权重文件存在，长度、SHA-256 和有限数值正确；
3. 当前特征编码、动作契约、搜索/训练协议和网络维度一致；
4. 角色、使魔、卡池作用域与内容集合绑定元数据内部一致；
5. 用户点击“添加并选择”。

普通/高级世界推演、训练胜率、能力探针和游戏主体验证只用于形成质量证据，不阻止硬兼容模型入库。证据满足完整正式合同时标记 `【正式】`，满足实验证据合同时标记 `【实验】`，其余标记 `【未验证】`。入库后默认保持模型关闭并选中该模型；隔离暂存项被清除，避免后续评估误用旧候选。

## 随 MOD 发布的内置底模

AuraToolsExp 启动时会在后台批量扫描发布底模。规范布局为 `AuraToolsExp/ModResource/Model/<角色名 [RoleId]>/<使魔名 [PartnerId]>/`；只有一个模型时，`foundation-model-package-v5.json` 与 `foundation-model-weights-v5.bin` 可以直接位于使魔目录。同一角色与使魔需要并存多个版本或卡池变体时，在使魔目录下增加一层完全由用户命名的发布目录，例如 `我的正式底模/`。发布目录只用于人工整理，不解析也不要求哈希、版本或卡包信息。角色与使魔方括号内的稳定 ID 会和包内 `RoleId`、`PartnerId` 交叉校验；哈希由程序读取原始文件后计算，版本和具体卡包从包内元数据读取。旧的 `<角色 [RoleId]>/<发布名 [PackageSha12]>/` 两层目录只作为迁移输入继续读取，新发布不得再要求用户把哈希写进目录名。根目录顶层 JSON 仍只作为旧版单包兼容入口。

扫描按角色、使魔、可选发布目录和文件名稳定排序；每个包独立执行 64MB 上限、严格 UTF-8、原始 JSON SHA-256、底模包协议、当前兼容元组、同目录 FP32 权重长度/哈希与生产读取路径复载。质量证据另行评估，不参与是否注册。命中 `aura-director.foundation-model-allowlist.json` 完整兼容元组与精确 `ArtifactSha256` 的包标记为官方随 MOD 底模；未命中官方目录、但通过硬兼容门禁的当前 v5 双文件包标记为 `player-trained`。来源身份与质量等级彼此独立：官方或玩家包都可以显示为正式、实验或未验证。共享资源发现完成后使用同一扫描器自动复扫；当模型目录中恰有一个可加载且已入库的兼容底模、玩家又尚未选择模型时，工具会自动选中它，但 `TrainedModelMode` 仍保持 `off`，不会自动开始观察、试用或正式接管。单个损坏文件只记录该包失败，不阻止其他有效包继续注册。

新发布底模包必须原样保留训练器生成的 `foundation-model-package-v5.json` + `foundation-model-weights-v5.bin`，并声明 `ModelVersion = 5.0.0`、MLP v2 与当前 Feature Schema。正式/实验发布仍必须携带对应等级证明；证据不完整的兼容工件只能作为未验证模型供本地导入，不能宣称正式发布。不要为了区分多个模型而改写这两个文件名；以角色、使魔和可选的用户发布目录隔离同名工件。读取端兼容已经正式验收的 v3/v4 顶层 JSON 包，导入后会在模型库中标记为 `legacy-formal-acceptance`，但不会改写源包。正式官方内置模型仍应在 allowlist 中单独授权；玩家训练模型不修改官方目录。

`角色名称-使魔名称-卡包数量卡包-v底模版本`

例如：`阿米莉娅-报丧偈羽-19卡包-v5.0.0`。对应的发布源目录可以直接是 `阿米莉娅 [career_1]/报丧偈羽 [Partner_10001]/`，也可以在其下使用 `稳定版/`、`实验版/` 等用户发布目录。目录改名不会改变模型身份。模型库中的程序管理文件继续使用内部稳定命名并绑定权重工件，中文名称只作为可编辑显示名；新底模通过工件与兼容性门禁即可入库，质量验收只决定正式、实验或未验证标记。

注册遵循非破坏性规则：同一模型 ID 与同一源包 SHA-256 直接去重；同一模型 ID 但不同哈希拒绝覆盖；同一角色、使魔、卡池和版本对应不同模型 ID 时要求提升 `ModelVersion`；不同版本可并存。除“未选择且唯一兼容底模”的便利选择外，自动注册不会改变选择或启用任何运行模式，不会删除已入库但本次未随 MOD 提供的模型，也不会覆盖用户手动修改过的显示名。模型库位于 `ModsData/AuraShared/Data/Owners/AuraToolsExp/FoundationModels/`。

模型库下拉项和详情始终以 `【正式】` / `【实验】` / `【未验证】` 显示质量等级。三类模型都可加载并进入观察模式；实验或未验证模型第一次切换到“试用/正式接管”前，用户必须按源包 SHA-256 显式确认“效果可能与正式模型存在差异”。确认按模型分别保存，包内容或哈希变化后需要重新确认。模型成功加载后，应用路径不以质量等级、低置信度或规则偏好覆盖模型动作。加载失败、推理异常/超时或连续无进展时，游戏保留用户配置并临时调度技术兜底；同一战斗连续三次技术失败后隔离模型，下一场战斗重新尝试加载。兜底轨迹保留为问题遥测，但不进入策略模仿标签。

## 是否需要可见 UI

大规模训练不属于游戏内功能；大部分验证也不需要做成可见游玩。

游戏主体验证仍保留真实 `FightUI` 对象和交互执行路径，因为自动战斗的合法动作最终通过这些入口提交；默认只使用 `CanvasGroup` 隐藏画面并关闭射线，不禁用 UI 逻辑。这样比真正的无 UI 游戏进程更接近玩家运行时，又省去渲染和人工等待。

建议发布前只补一轮很小的可见冒烟测试，用于检查画面层、按钮层和动画层没有妨碍真实交互。它不是训练步骤，也不需要覆盖大量种子。

## 默认实机用例

每个待晋升模型默认各运行一次：

- 永夜；
- 魔王；
- 神圣审判机关；
- 勇者卡洛琳。

每场设置动作数和时间上限。角色状态在验证前序列化，并在每场结束、取消或失败后还原；验证使用 `IsFake` 战斗，避免把奖励和进度当作正式游玩结果。

默认晋升门禁要求每场至少完成一个真实动作、没有无效运行，并完整覆盖四个用例。胜负会写入回执，但默认不设最低胜场，因为实机验证沿用当前角色构筑，少量胜负不能和外部固定世界种子的统计直接比较；需要固定人工构筑验收时，可在配置中提高 `minimumWinsPerFinalBoss`。

请求与回执写入 `ModsData/AuraShared/Logs/AuraToolsExp/game-validation/<模型摘要>/`。设置页的“实机验证”和“打开回执”用于补充质量证据。外部包的隔离副本和清单写入 `ModsData/AuraShared/Logs/AuraToolsExp/external-foundation-validation/`；“清除选择”只移除该隔离副本，不影响训练原目录或已经入库的模型。
