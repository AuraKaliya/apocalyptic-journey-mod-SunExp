# 知识与语义扩展

## 权威知识层

规划器不能依靠名称猜测卡牌效果。知识层将游戏表、反编译得到的程序语义和运行时注册表编译为：

- 卡牌、技能、遗物、祝福、敌人和状态定义；
- 数值表达式与动态变量；
- 目标规则、费用、次数和冷却；
- 伤害、防御、治疗、抽牌、能量、生成、持续和缩放语义；
- 不确定性、风险和权威来源；
- 原生程序包哈希与规则集哈希。

`combat-knowledge.base-game.report.json` 和 `base-game-knowledge-report.json` 是生成报告，不是手写设计文档。缺失、冲突和低置信条目必须进入报告。

## 动作语义

`CombatActionSemantics` 是规则评分、前向模拟和训练特征的共享语言。关键字段包括：

- 直接伤害、真实伤害、持续伤害和命中次数；
- 护盾、治疗、抽牌和能量变化；
- Buff、Debuff、净化和持续价值；
- 降费、卡牌生成和成长；
- 自身生命代价、周期末代价；
- 风险、不确定性和可解释标签。

同一个动作不能在评分器和模拟器中使用两套互相矛盾的语义。新增语义时应同时更新知识编译、前向模型、公开特征、测试场景和覆盖报告。

## 前向模型

前向模型负责：

1. 克隆公开模拟状态；
2. 校验动作；
3. 结算费用和使用次数；
4. 调用注册的效果解析器；
5. 应用伤害、状态和资源变化；
6. 处理机会结果；
7. 运行回合结束、敌方行动和终局规则；
8. 生成确定的公开状态哈希。

遇到未知程序时必须标记非权威或拒绝评估，不能把未知效果视为无效果。

## 扩展点

其他 MOD 可通过共享注册表提供：

- `RegisterEffectResolver`：解析自定义效果；
- `RegisterSimulationRule`：增加合法性或状态规则；
- `EvaluateSimulation`：为扩展机制提供有界评估；
- 权威定义和来源标识；
- 可公开的数值特征。

扩展实现必须：

- 只依赖共享合同，不引用 AuraTools 的 UI；
- 保持确定性，相同状态、动作和随机种子得到相同结果；
- 明确声明随机分支及概率；
- 不读隐藏宿主数据；
- 不返回 NaN 或 Infinity；
- 为合法、非法、终局和多目标路径提供测试。

## 覆盖门禁

主动模型和正式评估要求：

- 规则集构建成功；
- 原生程序包审计成功；
- 当前场景所用定义达到权威覆盖要求；
- 终局结果与游戏规则一致；
- 未知定义率和无效战斗率低于门槛；
- 规则集哈希、模型和评估结果一致。

覆盖不足时可继续生成诊断数据，但不能把结果当作正式胜率，也不能晋级模型。
