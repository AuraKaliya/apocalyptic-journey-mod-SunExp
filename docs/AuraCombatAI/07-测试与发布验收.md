### Worker

```powershell
powershell -ExecutionPolicy Bypass -File tools/Test-AuraFoundationTrainer.ps1 -PreflightOnly
powershell -ExecutionPolicy Bypass -File tools/Test-AuraFoundationTrainer.ps1
```

该入口只在 Worker 实现变更、`foundation` profile 或发布候选中运行；普通
AuraToolsExp、共享层和 Combat AI 内部行为变更不主动运行 Worker smoke。

预检必须运行随机种子和 `integrity-seeds-v1` 历史故障语料，返回 `preflight-passed` 且没有检查点。生产 Worker 在语义准入失败时仍返回 `training-rejected`，隔离已生成 episode，且必须非可恢复、零模型包、零持久化回放；但发布 smoke 必须实际通过语义门禁，不再把拒绝态视为发布成功。`TrainingCampaignsPerIteration` 可用于扩展抽样，发布前至少执行一次 16 旅程验证并确认 `SelectedInvalidActions=0`、`SelectedUnexplainedMismatchActions=0`。接纳结果必须同时生成能够通过长度、SHA-256、FP32 复载、内容集合绑定、配对证据验收证明和兼容性校验的 `foundation-model-package-v5.json` 与 `foundation-model-weights-v5.bin`。

### 外部控制台与导入

发布前还要确认：

1. `Build-AuraFoundationTrainer.ps1` 同时产生 Worker 和 Control Center 两个单文件程序；
2. 控制台能够启动任务、重新连接、请求安全取消和从 Champion 创建下一轮；
3. 游戏中的“选择底模验证”拒绝损坏包和不兼容包；
4. 导入后当前实战模型不变，正式推演和实机验证使用 `evaluationModelId`；
5. 普通、高级和实机门禁全部通过前，“加入模型库”不可用；
6. 加入模型库后模型默认关闭，且隔离待验证项被清除；
7. 两个 Worker 不能同时写同一成功案例库。
8. 控制台分别显示 Worker 完成、训练成功、模型接受、执行 epoch、选中 epoch 和检查点字节数。
9. 发布目录包含 `TransformerTeacher/train_teacher.py`、`Setup-AuraTransformerTeacher.ps1` 与可双击的 `Install-AuraPyTorch.cmd`；一键安装器必须能自动安装/发现 Python、验证 PyTorch 与 NumPy、注册 `AURA_TRANSFORMER_PYTHON`，并仅在 `auto` 下允许 CUDA 失败后回退 CPU。CPU 发布机至少运行一次 `Test-AuraFoundationTrainer.ps1 -TransformerTeacherBackend cpu`，确认教师模型、标注和质量门禁报告完整。CUDA 开发机以同一 smoke 参数改用 `cuda`，报告中的 `EffectiveBackend` 必须为 `cuda`。
10. `PythonExecutable=auto` 的 smoke 必须报告非空的绝对 `ResolvedPythonExecutable`、解析来源、Python/PyTorch/NumPy 版本和设备；显式请求 `cuda` 时不可接受 CPU 回退。
11. 自动执行计划必须报告有效 CPU/interop 线程、有效 Batch/Microbatch、DataLoader worker/prefetch、数值精度、数据准备/校准时间与有限的训练 frames/s；第二次相同配置运行应命中相应缓存。
12. 独立训练控制台不得暴露冒险或模型训练 CPU 并行度输入；Worker 必须以本机逻辑处理器数为上限，测量 50%/75%/100% 三个规范化并发点后按稳定吞吐自动选择。常规保留线固定为 128 MiB，Transformer 使用预测峰值外加 128 MiB 的独立阶段门禁；每轮必须在独立子进程中完成，检查点落盘后退出，后续轮复用本次训练内已经验证的 Auto-Tune。下一轮不得继承上一轮 GC 堆、搜索 Arena、线程池或 Python 数据集。每轮必须记录工作集、GC live/committed/fragmented、容量、余量、保留值、每通道成本和选择原因。Replay 仓库与有界跨进程热窗口、Transformer 磁盘分片及教师阶段内存门禁必须通过跨轮 smoke。
13. Episode 热路径必须优先保存数值 Token/Value 列；字符串特征字典只允许在 JSON、内容训练包、教师语料或诊断边界按需物化。教师后端关闭时不得构造 WorldModel Observation Envelope。遥测必须报告紧凑状态/候选向量数、兼容字典物化数以及 WorldModel 构造/跳过数。
14. 同一冒险内的决策引擎、搜索状态 Arena、搜索节点 Arena、模拟命令队列与动作语义 Outcome/Effect 槽必须跨战斗复用；观测投影不得重复扫描同一手牌或为标签合并构造逐牌临时集合。输出必须与非池化前向模型逐字段等价。50%/75%/100% 性能验收同时记录吞吐、CPU、Gen2 与分阶段托管分配，不能仅凭瞬时 CPU 峰值判定通过。
13. 教师首次运行必须报告 `WarmStarted=false`、`TrainingRefreshed=true`；同结构模型的仅标注运行必须报告 `WarmStarted=true`、`TrainingRefreshed=false`、`EpochsExecuted=0`，且标注行数与输入帧数一致。
14. 教师进度心跳必须覆盖 loading/preparing/training/evaluating/annotating/saving，Windows 上 `ProcessCpuPercent`、`ProcessCpuSeconds`、`WorkingSetBytes` 与 `PeakWorkingSetBytes` 不得长期保持无效值。
15. 滚动验证必须按种子序号确定性提交，在验证数小于检查间隔时仍执行队尾早停判定，并在外部 Worker 保留策略下释放完整战斗图。
16. 训练分析必须标记 `foundation-performance-probe-v1`，阶段热点至少包含墙钟、Worker/外部 CPU、分配、峰值并发和参与线程；Transformer 报告必须分别包含加载、张量化、校准、训练、评估、标注和保存耗时。
17. 教师和学生必须报告同一有界训练窗口的身份、源帧/入选帧和各自消费数；角色策略配额不足时正式晋级必须失败，并显示逐策略缺口。
18. 不安全结束回合必须分别报告策略监督帧、风险辅助帧和丢弃帧；风险辅助帧不得参与 Policy/Q 梯度。
19. 首次教师训练必须创建固定锚点；热更新应在相同锚点上报告基线/更新后多头指标、教师代次和接受状态。构造任一头超限回归的测试时必须回滚上一代权重。
20. 非引导轮的正式晋级必须同时验证最小胜负不一致对、Advanced 绝对胜率、同集多头不回归和策略配额，不得用“证据不足”通过门禁。

## 实机验证

自动门禁通过后，在与仓库程序集匹配的游戏环境检查：

1. 普通战斗、Boss、多目标和交互选择；
2. 自动战斗开关、暂停、人工接管和场景切换；
3. 费用变化、目标死亡、UI 重建和动作超时；
4. 隐藏牌序不进入日志和训练特征；
5. 预测标记与当前候选一致，不显示过期动作；
6. shadow 模式不改变实际执行；
7. active 模式只加载已通过门禁的当前模型；
8. 游戏退出、任务取消和 Worker 异常后的文件完整性；
9. 普通/高级情景旅程的权威覆盖和终局一致性。
10. 外部待验证模型不会在晋升前影响当前 active/shadow 模型。

## 性能验收

记录：

- 决策 p50、p95、p99；
- 每次决策模拟数、节点数、深度和早停原因；
- 搜索模拟/秒；
- 主线程最长阻塞；
- 后台队列长度和丢弃数；
- Worker CPU、内存、campaign/秒和预计剩余时间；
- 自动计划的请求值/有效值、缓存命中、教师分阶段耗时、训练/标注 frames/s、进程 CPU、峰值工作集、数值精度和峰值设备内存；
- 共享训练窗口消费率、策略配额/缺口、固定锚点、数据漂移、教师代次与更新回滚；
- 各阶段墙钟占比、Worker/外部 CPU、有效 CPU 利用率、托管分配、峰值并发与参与线程；
- 检查点序列化有效线程、扩展状态、耗时、入队/执行/合并计数；
- 训练碰撞率、梯度范数和裁剪次数。
- 语义隔离数量、不安全结束回合策略/风险辅助占比和归档去重节省字节数。

强制动作不应消耗深度搜索预算。复杂状态可以更慢，但必须受节点、深度、模拟量和动作超时共同约束。

### 失败种子重放

独立 Worker 可直接复用原始任务、检查点和训练策略重放单个世界种子：

```powershell
AuraFoundationTrainer.Worker.exe --job foundation-worker-job.json `
  --replay-seed 2049918757947132046 --difficulty advanced `
  --checkpoint foundation-training-checkpoint-v12.json.gz `
  --trace full --output foundation-replay.json
```

未显式提供 `--exploration` 或 `--exact-branch` 时沿用任务中的训练参数；输出保留完整战役、战斗状态、事件和失败诊断。已确认的失败种子同时进入 `CombatFoundationIntegritySeedCorpus`，后续训练必须在自博弈前自动回归。

### 32 逻辑线程验收基线（2026-08）

在 Ryzen 9 9950X3D（16 个物理核、32 个逻辑处理器）上，v9 隔离训练器的综合夹具托管分配由约 2039 MB 降至约 685 MB。关键消减来自：根公开观测哈希每次决策只计算一次；确定化洗牌复用 `卡牌 ID → 知识值`，不再为每次模拟重复创建动作语义对象；教师关闭时跳过 WorldModel Envelope；Episode 使用紧凑 Token/Value 列与可复用动作模型 Arena。

历史 v9 稳态标定曾得到 8/16/32 为 10.4/12.0/7.3 work/s，但该测量混入了每轮回放增长、检查点并发序列化、线程搜索 Arena 高水位驻留与 GC 压力，不能作为长期固定并发档位的依据。v11 改为按当前硬件的 50%/75%/100% 并发点重新测量稳定吞吐，内存容量只提供安全上限。若自动选择低于逻辑处理器数，报告必须同时给出本轮吞吐测量和可复算的内存容量证据。

## 发布阻断

出现以下任一项不得发布：

- 当前测试失败；
- 仓库仍存在被替代的搜索器、配置键、协议字符串或数据路径；
- 模型/规则集/结果哈希不一致；
- 权威覆盖不足却显示正式胜率；
- 测试集参与模型选择；
- 预检留下可恢复训练检查点；
- 语义准入失败后仍持久化 replay、保留可恢复检查点或生成模型包；
- 非有限特征、梯度、权重或搜索统计；
- 实机出现隐藏信息读取、非法动作或主线程长阻塞。

## 故障处置

先关闭模型为 `off`，保留规则底模和诊断日志；若硬合法性、信息边界或事务本身失效，则关闭自动战斗。修复后重新生成当前协议数据和模型，不使用旧产物继续训练。
