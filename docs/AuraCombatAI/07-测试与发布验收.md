# 测试与发布验收

## 自动测试

### AI 核心

```powershell
powershell -ExecutionPolicy Bypass -File tools/Test-AuraCombatAi.ps1
```

覆盖：

- 候选评分、支配和事务；
- 根抽样、机会结果、转置图和主变化；
- 风险统计、尾部收缩和统一根排序；
- 动态预算与质量档；
- 公开特征边界和哈希分区；
- 在线样本、Episode 和回报回填；
- AdamW、梯度裁剪、分组切分、早停和确定性恢复；
- CLI 无 UI 模拟固定哈希；
- 当前协议和已删除标记的仓库扫描。

### AuraTools 集成

```powershell
powershell -ExecutionPolicy Bypass -File tools/Test-AuraToolsExp.ps1
```

覆盖当前配置、设置 UI、后台任务、候选模型、数据清理和运行时编译门禁。

### Worker

```powershell
powershell -ExecutionPolicy Bypass -File tools/Test-AuraFoundationTrainer.ps1 -PreflightOnly
powershell -ExecutionPolicy Bypass -File tools/Test-AuraFoundationTrainer.ps1
```

预检必须返回 `preflight-passed` 且没有检查点。完整 smoke 必须产生搜索/模型遥测，并按是否晋级正确删除或保留检查点。接纳结果必须同时生成能够通过哈希和兼容性校验的 `foundation-model-package-v1.json`。

### 外部控制台与导入

发布前还要确认：

1. `Build-AuraFoundationTrainer.ps1` 同时产生 Worker 和 Control Center 两个单文件程序；
2. 控制台能够启动任务、重新连接、请求安全取消和从 Champion 创建下一轮；
3. 游戏中的“选择底模验证”拒绝损坏包和不兼容包；
4. 导入后当前实战模型不变，正式推演和实机验证使用 `evaluationModelId`；
5. 普通、高级和实机门禁全部通过前，“加入模型库”不可用；
6. 加入模型库后模型默认关闭，且隔离待验证项被清除；
7. 两个 Worker 不能同时写同一成功案例库。

### 原生奖励

运行 `AuraToolsExp.NativeReward.Tests`，确认原生卡牌、状态和奖励程序在权威模拟器中可确定执行。

## 实机验证

自动门禁通过后，在与仓库程序集匹配的游戏环境检查：

1. 普通战斗、Boss、多目标和交互选择；
2. 自动战斗开关、暂停、人工接管和场景切换；
3. 费用变化、目标死亡、UI 重建和动作超时；
4. 隐藏牌序不进入日志和训练特征；
5. 预测标记与当前候选一致，不显示过期动作；
6. shadow 模式不改变实际执行；
7. active 模式只加载已通过门禁的当前模型；
8. 游戏退出、任务取消和 Worker 异常后的文件完整性；
9. 普通/高级情景旅程的权威覆盖和终局一致性。
10. 外部待验证模型不会在晋升前影响当前 active/shadow 模型。

## 性能验收

记录：

- 决策 p50、p95、p99；
- 每次决策模拟数、节点数、深度和早停原因；
- 搜索模拟/秒；
- 主线程最长阻塞；
- 后台队列长度和丢弃数；
- Worker CPU、内存、campaign/秒和预计剩余时间；
- 训练碰撞率、梯度范数和裁剪次数。

强制动作不应消耗深度搜索预算。复杂状态可以更慢，但必须受节点、深度、模拟量和动作超时共同约束。

## 发布阻断

出现以下任一项不得发布：

- 当前测试失败；
- 仓库仍存在被替代的搜索器、配置键、协议字符串或数据路径；
- 模型/规则集/结果哈希不一致；
- 权威覆盖不足却显示正式胜率；
- 测试集参与模型选择；
- 预检留下可恢复训练检查点；
- 非有限特征、梯度、权重或搜索统计；
- 实机出现隐藏信息读取、非法动作或主线程长阻塞。

## 故障处置

先关闭模型为 `off`，保留规则底模和诊断日志；若硬合法性、信息边界或事务本身失效，则关闭自动战斗。修复后重新生成当前协议数据和模型，不使用旧产物继续训练。
