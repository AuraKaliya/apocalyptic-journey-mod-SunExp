# 异机环境与交接流程

## 环境要求

外部开发或测试机至少需要：

- Windows；
- Git；
- .NET 8 SDK；
- PowerShell 7，命令为 `pwsh`；
- 与仓库 `Managed/` 对应的游戏版本；
- 可以启动游戏并加载本地 MOD 的测试环境；
- 足够空间保存日志、录像和训练样本。

不要使用另一游戏版本的 Managed 程序集覆盖仓库基线后直接发布。需要升级宿主版本时，应建立单独升级任务并重新验证签名和反编译差异。

## 首次准备

1. 克隆仓库并确认当前分支和 commit。
2. 检查 `git status --short`，不要覆盖未提交的本地内容。
3. 确认 `Managed/Witch.dll`、`Witch.Core.dll`、Unity 和插件程序集存在。
4. 执行共享自动化测试。
5. 构建三个主要消费者。
6. 执行共享 DLL 一致性检查。
7. 将仓库中的交付 MOD 目录按测试机既有方式安装到游戏。
8. 启动游戏前记录 MOD 清单和配置。

推荐命令：

```powershell
pwsh -NoProfile -File tools\Build-MainSharedConsumers.ps1 -Configuration Release
pwsh -NoProfile -File tools\Test-SharedDllPackaging.ps1 -Configuration Release
pwsh -NoProfile -File tools\Test-SharedReleaseGate.ps1 -Configuration Release
pwsh -NoProfile -File tools\Test-TerriasCSharp.ps1 -Configuration Release
```

构建会更新：

- `Terrias/Scripts/Entry.dll`；
- `AuraToolsExp/Scripts/Entry.dll`；
- `SanGuoShaExp/Scripts/Entry.dll`；
- 各消费者的 `Aura.Shared.dll`。

## 配置准备

首轮烟雾测试建议：

```json
{
  "enabled": true,
  "startActive": false,
  "profile": "balanced",
  "decisionIntervalMs": 350,
  "actionTimeoutSeconds": 12.0,
  "unknownActionPolicy": "handoff",
  "captureTrainingSamples": true
}
```

先使用 `handoff`，确保未知交互不会被强行尝试。基础流程稳定后，再分别测试 `conservative` 和 `allow`。

## 证据目录约定

测试证据不要直接混入交付 MOD 目录。建议在仓库外或测试专用目录使用：

```text
auto-battle-validation/
  YYYY-MM-DD_commit/
    environment.md
    test-report.md
    logs/
    screenshots/
    videos/
    samples/
```

`environment.md` 至少记录：

- commit；
- 游戏版本；
- Windows 与 .NET 版本；
- MOD 清单及加载顺序；
- 分辨率和语言；
- 自动战斗配置；
- `Aura.Shared.dll` 哈希。

## 训练样本

启用样本记录后，默认文件由共享日志路径管理：

```text
Logs/Owners/AuraToolsExp/auto-battle-training-v1.jsonl
```

交接样本前：

- 保留原始文件只读副本；
- 记录对应 commit、配置和 MOD 清单；
- 不把不同协议版本直接合并；
- 检查文件是否包含意外的用户路径或个人信息；
- 以整场战斗为最小分组生成后续数据集。

## 完成一次测试后的交接

外部测试人员应提交：

1. 填写完成的测试报告；
2. 所有 P0/P1 结果；
3. 可复现缺陷及证据；
4. 自动化命令输出摘要；
5. 构建产物哈希；
6. 训练样本审计摘要；
7. 是否建议进入下一阶段。

只提供“玩了几局没问题”不能作为阶段退出证据。
