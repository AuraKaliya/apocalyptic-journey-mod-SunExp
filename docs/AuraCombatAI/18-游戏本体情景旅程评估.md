# 游戏本体情景旅程评估

## 目标

正式评估不再把首领战当成孤立快照。每个世界种子只初始化一次游戏本体开局，角色连续经历普通战斗、奖励选择和局内成长，最后挑战固定的游戏本体首领。

Terrias 角色、卡牌和首领不进入首批正式评估包。

## 确定性边界

`CombatJourneyWorldPlanner` 在战斗开始前冻结世界计划：

- 关卡数和敌人池来自旅程数据，不在算法中臆造。
- `encounter` 与 `reward` 使用隔离的命名随机流。
- 同一世界种子的底模与学习模型共享敌人序列和奖励候选。
- 世界计划具有稳定 `planHash`，结果与检查点都记录该值。

双方采用相同的奖励评分器，但生命、牌组或已选奖励不同后，允许做出不同选择。

## 奖励选择

奖励卡使用连续特征向量描述。评分包含：

- 基础奖励价值；
- 当前牌组的体系契合；
- 角色初始倾向与构筑倾向；
- 越接近最终首领权重越高的首领适配；
- 防御、抽牌、可靠性等短板补齐；
- 牌组膨胀、重复卡和风险惩罚。

评分结果逐项写入旅程结果，可解释且使用稳定卡牌 ID 处理同分。允许在最高总分不大于零时跳过奖励。

## 运行与恢复

`CombatJourneyRunner` 在每场战斗后生成检查点，包含：

- 下一场战斗索引；
- 当前生命；
- 当前牌组；
- 已完成战斗与奖励记录；
- 世界种子、计划哈希和策略 ID。

恢复时必须匹配旅程 ID、世界种子、计划哈希和策略 ID，避免把旧检查点套到不同评估上。

AuraToolsExp 的模拟评估会把 `*.journey.json` 与 `*.ruleset.json` 同时从以下位置载入：

1. 用户日志目录的 `combat-simulation-input`；
2. MOD 自带的 `Config/combat-simulation`。

用户目录优先，方便临时修订；正式发布包应放在 MOD 配置目录。

## 门禁

普通失败和最终首领失败计入全旅程失败。规则无效、非权威覆盖或不支持语义计为 invalid，不冒充战败，同时阻止门禁通过。

建议规模：

- 快速检查：每场景 8 个世界种子；
- 标准验证：64 个世界种子；
- 发布门禁：200 个独立保留种子。

当前知识包尚无权威敌人和遭遇导出，因此实现只提供协议、执行器、检查点和自测，不附带伪造的正式首领套件。
