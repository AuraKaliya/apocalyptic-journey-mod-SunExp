# 扩展接入规范

## 语义提供器

内容 MOD 应为自己拥有的卡牌或技能补充效果语义。语义提供器可以描述：

- 伤害、护盾、治疗、抽牌和能量；
- 成长、牌组价值、风险和不确定性；
- 是否会打开额外交互；
- 是否包含随机结果。

注册入口：

```csharp
CombatAiRegistry.RegisterSemanticProvider(
    ownerModId,
    providerId,
    provider,
    priority);
```

要求：

- provider id 在 owner 范围内稳定；
- 不修改游戏状态；
- 不打开 UI；
- 不依赖 AuraToolsExp；
- 对不属于自己的动作返回 `false`；
- 同一动作的语义必须可重复。

## 合法性规则

对宿主基础规则无法表达的条件使用 `ICombatPreflightRule`：

```csharp
CombatAiRegistry.RegisterPreflightRule(
    ownerModId,
    ruleId,
    rule,
    priority);
```

规则必须是纯检查。禁止：

- 调用出牌或技能入口；
- 扣费、移除卡牌或改变冷却；
- 触发事件；
- 播放提示、音效或动画；
- 写入 `Vars`、状态或存档；
- 用异常作为正常拒绝流程。

返回 `false` 时应提供可诊断的拒绝原因。

## 复杂交互提示

在调用原生选择 API 前设置“下一次交互”提示：

```csharp
CombatInteractionBroker.SetNextHint(new CombatInteractionHint
{
    OwnerModId = ownerModId,
    Purpose = "select-cards-to-burn",
    Kind = CombatPromptKind.BurnCards,
    Zone = CombatPromptZone.Hand,
    Forced = true,
    PreferLowestValue = true
});
```

要求：

- 只有确认将打开选择 UI 时才发布；
- 原生调用抛出异常时清除未消费提示；
- `Purpose` 使用稳定、可检索的英文标识；
- `PreferLowestValue` 只表达选择方向，不能代替完整语义；
- 自定义排序、滑条或拖放 UI 必须新增专用适配器，不能伪装成卡牌多选。

## 新 UI 适配器

新增适配器前需要回答：

1. 原生 UI 的创建入口是什么；
2. 选择完成事件是什么；
3. 可以通过哪个原生控件提交；
4. 关闭自动战斗时如何交还玩家；
5. UI 消失、对象销毁或战斗结束时如何清理；
6. 是否允许多帧选择；
7. 如何防止重复提交；
8. 如何设置超时和记录失败。

适配器只负责桥接原生 UI。选择价值仍由共享决策层计算。

## 友方 AI 接入

友方单位需要实现或组合：

- `ICombatObservationProvider`；
- `CombatDecisionEngine`；
- `ICombatActionExecutor`；
- 内容语义和合法性注册；
- 单位行动权检查；
- 联机 authority 检查。

友方观察必须只暴露该单位可以知道和使用的状态。执行器必须验证：

- 当前是否轮到该单位；
- 动作是否属于该单位；
- 资源是否属于该单位；
- 目标是否仍然有效；
- 当前进程是否拥有执行 authority。

不要让友方 AI 操作玩家 FightUI，也不要复用玩家按钮点击作为友方动作入口。

## 模型接入

学习模型实现 `IDecisionResidualModel`：

- 输入只能是版本化数值特征；
- 输出是有限范围的分数残差；
- 不持有运行时对象；
- 不执行 I/O；
- 不改变合法性；
- 推理异常时返回 0 并回退启发式模型。

模型加载器属于战斗共享层或独立共享模型适配层，不能放进内容 MOD 的脚本入口。

## 兼容与发布

新增公共类型或协议字段后：

1. 更新协议文档；
2. 增加纯逻辑测试；
3. 运行共享公共 API 兼容性检查；
4. 构建 Terrias、AuraToolsExp 和 SanGuoShaExp；
5. 验证三个 `Aura.Shared.dll` 副本一致；
6. 更新外部测试场景。
