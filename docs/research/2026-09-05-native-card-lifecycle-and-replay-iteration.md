# 原生卡牌生命周期与战斗回放迭代

本轮依据用户确认的正常战斗焚毁错位，以及
`AuraTools-20260905-174258.log` 中三场洛奈尔战斗的耗时和材质冲突展开。

## 最终实现

- 删除 Terrias 完整战斗卡牌对象池、桶目录、实例标记、退出层/动画替代、
  构造探针及功能开关。动态卡牌经原生 `GetCardFromDeck` 队列创建、初始化、
  使用、退出和销毁。保留资源缓存及独立 UI 列表池化。
- 战斗结算关闭原生待创建队列的职责移交给独立的卡牌生产边界；视图销毁
  由原生 FightUI 完成。没有保留可再次启用旧整卡池的分支。
- 共享 CardPresentation 在原生 Init/DataUpdate/SetCardStyle 的嵌套调用期间
  阻止中途重挂，在需要改写材质前释放旧效果，外层成功结束后提交一次表现。
  NativeExit 保留静态卡面、释放临时效果并阻止后续重挂；正常战斗与无脚本
  回放都使用 `PrepareNativeExit`。共享公共面增加 9 项元数据条目，没有删除旧 API。
- Terrias 精灵 HUD 移除元素徽标，回放的竖向 HUD 同步省略该装饰。
- 新记录采集碰撞体的局部几何及动作期间变化，回放按宿主实际姿态定位精灵，
  避免武器/披风动画帧扩大 Sprite 边界而移动精灵和 HUD。旧记录使用已有的
  初始形体作为稳定参照，不伪造缺失的碰撞体测量。
- 记录真实手牌拖动、释放、归位和退出轨迹；同一物理视图跨阶段连续观察。
  同一逻辑卡牌的手牌和中央展示使用独立 visual identity，移动时隐藏静态
  手牌副本。原生攻击卡仍使用自己的指向操作，不人为制造拖动。
- 卡牌和角色轨迹压缩保留静止区间两端，防止下一段移动被插值拉长到整个
  停顿期间。焚毁材质只在实测焚毁阶段启用，录制时按原生 Shader 身份识别。
- 原生中央卡在 `needInit=false` 时没有 dataConfig；按调用前实例集合、
  明确父节点和排他视图所有权绑定，避免误拒绝或重复记录其同步退出动画。

## 录制开销

移除录制阶段反复生成、最终封存时又会重建的临时事件/状态哈希链。增量批次
仍有完整性哈希；最终哈希链、检查点和文档根在封存时生成。保留开放事务及
可变轨迹的耐久前缀约束，并用事务起始序号索引避免每次排序整个历史。

事务快照改为独立的类型化复制；标量读取不再复制整个可见状态；复用已经
计算好的状态差异并检查其原始状态版本。每场记录缓存内容来源与 MOD 版本，
避免每个 BUFF、每次状态采集都枚举程序集。JSON serializer 按线程独立持有。

相同实际记录的 C# 工作负载（60 次事务、状态比对与账本快照）：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 耗时 | 122.3875 ms | 5.2566 ms |
| 当前线程分配 | 94,607,672 bytes | 6,530,480 bytes |
| 最终状态哈希 | 相同 | 相同 |

该基准不包含 Unity、最终封存、GC 停顿及完整游戏帧耗时，不能换算成游戏 FPS
提升或断言精灵首次召唤的全部耗时已经消失。原日志的 445 次同步处理合计
2042.17 ms、单次最高 73.981 ms，作为后续新日志的对照数据。

- AuraTools 全套门禁及 1457 条行为断言通过。
- 共享 Core 1296 条断言通过；公共 ABI 的 9 项新增已逐项审核，基线 5670 项。
- Terrias 847 条断言、架构门禁通过；删除的是已退役整卡池的专属断言，

- Unity 6000.0.46f1 / URP 17.0.4 GPU PlayMode 16 项通过，覆盖原生 HP/护盾
  像素、精灵锚点、多视图、拖动停顿和延后焚毁。
- 两个产品 Release 构建零警告/错误，共享 DLL 包装一致性通过。
- 用户提供的三场新记录及此前一条记录，共四条封存 v17 文档，通过当前生产
  校验逻辑，数据只读且不重封存。新几何和视图字段在缺省时不参与 canonical
  JSON；新记录按实际字段声明 `measured-attachment-bounds.v1` 与
  `observed-card-view-identity.v1`，旧播放器会拒绝需要新能力的记录。

完整拖动、原生碰撞体测量和修正后的实战焚毁需要新录制的战斗验证。历史记录
已录入的错误位置或未采集的拖动不能无损恢复。完整三场实机、拖动取消、
快速连续出牌、变速、定位、导出和下一场战斗，不能用上述自动测试替代。
