# 战斗回放：确认决策与统一观看节奏

## 已确认的功能契约

回放呈现最终被游戏受理的决策及其结果，省去思考、未提交拖牌、取消、悬停和暂定选择。
受理后被免疫/抵消的出牌仍是有效动作。出牌、技能、结束回合和动作中的确认选择构成决策；
抽牌、被动、精灵/伙伴动作等因果过程保持原来的执行关系。可裁剪的决策等待替换为一次
0.5 秒观看停顿，必要表现发生重叠时保留执行区间。

## 实现与边界

- `MatchReplayDecisionCapture` 读取原生输入、选牌确认、动作/抽牌队列和观察生命周期；
  `ReplayDecisionCaptureV17` 持有唯一开放等待，向已有 journal 写入不可变的开始、结束和确认事件。
- 新 UI 描述声明 `confirmed-decisions.v1`，文档及联机录制协商声明对应能力。历史 v17 文档
  不补造输入见证，保持原始节奏和封存字节，在播放器明确显示其节奏来源。
- `ReplayDecisionTimelineV17` 生成仅供观看的派生文档。原始事件、根哈希和用户文件不变；
  状态增量按原顺序通过原状态哈希校验。派生文档不会重新封存或写入资料库。
- 播放、检查点定位、暂态重建、样本偏移、音频采样起止、视频帧数和回合导航共用同一映射。
  晚到的实际轨迹、有限音效及其他必要表现区间受保护；BGM 和持久 HUD 不把整个等待变成执行。
- 输入接管原生入手/重排时，先结束该自动观察，避免把鼠标过程追加到原有轨道。
  静态手牌使用既有 `CaptureCardLayout` 的原生 `initPosition` / `initScale` 目标布局；无需补写
  一条合成回手轨迹。确认选牌后的重排保持录制，即使原生还没有清理选择 UI。
- `OtherTurn` 表示本视角等待远端动作，不能据此声明远端玩家的私有输入状态。
  已收到的状态和动作、队列与来源义务以及观察到的执行仍需保留。
