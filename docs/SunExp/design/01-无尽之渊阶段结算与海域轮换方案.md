# 无尽之渊阶段结算与海域轮换方案

> 状态：候选设计，尚未实施
> 整理日期：2026-07-13
> 适用基线：当前 `EndlessSea*` 六节点楼层循环
> 本文只沉淀已讨论方案，不代表当前游戏行为。

## 1. 目标与边界

当前无尽之渊会在每层完成后直接增加 floor、重置宿主 Level 并生成下一层，没有自然终点。`EndlessSeaRunStateStore` 已有 `BetweenFloors` 和 `Ended`，但尚无玩家可操作的主动撤离、不可重复的阶段结算或运行历史。

候选方案希望补齐三件事：

1. 给无限运行提供明确、可恢复的主动结束路径；
2. 用阶段和海域组织长期难度、敌人、场地与奖励变化；
3. 保持宿主地图、无尽深渊压力、联机权威和旧存档兼容边界不变。

本文不设计具体 UI、美术资源、数值表和永久局外奖励，也不在当前版本改变楼层推进。

## 2. 阶段结构候选

建议以 6 层为一个完整“海域”，以 3 层为一个“潮汐阶段”：

| 位置 | 作用 |
| --- | --- |
| 海域第 1-2 层 | 引入本海域敌人与主要规则 |
| 海域第 3 层 | 潮汐切换，可提供低规格紧急撤离 |
| 海域第 4-5 层 | 提高压力，增加精英或特殊组合 |
| 海域第 6 层 | 海域首领、完整奖励和港口结算 |

6 层周期与当前 1-6 层潜行、第 7 层进入无尽阶段的边界一致。若后续认为每 3 层变化不足，可以更换潮汐场地和敌人权重，但不建议每 3 层同时替换整套地图、美术、首领和奖励池。

## 3. 主动撤离

第一版只在安全结算点开放撤离，不提供战斗中逃跑：

- 第 3 层完成全部节点、奖励和深渊结算后，可进入“紧急撤离”；
- 第 6 层击败海域首领并领取全部奖励后，进入“港口结算”；
- 撤离选择发生在 `BetweenFloors`，并且早于下一层 floor 递增和地图计划生成；
- 继续深入保持 run 未结束，撤离则写入结果后调用结束路径。

紧急撤离可以使用较低的结算倍率或较少的阶段奖励；港口撤离提供完整阶段成绩。具体奖惩留待数值设计，不在状态机中硬编码。

## 4. 结算事务

撤离不能只是弹窗后设置 `Ended`。推荐顺序为：

```text
完成本层奖励与深渊结算
  -> 冻结阶段结果快照
  -> 写入 runId:floor:stage 的结算事务键
  -> 选择继续或撤离
  -> 撤离时先持久化结果历史
  -> 标记运行终态并清理 run-only 内容
  -> 展示结果并离开当前冒险
```

事务必须幂等。若保存后崩溃或 UI 中断，再次载入只能继续展示同一结果，不能重复发放奖励、再次生成地图或覆盖最终成绩。

运行终态建议从单一 `Ended` 标志扩展出结果类型：

| 结果 | 含义 |
| --- | --- |
| `Extracted` | 在阶段结算点主动撤离 |
| `Defeated` | 战斗失败导致运行结束 |
| `Abandoned` | 从存档管理主动放弃 |

`Ended` 仍可作为兼容布尔字段，结果类型用于历史、统计和后续成就。

## 5. 结果快照与历史

结算快照建议至少保存：run id、seed、角色、抵达层数、完成节点和首领、卡组、遗物、祝福、本源、注视等级、深渊进化、运行时长、内容版本和最终分数。未来新增的本场冒险限定收藏可以通过带版本的扩展段加入。

历史记录应与可续玩的 `SaveInfo` 分离。删除、覆盖或迁移运行存档不能同时抹掉已经完成的结算记录。分数第一版只用于展示和比较，不直接作为可反复刷取的永久货币。

## 6. 海域与潮汐配置

建议由 SunExp 自己维护 `EndlessSeaRegionSpec` 注册表，而不是把无尽之渊语义下沉到 Aura 共享层。每个海域配置包含：

- 稳定主题 id、显示名和版本；
- 地图标题、背景、音乐与视觉资源键；
- 普通、精英、召唤物和首领候选池；
- 第 1-3 层与第 4-6 层的潮汐场地或战斗修正；
- 奖励配置 id、卡包倾向和遗物稀有度权重；
- 不可用内容、兼容回退和旧版本迁移规则。

海域选择必须由 run seed 与海域序号确定，并把主题 id、潮汐 id 和配置版本写入楼层计划或权威快照。重新打开 UI、客户端晚加入或存档续玩不能重新随机主题。

## 7. 敌人、场地与奖励

敌人池以策划维护的 id 或标签集合为主，现有动态 Map 筛选只作为兼容回退。这样可以避免其他 MOD 或新增官方内容未经验证就进入主题池。首领应在海域开端或后半段提供预告，保证玩家能够围绕终局威胁调整卡组。

“场地变化”必须对应真实战斗规则和可同步状态，而不只是更换地图背景。若新场地运行时尚未准备好，可以先用无尽之渊自己的战斗修正实现潮汐规则，不能显示一个没有实际效果的场地名称。

奖励通过 `RewardProfileId` 选择卡牌数量、卡包倾向、祝福概率和遗物组。主题主要改变奖励结构与偏向，不应让每个新海域都无条件增加奖励总量。

候选主题原型包括：

| 海域 | 主要方向 |
| --- | --- |
| 灼热海 | 灼烧与持续伤害，净化和恢复倾向奖励 |
| 晨星海 | 魔能、费用和出牌次序，升级与谱句倾向奖励 |
| 镜像海 | 投影、复制和意图干扰，伙伴与形态倾向奖励 |
| 深渊海 | 诅咒、牺牲与高压成长，提高成绩倍率和撤离风险 |

## 8. 联机与权威

只有主机或服务器能够冻结结算快照、决定主题、推进 floor 和写入最终结果。客户端只提交撤离意向并接受权威广播。

多人主动撤离候选规则为“房主发起、全员确认”。未达成一致则继续深入，避免单个玩家直接终止全队运行。超时策略、掉线成员处理和是否允许多数票需要在 UI 设计阶段另行确认。

权威快照未来需要增加海域 id、潮汐 id、配置版本、结算事务键和结果类型；仍沿用现有 generation、host session、payload 大小限制和旧快照拒绝规则。

## 9. 兼容与实施前置

- 历史 `EndlessSea*` 类名和存档 key 保持不变，玩家标题继续使用“无尽之渊”；
- 旧存档没有主题 id 时，可从 seed 与 floor 推导一次并立即持久化，不能每次载入重算；
- 配置删除或版本不匹配时优先使用已保存主题 id 的回退定义，不能静默换成另一个随机主题；
- 当前 floor 推进在 `ReadyToChangeMap` 前完成，实施撤离时必须把选择点前移到 floor 增加和下一层计划生成之前；
- 阶段奖励、深渊震荡、卡牌附着和 run-only 内容清理需要统一规定结算先后顺序。

## 10. 后续决策清单

正式开发前仍需确认：紧急撤离是否保留完整战斗奖励、结算分数公式、永久奖励边界、多人投票规则、首批海域数量、场地实现方式、主题重复保护，以及失败和主动放弃是否写入同一历史列表。

在这些问题确定之前，当前版本继续使用既有无限楼层循环；本文不作为实现完成的证据。
