# 异次元卡包机制与内容介绍

本文整理【更多的次元】卡包。数据主要来自 `SunExp/Data/Card/sunexp.csv`、`SunExp/Text/Card/sunexp.csv`、`SunExp/Data/CardPack/sunexp.csv`、`SunExp/Text/CardPack/sunexp.csv`，机制以 `SunExp-Dev/Scripting/CardScripts.cs`、`SunExp-Dev/Mechanics/PolymorphActivationService.cs`、`SunExp-Dev/Mechanics/PolymorphBuffService.cs`、`SunExp-Dev/Mechanics/ProjectionActivationService.cs`、`SunExp-Dev/Mechanics/ProjectionSummonService.cs` 和 `SunExp-Dev/Mechanics/HeartChangeControlService.cs` 为准。

## 卡包定位

【更多的次元】是异次元主题功能卡包，运行时 ID 为 `SunExp_sunexp_cardpack_more_dimensions`。当前卡包文本描述仍是占位文案“请输入文本。”，但实际内容已经实现三张正式主牌：`百变`、`拜托了`、`心变`。

这个卡包不是传统数值循环，而是战斗形态工具箱：

| 方向 | 对应卡牌 | 作用 |
| --- | --- | --- |
| 角色变身 | 百变 | 选择已注册角色，生成一次性化身牌，使用后本场战斗变身为目标角色。 |
| 友方投影 | 拜托了 | 生成“另一个我”衍生牌，使用后召唤当前角色的投影作为友方单位参战。 |
| 敌方临控 | 心变 | 在多敌人战斗中临时控制目标敌人，让其下一次行动转向原友方。 |

## 百变机制

`百变`读取当前职业表中已经注册的角色，而不是写死固定角色列表。角色条目来自 `Data/Career` 与对应的角色数据，显示名、卡面、技能字段等会在运行时组装为可选择角色。

使用 `百变`后的流程如下：

1. 打开角色选择界面。
2. 选择目标角色后，获得一张 `百变化身`衍生牌。
3. 衍生牌为 0 费，并带有 `Burnout`、`Nihility`。
4. 使用化身牌后，给自身添加 `百变`特性 Buff。
5. Buff 应用时切换当前角色职业，并进入对应的化身运行时。
6. 化身只在本场战斗内生效；战斗清理时会清空百变状态和相关冷却。

`百变`Buff 的描述会被动态更新为“变身成为目标角色”。如果 Buff 被清除，对应化身状态也会被清理。

## 拜托了与投影机制

`拜托了`先生成一张 `另一个我`衍生牌。当前正式入口使用的是当前角色，也就是说它会尝试召唤“当前角色的投影”。投影不是临时贴图或一次性伤害，而是一个真实加入战斗队列的友方行动单位。

投影召唤条件：

| 条件 | 说明 |
| --- | --- |
| 必须在战斗中 | 非战斗状态不能召唤。 |
| 友方单位未达上限 | 真实玩家数 + 已存在投影数不能达到 4 人上限。 |
| 需要可用友方站位 | 没有空位时召唤失败。 |
| 模型资源可加载 | 投影使用 `Model/player` 资源生成战斗对象。 |

投影属性会根据当前角色源初属性和难度缩放生成：

| 属性 | 计算来源 |
| --- | --- |
| 最大生命 | `28 + 精神 * 3 + 幸运 * 2`，再乘以深渊/词条难度倍率。 |
| 最大魔能 | `3 + 魔力 * 0.2 + 感知 * 0.16`，再乘以倍率。 |
| 攻击 | `5 + 魔力 * 1.2`，再乘以倍率。 |
| 护甲 | `4 + 精神 * 0.7 + 感知 * 0.8`，再乘以倍率。 |

投影加入后会注册到战斗状态、行动队列和 UI 状态列表。它拥有自己的意图，当前内置两类：

| 意图 | 类型 | 效果 |
| --- | --- | --- |
| 敲击 | 攻击 | 基础为伤害意图，按投影攻击和魔力缩放，优先处理低血量目标。 |
| 护盾祝福 | 防御 | 基础为护盾意图，按投影护甲和魔力缩放，在低血量或无护盾时优先级更高。 |

投影死亡或战斗结束时会从投影状态表中清理，并销毁对应战斗对象。

## 心变机制

`心变`用于多敌人战斗中的临时控制。它的正式卡牌文本较短，但实现限制比较明确。

可用条件：

| 条件 | 说明 |
| --- | --- |
| 必须在战斗中 | 非战斗状态不能使用。 |
| 目标必须是敌人 | 不能选择友方或非敌方对象。 |
| 目标必须存活 | 死亡或不可行动目标无法控制。 |
| 目标不能已被心变控制 | 同一目标不可重复控制。 |
| 至少有 2 名未受控敌人 | 防止只剩单敌时把敌方行动完全转空。 |
| 己方必须有空位 | 控制目标会被临时投影到己方站位。 |

控制流程：

1. 对目标敌人添加 `心变`特性 Buff。
2. Buff 应用时创建控制状态，记录目标原位置、缩放、敌人对象和己方空位。
3. 目标被移动到己方站位，并调整朝向。
4. 原生敌人行动队列被代理行动替换。
5. 代理行动会让受控敌人优先攻击原友方中生命值最低的未受控敌人。
6. 行动完成或控制结束后，目标返回原位，心变状态被清理。

`心变`控制期间，目标的生命值与 Buff 仍然是原对象共通，并且仍计为敌人。它不是永久倒戈，而是一次行动窗口的借位与重定向。

## 与其它系统的关系

异次元包会调用跨系统能力：百变使用角色注册与化身运行时，拜托了使用友方槽位与伙伴意图系统，心变使用敌人行动队列代理与目标重定向。因此它比普通卡包更依赖运行时安全处理。清理战斗、死亡状态、行动结束和 UI 关闭时，相关状态都会被主动清空，避免投影或控制残留到下一场战斗。

## 构筑思路

`百变`适合把某个角色的技能或被动临时带入当前战斗，价值取决于角色池。`拜托了`适合长线战斗或需要额外行动单位分摊压力的场景。`心变`适合多敌人战斗，尤其是敌方高攻击意图明显、且场上仍有可被攻击的原友方目标时。

这个卡包的强度更多来自战斗结构，而不是牌面数值。敌人数、己方空位、角色池质量和战斗时长都会显著影响它的表现。
