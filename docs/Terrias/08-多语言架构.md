# Terrias 多语言架构

Terrias 的运行时语言统一使用 `zh-Hans`、`zh-Hant`、`en`、`ja` 四个标识。`TerriasLanguageApi` 负责把游戏语言规范化，并转发游戏的 `LanguageChange` 事件。

## 文本来源

- 游戏原生 CSV 字段继续使用 `Name`、`Name_zh-Hant`、`Name_en`、`Name_ja` 等原生字段和 `.Localize(...)`。
- Terrias 自定义界面的固定文案统一维护在 `Terrias/localization.registry.json`，代码只引用稳定 key。
- 自定义 JSON 模型使用 `TerriasLocalizedText` 表示四语文本，不在加载时提前解析为当前语言。
- 运行时生成的卡牌、Buff 和角色数据必须一次写入所有原生语言字段，不能只生成当前客户端语言。

缺失翻译采用确定性回退：目标语言、简体中文、英文、繁体中文、日文，最后才使用旧存档兼容文本或稳定 ID。资源门禁要求文本目录中的每个条目完整提供四种语言，并确保各语言的命名占位符一致。

## 界面刷新

每个 Terrias 自定义 UI 根节点只挂载一个 `TerriasLocalizationScope`。公共文本工厂会把目录中可识别的固定文案绑定到该 scope；包含数字、角色名或状态的动态面板注册自己的刷新函数。

scope 在启用时订阅游戏语言事件，在禁用或销毁时取消订阅。切换语言后保留当前选择的稳定 ID，再刷新展示内容；不会关闭并重新打开窗口，也不会用旧语言名称恢复选择。

## 存档与联机

领域状态和网络协议以稳定 ID 为权威：

- 精灵使用 `SpiritUid`、`EnemyId`、`SpeciesId` 和 `ProfileId`；版本 6 存档额外保存四语展示快照，用于内容缺失时回退。
- 百变与投影保存、同步 `RoleId`，不保存当前语言的角色名作为身份。
- 投影召唤失败同步枚举错误码，接收端通过稳定 localization key 生成本地语言提示。
- 客户端语言不参与同步，也不进入玩法哈希；不同语言客户端可以在同一房间独立展示。

旧协议中的 `DisplayName`、`Description` 字段只作为版本 15 的兼容回退，不得再参与身份判断、排序或权威校验。

## 校验

修改多语言内容后至少执行：

```powershell
dotnet run --project Terrias-Dev.Tests/Terrias-Dev.Tests.csproj -c Release
./tools/Test-TerriasResources.ps1
./tools/Test-TerriasCSharp.ps1
```

涉及动态卡牌、存档或 RPC 时，还需执行对应的 spirit 与 network release gate。
