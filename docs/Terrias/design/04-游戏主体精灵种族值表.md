## 2. 阶级判定

游戏主体只提供 `Rarity = 1/2/3`，因此普通、精英、首领可以直接映射，最终首领必须显式指定。

本表将以下条目设为最终首领：

- `10027` 永夜化身；
- `10048`、`10051`、`10052` 魔王三个形态；
- `10055` 神圣审判机关；
- `10058` 勇者卡洛琳·完全天使。

边界处理：

- `10049`、`10050` 魔王剑是最终首领战中的独立伴随单位，仍按精英计算。

已确认采用“同一物种、不同形态档案”。本表仍保留 55 个数值档案行，但仓库和图鉴通过 `speciesId` 聚合。

## 3. 生成规则

表内字段顺序固定为 `M/S/L/P`：魔力、精神、幸运、感知。

| 本源 | 主要生成依据 |
| --- | --- |
| 魔力 `M` | 原始攻击、攻击型精灵意图占比、行动次数 |
| 精神 `S` | 原始生命、恢复与支援倾向、防守型意图占比 |
| 幸运 `L` | 诅咒、牌库干涉、随机效果、特殊机制与多行动倾向 |
| 感知 `P` | 原始护甲、防御型精灵意图占比 |

原始生命、攻击和护甲先在同阶级内部转为相对排名，避免后期敌人的绝对生命值直接压满精神本源。基础总值与成长总值继续使用已确定的阶梯区间：

| 阶级 | 基础总值范围 | 成长总值范围 |
| --- | ---: | ---: |
| 普通 | 24–32 | 56–72 |
| 精英 | 32–40 | 72–88 |
| 首领 | 40–48 | 88–108 |
| 最终首领 | 48–60 | 108–132 |

同阶级内的总值由身体强度和机制潜力决定，不再让所有同阶级物种强制使用同一个默认总值。每个本源仍满足所在总值的 10%–45% 分配限制。

普通与精英档案继续使用可解释的 `rule-v1` 生成结果。15 个首领与 6 个最终首领档案已逐项核对原始生命、攻击、护甲、行动数、特性脚本、卡池和阶段关系，并统一标记为 `manual-boss-review-v1`。完整判定依据见《[首领与最终首领精灵档案人工复核记录](05-首领与最终首领精灵档案人工复核记录.md)》。

人工复核额外遵循两条规则：

- 原始面板只决定身体基础，特性、状态施加、召唤、牌库干涉和阶段机制可以改变四轴重心。
- 捕获形态永久固定，因此连续阶段可以使用递增总预算；不能只因宿主表中的原始面板相同而把各阶段做成同一数值档案。

## 8. 数据使用边界

CSV 中只有以下字段应进入未来物种配置：

- `profileId`、`enemyId`、`variantId`、`tier`；
- `baseMagic/baseSpirit/baseLuck/basePerception`；
- `growthMagic/growthSpirit/growthLuck/growthPerception`。

`sourceRarity/sourceHp/sourceAttack/sourceArmor/sourceActions` 是生成审计字段，不应成为运行时成长公式的输入。否则游戏主体平衡补丁会在不修改精灵注册表的情况下隐式改变已有物种。

`displayName` 仅用于审阅，不应替代游戏主体本地化查询。`generationMode` 用于标记规则生成和人工复核边界。

CSV 是逐宿主条目的审阅表，因此暂未复制物种分组列。转换为 schema 2 JSON 时，必须按第 2 节映射补充 `speciesId`、`formKey` 与 `formOrder`；不能通过名称相同临时推断。

## 9. 实现状态与后续讨论入口

在进入 schema 2 与雷达图实现前，需要依次确认：

1. **已确认：**多阶段敌人采用同一 `speciesId`、不同 `profileId`。
2. **已确认：**捕获形态永久固定，当前版本不提供形态转换。
3. **已确认：**最终首领采用 `10027`、`10048`、`10051`、`10052`、`10055`、`10058` 六个形态档案。
4. **当前默认：**允许使用完整阶级总值区间，注册表继续强制预算边界。
5. **当前默认：**幸运继续代表特殊机制、诅咒和随机性，并参与生命、攻击、护甲的副权重。
6. **已完成：**15 个首领与 6 个最终首领档案全部完成人工复核。
7. **已完成：**CSV 已由 `tools/Generate-SpiritGrowthRegistry.ps1` 转换为 schema 2 JSON；内容测试保证 55 个正式敌人全部显式存在。

本表既是人工复核基线，也是当前运行时配置的生成源。后续调整应先修改本表并复核，再运行生成工具，避免手工改 JSON 造成审计源与游戏行为分叉。
