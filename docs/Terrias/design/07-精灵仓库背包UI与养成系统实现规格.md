# 精灵仓库、背包与养成 UI 当前规格

> 状态：当前实现规格
> 更新日期：2026-08-18
> 行为权威：[精灵收集、培养与出战系统](../modules/08-精灵球捕获与精灵召唤.md)

## 1. 信息架构

图书馆【精灵仓库】负责默认六槽编队、养成和归元；旅程地图【精灵】负责当前旅程编队与出战选择。两者共用三栏详情结构：列表、动态预览、属性/养成/归元详情。

仓库卡片显示头像、名称、等级、资质、星级和携带状态。九宫格边框、资质底色、按钮反馈、当前选择描边和出战印记使用独立视觉通道。左侧仓库列表的正常卡片使用内层品质色面：基础资质色向白色混合 24%，透明度为 0.72；悬停在当前颜色上提亮 8%，按下时压暗 10%。底部编队槽继续使用基础资质色，归元禁用卡片继续使用独立暗色。

## 2. 虚拟化列表

仓库网格固定三列、单元高度 166。`SpiritVirtualizedGridView` 按 viewport 高度创建可见行加两行 overscan 的复用单元：

- 260 高 viewport 使用 12 个单元；
- 更高窗口通常不超过 21 个；
- 收藏数量只改变 content 高度，不改变活跃单元数量；
- 滚动只更新 `anchoredPosition` 和绑定数据；
- 不在滚动期间重设父级、sibling 或创建/销毁 GameObject；
- viewport 使用 `RectMask2D`；
- 单元通过 `TerriasUiPool` 在窗口开关之间复用。

单元 `ResetForPool` 必须清除 UID、Sprite、描边、出战印记和交互状态。公共对象池回收时会清除按钮监听，因此单元首次创建和每次从对象池取出时都必须幂等地重新绑定点击监听，并在重新激活前完成。

## 3. 增量刷新

- 选择变化只重绑当前可见单元，并刷新预览、详情和操作栏；
- 筛选/排序只重建数据索引并复用现有单元；
- 仓库在当前游戏会话中记住最后一次手动选择；重新打开时依次回退到最后选择、当前出战精灵、排序后的第一只可见精灵；
- 筛选隐藏当前选择时自动选择筛选结果中的第一只精灵，但不覆盖最后一次手动选择记录；
- 编队、归元或收藏变化才重新读取收藏快照；
- 静态列表只加载一帧头像；只有详情对象播放 Idle 动画；
- 本地化切换重新绑定当前可见文本，不重建窗口结构。

关键计数器：`SpiritUi.VirtualGrid.Query`、`Bind`、`CellCreated`。压力测试使用 50、200、1000 只精灵，预热后的滚动和选择不得产生单元 GameObject 创建/销毁。

## 4. 属性与养成

属性页显示四轴雷达图、生命、攻击、护甲、魔能、速度、等级和经验。养成页显示最多 3 个意图槽、1 个被动槽和已学会能力库。

更换能力免费并立即保存，但只从下一场战斗的冻结快照生效。高度专用通用被动只会在成长计划中分配给能够触发它的能力空间。

外部 MOD 精灵显示“外部兼容”被动与完整三意图兼容套装，不向玩家暴露内部 fallback profile 或合成 ID。

## 5. 归元

归元页只在仓库允许选择材料。列表进入材料模式后：目标、可选、已选、异种、锁定和编队禁用状态通过绑定数据更新，不重建整个网格。

确认采用两段式操作。持久化成功前不删除材料；失败时目标、材料和编队均保持原状。

## 6. Hover 与战斗表现

精灵场上不常驻 Buff 图标。Hover Tooltip 显示生命、护盾、实际 Buff、装备被动及其当前进度。客机使用主机下发的只读状态快照，不通过 Tooltip 状态触发任何战斗效果。

## 7. 验收

自动化验证纯布局策略、列表池上限、能力/归元事务和快照上限。Unity 实机仍需检查：

1. 760×620、1080p、2K 和超宽窗口；
2. 1000 只收藏的滚动、筛选、选择和归元模式；
3. 多语言长文本与动态切换；
4. 鼠标、键盘提交、关闭和射线安全；
5. 单机、主机和客机 Hover 的 Buff/被动状态一致性；
6. 左侧正常卡片与仓库底板具有明确区分，同时不削弱资质色、选中描边和归元禁用状态；
7. 连续开关仓库至少十次后，首屏、滚动复用区、筛选结果和归元素材模式中的卡片仍可正确切换选择。
