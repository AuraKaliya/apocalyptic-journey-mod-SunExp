# 精灵仓库、精灵背包 UI 与养成系统实现规格

> 状态：养成与归元首版已实现；自动化门禁通过，待游戏内多分辨率视觉走查  
> 形成日期：2026-08-11  
> 归元修订：2026-08-12  
> 作用域：精灵仓库、旅程编队/携带、属性页、养成页、归元页、速度、意图配置、被动配置、隐藏升级解锁计划、存档与联机同步  
> 关联现状：[06-精灵Schema2成长与仓库界面实现记录](06-精灵Schema2成长与仓库界面实现记录.md)

## 1. 结论摘要

本规格冻结以下产品结论：

1. 精灵仓库保留“仓库列表 / 立绘预览 / 详情”三栏框架；仓库列表固定每行 3 张精灵卡。
2. 精灵卡显示头像、名称、等级、资质和状态；头像水平居中，卡片底色按资质七档显示。
3. 资质底色、选中状态、出战状态是三个相互独立的视觉通道：
   - 资质使用低饱和底色；
   - 选中对象使用高对比描边；
   - 出战对象使用右上角倾斜方印“出战”。
4. 详情页签改为“属性 / 养成 / 归元”；取消成长曲线以及“总值 / 魔力 / 精神 / 幸运 / 感知”曲线切换按钮。
5. 属性页保留四轴雷达图，雷达图为 1:1 正方形；轴标签只显示“魔力 / 精神 / 幸运 / 感知”，不直接携带数字。
6. 雷达图右侧纵向显示“生命 / 攻击 / 护甲 / 魔能 / 速度”。原战斗属性“意图”仅改玩家可见名称为“魔能”，内部仍代表意图能量上限。
7. 每个精灵新增固定个体属性“速度”：捕获时在 80–120 闭区间内按离散均匀分布生成，不随升级成长。
8. 速度只用于同一个 Partner 行动阶段内各 Partner 的出手排序，以及显式声明速度倍率的技能伤害基值。未被 Terrias 明确登记速度的 Partner 统一按 100 处理。
9. 每个种族/形态初始学会游戏主体对应的全部合法 PVE 意图，但同时最多装备 3 个；每个种族初始拥有 1 个固定种族被动，同时只能装备 1 个被动。
10. 更换意图和被动完全免费；配置立即保存，但已开始的战斗继续使用开战快照，新配置从下一场战斗生效。
11. 捕获时一次性生成并永久保存 5 个隐藏升级节点：3 个 Terrias 通用意图、1 个通用被动、1 个“通用意图/通用被动”随机节点。
12. 隐藏节点不在 UI 显示等级、类型或内容；达到对应等级时自动加入已学会能力库，不自动装备。
13. 首版内容规模固定为 15 个通用意图和 12 个通用被动；种族只保留一个捕获时获得的初始固有被动。
14. 现有合法 PVE 固有意图必须同步配置魔能消耗和冷却，不能继续全部为 0 消耗。

## 2. 设计目标与非目标

### 2.1 设计目标

- 玩家能在仓库中快速完成识别、定位、比较资质和判断携带状态。
- 玩家能一眼区分“正在查看谁”和“谁正在出战”。
- 属性页只保留决策所需的当前数据，避免用大面积成长图表制造信息噪声。
- 养成页形成经典的“已学会能力库 → 有限装备槽 → 免费替换”闭环。
- 捕获到的同种精灵因速度与隐藏解锁计划不同而具有个体差异，但所有差异都可持久化、可复现、可联机同步。
- 已开始战斗的配置完全冻结，避免中途修改配置导致服务器与客户端结果分叉。

### 2.2 非目标

- 不调整不同种族的立绘尺寸和预览占比。
- 不提供两只精灵的并排数值对比。
- 不显示未来解锁节点、下一解锁等级或未获得能力剪影。
- 不增加更换能力的货币、材料、冷却时间或次数限制。
- 不让速度参与玩家、敌人或非 Partner 阶段的全局行动排序。
- 不让速度随等级成长；本期也不提供战斗内临时速度增减效果。
- 不改变现有四项起源属性的成长公式、资质公式和雷达上限。

## 3. 名词和状态定义

| 名词 | 定义 |
| --- | --- |
| 详情对象 | 当前被玩家点击、在中间预览和右侧详情中显示的精灵。 |
| 出战对象 | 当前编队中被标记为 Active、下一场战斗允许召唤的精灵。 |
| 携带对象 | 位于 6 个旅程编队槽之一、但不一定处于出战状态的精灵。 |
| 原生意图 | 来自该精灵形态在 `spirit.intent.registry.json` 中的合法 PVE 意图。 |
| 通用意图 | 由 Terrias 提供、可通过隐藏升级节点解锁的意图；首版共 15 个。 |
| 初始被动 | 某个 `speciesId` 固定拥有、捕获时自动学会并装备的种族被动。 |
| 通用被动 | 由 Terrias 提供、可通过隐藏升级节点解锁并免费替换初始被动的被动；首版共 12 个。 |
| 已学会能力 | 已经进入该精灵永久能力库的意图或被动。 |
| 已装备能力 | 战斗快照实际采用的最多 3 个意图和恰好 1 个被动。 |
| 魔能 | 原内部 `MaxMagic / CurrentMagic` 的玩家可见名称；不是“意图数量”。 |
| 速度 | 精灵个体固定值，范围 80–120；用于 Partner 内部排序和显式速度技能。 |

仓库卡片的状态文本只有三种，优先级从上到下：

1. `出战`：UID 等于当前 `ActiveSpiritUid`；
2. `携带`：UID 位于编队槽，但不是出战对象；
3. `仓库`：UID 不在编队槽。

收藏、锁定不是“状态”，继续使用独立小图标表达。

## 4. 信息架构

### 4.1 精灵仓库

```text
┌────────────────────────────── 精灵仓库 ──────────────────────────────┐
│ ┌──── 仓库列表 ────┐ ┌────── 立绘预览 ──────┐ ┌────── 精灵详情 ──────┐ │
│ │ [筛选] [排序]     │ │                      │ │ 名称 Lv.             │ │
│ │ [卡][卡][卡]      │ │                      │ │ 种族阶级 · 资质       │ │
│ │ [卡][卡][卡]      │ │      当前立绘        │ │ [属性] [养成]         │ │
│ │ [卡][卡][卡]      │ │   （尺寸暂不调整）   │ │ 页面内容，可隐形滚动  │ │
│ │      纵向滚动     │ │                      │ │                      │ │
│ └───────────────────┘ └──────────────────────┘ └──────────────────────┘ │
│ 本次旅程编队配置说明                                                   │
│ [槽1][槽2][槽3][槽4][槽5][槽6]                                        │
│ 当前详情对象 / 配置状态                 [设为出战][加入/放回][关闭]      │
└────────────────────────────────────────────────────────────────────────┘
```

三栏框架不变，参考宽度调整为：

| 区域 | 参考占比 | 约束 |
| --- | ---: | --- |
| 仓库列表 | 25% | 最小 276 px，最大 336 px，保证 3 列卡片可读。 |
| 立绘预览 | 30% | 不改变当前精灵立绘的实际缩放策略。 |
| 精灵详情 | 剩余宽度 | 建议不低于 420 px；内容超高时允许隐形纵向滚动。 |

三栏间距统一为 12 px。面板基准分辨率为 1280×720；低于基准时整体缩放，但仓库卡不改成 1 列或 2 列。

### 4.2 精灵背包 / 旅程编队

背包不显示仓库列表，继续采用“立绘预览 / 精灵详情”的双栏主体。底部保留 6 个携带槽和操作栏。点击已占用的携带槽只改变详情对象，不改变出战对象；只有“设为出战”操作会改变 Active。

## 5. 精灵卡片规格

### 5.1 仓库卡片

仓库列表固定 3 列：

```text
┌────────────┐
│   [头像]   │  头像区域水平居中
│  精灵名称  │  单行，超出省略
│ Lv.12 · 76 │  等级 · 资质
│   [携带]   │  状态标签
└────────────┘
```

| 项目 | 规格 |
| --- | --- |
| 列数 | 固定 3 列，不根据数量或分辨率重排。 |
| 列间距 / 行间距 | 8 px / 8 px。 |
| 卡片宽度 | `(列表内容宽度 - 16 px) / 3`。 |
| 卡片高度 | 118 px；可随整体 UI 缩放，不随名称长度增长。 |
| 内边距 | 6 px。 |
| 头像 | 52–60 px 正方形容器，保持原图宽高比，水平居中，不裁切主体。 |
| 名称 | 12 px，中等字重，主文本色，单行省略。 |
| 摘要 | `Lv.{等级} · 资质 {值}`，11–12 px，次文本色。 |
| 状态 | 10–11 px 小标签，文本必须出现，不能只依赖底色。 |
| 收藏/锁定 | 右上或左上 12 px 图标，不与“出战”状态混用。 |

当卡片过窄时，优先缩小头像至 48 px，其次将摘要字号降至 11 px；不得隐藏等级、资质或状态。

### 5.2 资质底色

“白色资质”使用银灰而非纯白，避免破坏深色面板并保持文本对比。所有颜色均为低饱和底色，不直接把名称文字染成资质色。

| 资质 | 等级色名 | 背景色 | Unity RGB（0–1，约值） |
| ---: | --- | --- | --- |
| 0–39 | 灰 | `#34373D` | `(0.204, 0.216, 0.239)` |
| 40–59 | 白/银 | `#474D52` | `(0.278, 0.302, 0.322)` |
| 60–69 | 绿 | `#304B3D` | `(0.188, 0.294, 0.239)` |
| 70–79 | 蓝 | `#324258` | `(0.196, 0.259, 0.345)` |
| 80–89 | 紫 | `#4A3758` | `(0.290, 0.216, 0.345)` |
| 90–99 | 金 | `#5B4D33` | `(0.357, 0.302, 0.200)` |
| 100 | 红 | `#5F3539` | `(0.373, 0.208, 0.224)` |

统一文本色：

- 主文本：`#EBF0F5`；
- 次文本：`#BDC7D1`；
- 金色装饰：沿用面板现有低亮度金色边框，不用于正文。

上述主文本在七种底色上的对比度均大于 7:1，次文本均不低于约 4.8:1。资质数值始终显示，因此即使玩家无法区分颜色，也能获得完整信息。

### 5.3 选中、悬停与出战

资质底色不得被交互状态替换。

| 状态 | 表现 |
| --- | --- |
| 默认 | 资质底色 + 1 px 暗金/同阶浅色边。 |
| 悬停 | 整体亮度提高约 6%，边框亮度提高；不改变布局。 |
| 详情选中 | 2 px 青白色内描边 `#83D7DE`，四角可加短角标；不叠加大面积底色。 |
| 键盘焦点 | 与选中描边同形，但使用虚线或呼吸明暗区分。 |
| 出战 | 右上角叠加旋转约 `-10°` 的方印，文字为“出战”。 |

“出战”方印不套用现有九宫格面板或按钮资源，使用独立绘制的半透明底色、外层高透明描边、内层低透明描边和同色系文字。建议尺寸 46×28 px：深褐金半透明填充、低饱和金色双层边线、浅金文字。印章不得遮挡头像眼睛或名称；在小卡上可越过卡片右上边界 2–4 px。

同一张卡可以同时具有：资质底色、选中描边和出战方印。三者不互相排斥。

### 5.4 旅程编队卡

6 个携带槽继续横向排列。头像在可用区域内水平居中，卡片显示名称和 `Lv.{等级} · 资质 {值}`。空槽只显示“空位”和槽位序号，不使用假头像。

- 出战槽使用“出战”方印，不再仅依靠轻微底色差异。
- 当前详情对象使用选中描边。
- 点击已占用槽：选择详情对象。
- 点击空槽：不修改编队；仓库界面提示通过“加入携带”按钮配置。
- 先在仓库选中对象，再点击“加入携带”：加入编号最小的空槽。
- 编队已满时保留禁用的“队伍已满”按钮，不允许通过槽位点击覆盖或交换精灵。
- 如果后续需要调整槽位顺序，必须提供独立的调整模式，不复用普通槽位点击。

## 6. 详情区通用头部与页签

详情头部从上到下为：

1. `名称  Lv.{等级}`，左对齐；
2. `种族阶级 · 资质 {值}`，左对齐；
3. “属性 / 养成”页签；
4. 当前页内容；
5. 经验条（也可置于页签之上，但两个页签的位置必须一致）。

经验不再使用只有 `0/20` 的孤立文本，而使用 8–10 px 高度的全宽进度条：左侧 `经验`，右侧 `{当前经验}/{下级所需}`。满级时显示“已满级”，填充为 100%。资质不再重复放入经验摘要。

### 6.1 页签状态

移除当前页签文字后的“·”。页签使用同宽分段控件：

- 未选中：透明或 `BandTint` 背景、次文本色；
- 悬停：背景提高约 6% 亮度；
- 选中：较深青靛底、主文本色、底部 2 px 金色指示条；
- 键盘焦点：在控件外增加 1 px 青白焦点框。

页签改变只重建详情内容，不重建立绘和整个面板，避免视觉闪烁。

## 7. 属性页

### 7.1 首屏布局

```text
┌────────── 1:1 雷达图 ──────────┬──────── 战斗属性 ────────┐
│              魔力              │ 生命              36    │
│                                │ 攻击               9    │
│ 幸运      ◇ 当前/潜力      感知 │ 护甲               5    │
│                                │ 魔能               4    │
│              精神              │ 速度              107   │
└────────────────────────────────┴──────────────────────────┘
┌──────────────────── 描述与数据说明，可隐形滚动 ───────────────────┐
└───────────────────────────────────────────────────────────────────┘
```

雷达图保持当前约 218 px 的高度，并把绘图表面压缩为 218×218 px。四轴标签只显示名称，不显示 `当前/潜力` 数字。当前值与满级潜力继续通过两层图形表达；详细数字在悬停提示或下方说明区显示。

右侧 5 行战斗属性等高纵排：

| 标签 | 数据来源 | 说明 |
| --- | --- | --- |
| 生命 | `BattleStats.MaxHp` | 当前等级换算后的最大生命。 |
| 攻击 | `BattleStats.Attack` | 当前等级换算后的攻击。 |
| 护甲 | `BattleStats.Armor` | 当前等级换算后的护甲。 |
| 魔能 | `BattleStats.MaxMagic` | 意图能量上限；内部字段不要求重命名。 |
| 速度 | `SpiritInstance.Speed` | 个体固定值 80–120，不随升级变化。 |

数值使用 16 px 主文本，标签使用 12–13 px 次文本。`魔能`提示为“释放意图所使用的能量上限”；`速度`提示为“决定同一 Partner 阶段内的出手先后，部分技能以速度计算伤害”。

### 7.2 描述文本排版

允许隐形滚动，但内容必须按语义分组，不再以未对齐的连续文本堆叠：

```text
【种族基础】  魔力 6   精神 6   幸运 7   感知 6
【成长预算】  魔力 16  精神 14  幸运 14  感知 8
【满级预估】  当前资质 ...
【说明】      玩家可读的精灵描述
```

每组采用固定标签列和自动换行内容列；数字用等宽数字或右对齐小列。组间距 12 px、行间距 6 px。开发诊断、内部 ID、后备档案说明不得出现在普通玩家文本中。

## 8. 养成页

### 8.1 页面结构

养成页不再展示成长曲线，改为以下顺序：

```text
┌─ 已装备意图（3） ─────────────────────────────────────────┐
│ [槽1：意图] [槽2：意图] [槽3：意图]                       │
└────────────────────────────────────────────────────────────┘
┌─ 已装备被动（1） ─────────────────────────────────────────┐
│ [被动名称]  [类型 / 来源]                                  │
└────────────────────────────────────────────────────────────┘
┌─ 当前查看能力 ─────────────────────────────────────────────┐
│ [能力名称] [类型 / 来源 / 魔能 / 冷却]                      │
│ 完整效果说明                              [替换到目标槽位]   │
└────────────────────────────────────────────────────────────┘
┌─ 已学会能力 ───────────────────────────────────────────────┐
│ [全部][攻击][防御][辅助][恢复][干扰]                        │
│ [单列意图卡：名称 / 元数据 / 一行摘要]……                    │
│ 被动技能                                                    │
│ [单列被动卡：名称 / 来源 / 一行摘要]……                      │
└────────────────────────────────────────────────────────────┘
配置免费 · 已开始的战斗不受影响 · 下一场战斗生效
```

未来节点不出现于页面的任何位置，也不显示“还有 N 个未解锁能力”“Lv.X 解锁”或剪影占位。

已装备槽只承担快速识别和选择槽位，不承载完整效果文本。能力名称使用固定字号，元数据与说明使用次级固定字号；禁止用 Best Fit 为容纳长文本而整体缩小字体。长说明在“当前查看能力”卡中自动换行，已学会能力采用单列列表，超出高度由页面滚动承担。

养成页同时存在两个不同的交互状态：金色描边和“目标”前缀表示本次确认操作会写入的装备槽；青色描边表示详情面板当前查看的能力。三个意图槽和一个被动槽的“目标”状态必须互斥，任意时刻最多只有一个装备目标。能力库中的预览卡可以与目标槽同时显示，但不得使用相同颜色或相同语义的选中样式。

### 8.2 意图卡

意图卡最少显示：

- 意图名称；
- 类型：攻击 / 防御 / 辅助 / 恢复 / 干扰；
- 魔能消耗；
- 冷却；
- 一行玩家可读效果摘要；
- 来源标签：`种族` 或 `通用`；
- 新获得但未确认时的 `NEW` 标记。

不在卡片首屏显示内部 `handlerId`、威胁值、AI 优先级或原敌人卡 ID。完整说明通过悬停/点击详情展示。

### 8.3 被动卡

被动卡最少显示名称、一行效果摘要和来源：

- 初始固定被动：`被动·种族`；
- 升级获得的通用被动：`被动·通用`。

初始被动解锁后永久保留在能力库；解锁新被动不会覆盖、删除或自动替换当前被动。

### 8.4 更换流程

1. 点击一个已装备意图槽，确定当前目标槽位，并在“当前查看能力”卡中查看该能力。
2. 点击空意图槽时保留该槽为目标，详情显示“槽位 N 尚未装备”引导，不得回退显示被动或其他能力。
3. 点击已学会意图只切换预览，不立即更换；确认名称、魔能、冷却和完整说明后，点击明确的“装备到槽位 N”或“替换到槽位 N”按钮。
4. 同一个意图不能重复占用多个槽；已在目标槽位装备时，按钮显示“当前槽位已装备”且不可重复提交。
5. 点击已装备被动会把唯一目标切换为被动槽并清除意图槽目标。点击已学会被动只切换预览，再通过“设为当前被动”按钮确认更换。
6. 预览能力与目标槽类型不一致时只显示“请先选择意图槽位 / 被动槽位”，不得隐式切换目标或提供错误类型的确认按钮。
7. 每次确认更换后立即写入个体存档，并显示轻提示：`配置已更新 · 下一场战斗生效`。
8. 如果战斗正在进行，页脚补充：`本场战斗仍使用开战时配置`。

拖拽可以作为后续增强，但首版必须完整支持“点击预览 → 明确按钮确认”的替换流程和键盘操作，不能把拖拽作为唯一方式。

`NEW` 标记保留到玩家点击该能力卡查看详情为止。养成页签可显示未读数量，但不得由未读数量推断未来节点数量。

## 9. 初始能力规则

### 9.1 初始意图库

捕获时，按精灵的固定 `profileId` 从 `spirit.intent.registry.json` 生成原生意图库：

```text
KnownNativeIntents = Distinct(PveAttackTendency ∪ PveDefenseTendency)
```

明确排除：

- `PvpAttackTendency`、`PvpDefenseTendency`；
- `FallbackAttackTendency`、`FallbackDefenseTendency`；
- 调试、阶段专用、缺少可执行处理器或被标记为不可装备的意图。

初始即学会上述全部合法意图，不通过升级逐个找回。每个 profile 在养成注册表中维护 1–3 个经过人工策划的 `defaultEquippedIntentIds`；不能简单取列表前 3 个。少于 3 个合法意图的外部/后备档案允许留空槽。

### 9.2 初始被动

每个 `speciesId` 必须配置一个 `initialPassiveId`。捕获时自动加入已学会被动并装备。多阶段形态共享 `speciesId` 时共享初始被动；不同 `profileId` 仍可拥有不同初始意图装配。

种族不维护升级替换被动池。升级期间获得的新被动全部来自 Terrias 通用被动池，作为种族初始被动的横向替换项。若未来增加进化或突破，再单独设计“种族进阶被动”，不混入本期五阶段计划。

未知外部 MOD 种族使用显式的安全后备被动，不因缺少 Terrias 内容配置阻止捕获。

## 10. 五阶段隐藏解锁计划

### 10.1 阶段配比

每只精灵捕获时固定生成 5 个节点，采用以下阶段和配比：

| 阶段 | 等级区间 | 能力类型 | 内容来源 |
| --- | --- | --- | --- |
| 1 | Lv.6–10 | 通用意图 | 基础通用意图池（5 个） |
| 2 | Lv.14–18 | 通用意图 | 战术通用意图池（5 个） |
| 3 | Lv.23–28 | 通用被动 | 核心通用被动池（8 个） |
| 4 | Lv.32–38 | 通用意图 | 高级通用意图池（5 个） |
| 5 | Lv.42–47 | 50% 通用意图 / 50% 通用被动 | 未获得通用意图 / 高级通用被动池（4 个） |

因此每个完整计划必然包含 3 个通用意图、1 个通用被动，以及 1 个随机类型节点。种族固有意图和初始固有被动在捕获时获得，不占用五个升级节点。

每个阶段的具体等级在各自闭区间内按离散均匀分布生成。阶段区间不重叠，因此无需额外解决同级节点冲突。

### 10.2 生成算法

生成发生在捕获结算中，并持久化每个节点的精确结果，而不是只保存随机种子：

```text
seed = "spirit-training-plan:v1:" + SpiritUid + ":" + ProfileId

for stage in stageBands:
    unlockLevel = DeterministicUniformInt(stage.minLevel, stage.maxLevel, seed + stage.id + ":level")
    kind = stage.kind
    if kind == Mixed:
        kind = DeterministicUniformChoice([Intent, Passive], 1:1, seed + stage.id + ":kind")
    abilityId = DeterministicSampleWithoutReplacement(availablePool(stage, kind), seed + stage.id + ":ability")
    persist(stageId, unlockLevel, kind, abilityId, unlocked=false)
```

约束：

- 通用意图在同一只精灵的 5 个节点内不重复。
- 通用被动在同一只精灵的节点内不重复。
- 不抽取该精灵已经学会的能力。
- 第 5 阶段先在仍有候选的类型中做 1:1 随机；若抽中的池为空，自动改取另一类型，并记录诊断。
- 固定类型阶段的内容池不足属于发布配置错误，注册表校验必须在进游戏前失败，不得在运行时用重复能力凑数。
- 首版必须恰好提供 15 个通用意图：基础、战术、高级子池各 5 个；三个固定通用意图不能全部属于同一意图类型。
- 首版必须恰好提供 12 个通用被动：核心池 8 个、高级池 4 个；种族初始固有被动不计入这 12 个。

`DeterministicUniformInt` 必须使用无模偏的拒绝采样或等价算法，不能直接用 `hash % range` 冒充严格均匀分布。

### 10.3 解锁行为

- 升级跨过节点等级时自动把指定能力加入已学会库。
- 一次获得多级时按 `unlockLevel`、`stageId` 顺序处理全部跨过节点。
- 自动解锁不自动装备，不改变当前 3+1 配置。
- 升级结果弹出汇总，例如：`使魔猫猫升至 Lv.24，学会被动「……」`。
- 新能力加入 `UnseenAbilityIds`，养成页签出现未读计数，能力卡显示 `NEW`。
- 未来节点不进入普通 UI 查询 DTO；调试日志默认也不输出未来能力名称。

## 11. 速度与 Partner 行动顺序

### 11.1 个体速度

捕获时生成：

```text
Speed = DeterministicUniformInt(80, 120, "spirit-speed:v1:" + operationToken + ":" + SpiritUid)
```

- 结果为整数，80 和 120 均可取到，共 41 个等概率结果。
- 速度写入 `SpiritInstance` 后永久保持，不受等级、资质、意图或被动影响。
- 战斗开始时把速度冻结进战斗部署快照。
- 旧存档迁移使用 `SpiritUid + ProfileId` 生成确定结果，保证同一旧档重复加载不会变化。

### 11.2 排序边界

游戏主体 `FightManager.DOAllAction()` 会先从 `ActionQueue` 建立不可变快照，因此排序必须在该方法建立快照之前完成，并在服务器与所有客户端执行同一策略。

排序只重排 `ActionQueue` 中 `Partner` 项目的子序列，其他位置保持不变：

```text
原队列：Player, Partner-A(90), Partner-B(110), Enemy-1, Enemy-2
新队列：Player, Partner-B(110), Partner-A(90), Enemy-1, Enemy-2
```

比较规则：

1. 速度降序；
2. 速度相同则保持该回合原 Partner 队列顺序；
3. 若无法取得原序号，最后使用稳定 `InstanceId` 的 Ordinal 顺序兜底。

速度解析规则：

- Terrias 精灵 Partner：取冻结战斗快照速度；
- 其他被 Terrias 明确登记速度的 Partner：取登记值；
- 游戏主体 Partner、其他 MOD Partner、未识别 Partner：100；
- 缺失、越界或非法值：100，并记录一次限频诊断。

不得按速度重排 Player 与 Partner、Partner 与 Enemy、不同战斗阶段之间的先后关系。

### 11.3 速度技能

`CompanionIntentEffectSpec` 新增默认值为 0 的 `SpeedScale`：

```text
resolvedValue = FlatValue
              + Attack * AttackScale
              + Armor * ArmorScale
              + MaxMagic * MagicScale
              + Speed * SpeedScale
```

只有 `SpeedScale > 0` 的效果使用速度。不存在全局速度伤害乘区，也不自动修改旧意图。速度 100 是内容设计时的自然基准值。

## 12. 战斗中的意图与被动

### 12.1 意图选择

战斗 AI 的候选集合严格限制为冻结的 `EquippedIntentIds`：

1. 根据现有攻击/防御倾向权重选择本回合倾向。
2. 原生意图沿用 profile 中的攻击/防御归类。
3. 通用意图按类型映射：攻击、干扰 → 攻击倾向；防御、恢复 → 防御倾向；辅助 → 两者。
4. 当前倾向没有候选时，可在其余已装备意图中选择。
5. 过滤魔能不足、冷却未结束、无合法目标的意图。
6. 如果全部已装备意图都不可用，则等待/恢复魔能；绝不偷偷使用未装备意图或 fallback 意图。

注册表缺失某个已装备 ID 时，该 ID视为不可用并产生诊断；不得换成未装备能力。

### 12.2 固有意图的魔能消耗与冷却

当前 54 个被 profile 实际使用的合法 PVE 固有意图必须逐项审核，首版统一使用 0–3 点魔能和 0–2 回合冷却：

| 等级 | 魔能消耗 | 冷却 | 适用能力 |
| --- | ---: | ---: | --- |
| 回能/等待型 | 0 | 1–2 | 主要效果是恢复魔能、等待或极弱的纯准备动作。 |
| 基础 | 1 | 0 | 普通单体伤害、小额护盾、单一轻度增益/减益。 |
| 标准 | 2 | 0–1 | 中等伤害、治疗、双效果、带条件增幅的常规能力。 |
| 强力 | 3 | 1–2 | 多段高伤害、群体效果、强控制、显著恢复或攻防复合能力。 |

定价遵循以下规则：

- 不因为来源是 Boss 就直接提高消耗；按 Partner 适配后的实际效果定价。
- 同一意图包含多个 `effects` 时，按整张意图的总效果定价，不能给每个 effect 分别收费。
- 除明确的回能/等待型能力外，不允许 `cost=0`。
- 高消耗和长冷却不必同时使用；只有明显高于标准强度的能力才同时具备二者。
- 初始默认装配必须至少包含一个当前最大魔能下可立即使用的意图。
- 通用意图使用同一套定价尺度，不获得额外优惠或惩罚。

### 12.3 被动执行

每个战斗精灵只装载冻结的一个 `EquippedPassiveId`。被动定义只引用 Terrias 内已注册的类型化处理器，不允许在 JSON 中嵌入任意 C#、Lua 或反射调用字符串。

首版被动触发面至少支持：

- `OnSummoned`：精灵成功进入战场；
- `BeforePlan`：生成当回合意图计划前；
- `BeforeIntentResolve`：意图效果结算前；
- `AfterIntentResolve`：意图效果结算后；
- `AfterDamageTaken`：受到伤害并完成生命更新后；
- `OnTurnEnd`：该 Partner 行动结束。

服务器负责被动效果的权威执行，客户端只应用权威状态，不重复执行业务效果。每次触发使用 `battleEpoch/statusId/turnIndex/trigger/revision/passiveId` 形成幂等键，避免网络重放导致重复收益。

## 13. 数据注册表

### 13.2 内容与代码的边界

- 被动处理器、意图处理器和允许的触发点写死在 C# 类型化注册表中。
- 能力 ID、文本键、参数、种族池、默认装配和阶段区间由 JSON 维护。
- 不手工维护第二份数值文档。新增生成脚本从运行时 JSON 输出 `docs/Terrias/design/08-精灵养成能力维护表.md`，供策划审计。
- 维护表公开种族固有意图、种族初始固有被动、通用意图池和通用被动池，但不包含任何具体精灵个体的未来节点。

### 13.3 发布校验

注册表加载/构建必须校验：

- stage ID 唯一、区间合法、互不重叠且不超过等级上限；
- 恰好为 3 个固定 Intent、1 个固定 Passive、1 个 Mixed；
- 15 个通用意图 ID 全局唯一，三个子池各 5 个；定义存在、可执行且不属于 PVP/fallback；
- 12 个通用被动 ID 全局唯一，核心池 8 个、高级池 4 个；定义、文本和处理器完整；
- 每个受支持 `speciesId` 恰好一个初始固有被动，且初始固有被动不属于通用被动池；
- 每个受支持 `profileId` 的默认意图均属于该 profile 的合法初始意图库，且不重复、数量 1–3；
- 每个合法 PVE 固有意图都具有已审核的魔能消耗和冷却；除明确的回能/等待型能力外，不允许继续使用默认 `cost=0`；
- 被动 ID 唯一，文本键存在，trigger 和 handler 已注册，参数在合法范围；
- 能力别名无环、目标存在；
- 意图注册表与养成注册表的组合哈希稳定且可参与联机握手。

能力 ID 发布后不可复用。退役能力应保留兼容定义或通过 `abilityAliases` 显式迁移，不能直接删除并让旧存档静默丢失。

## 14. 存档模型与迁移

### 14.1 收藏存档版本

`SpiritCollectionDocument.Version` 从 3 升至 4。`SpiritInstance` 新增：

```text
int Speed
List<string> LearnedIntentIds
List<string> EquippedIntentIds
List<string> LearnedPassiveIds
string EquippedPassiveId
List<SpiritAbilityUnlockNode> AbilityUnlockPlan
List<string> UnseenAbilityIds
int MigrationGrantCount
```

`SpiritAbilityUnlockNode` 至少保存：

```text
string StageId
int UnlockLevel
SpiritAbilityKind Kind
string AbilityId
bool Unlocked
```

保存精确节点是强制要求；未来算法或池内容变化不得改变已经捕获个体的计划。

### 14.2 version 3 → 4

加载旧存档时按以下顺序迁移：

1. 先沿用现有流程归一化 UID、`speciesId/profileId`、等级、经验和资质。
2. 使用 `SpiritUid + ProfileId` 确定性生成 80–120 速度。
3. 生成合法原生意图库和人工配置的默认装备意图。
4. 加入并装备该种族初始被动。
5. 生成并持久化 5 个未来节点。
6. 对所有 `UnlockLevel <= 当前等级` 的节点立即补发能力并标记已解锁。
7. 不在读档阶段逐条弹窗；记录 `MigrationGrantCount`，下次打开养成页时显示一次“已按当前等级补发 N 项能力”的汇总，并保留对应 `NEW` 标记。
8. 完整保存 version 4 文档后才替换内存文档；写入失败时保留原档，不做半迁移。

### 14.3 归一化规则

- 已装备意图必须已学会、存在且不重复，最多 3 个。
- 已装备被动必须已学会且存在；否则恢复到仍有效的初始被动。
- 计划节点能力经过别名迁移后仍缺失时，保留诊断记录，不随机重抽，以免计划在不同版本漂移。
- `Speed` 不在 80–120 时，旧版本存档重新确定性生成；version 4 的损坏值回退 100 并记录诊断，不反复改写随机值。
- 配置写入采用候选文档克隆 → 校验 → 原子保存 → 替换内存状态的既有事务模式。

## 15. 战斗冻结与联机同步

### 15.1 开战快照

`SpiritBattleDeploymentService.Begin` 克隆出战个体时，同时冻结：

- `Speed`；
- 最多 3 个 `EquippedIntentIds`；
- 1 个 `EquippedPassiveId`；
- 组合能力注册表哈希；
- 配置修订号 `LoadoutRevision`。

部署卡/召唤请求只携带上述已装备能力，不携带已学会库、未读标记或未来节点。战斗中打开养成页并修改配置只增加永久存档的修订号，不修改已存在的战斗快照。

### 15.2 网络权威

- 捕获和战斗结算由服务器/主机权威确认；收藏、编队与养成配置属于玩家作用域，只写入对应玩家存档。
- 服务器绑定 RPC 的真实发送者，不能相信 payload 自报的玩家 ID。
- `SpiritCompanionSnapshot` 同步速度、冻结意图、冻结被动、配置修订和组合注册表哈希。
- 召唤前校验协议版本、战斗 epoch、registry hash、owner、token 和配置结构。
- 被动与意图效果只在服务器执行；客户端应用状态快照和表现。
- Partner 排序在每个 peer 的 `DOAllAction` 快照前执行；因速度和稳定 tie-break 已同步，结果必须一致。
- 战斗结束、场景卸载、掉线和重连时清理速度/被动运行态以及幂等键。

新增字段后需要提升精灵 companion 协议版本。网络握手哈希由 `spirit.intent.registry.json + spirit.training.registry.json + 被动处理器版本` 的规范化内容共同生成。

## 17. 玩家操作规则

| 操作 | 结果 | 是否影响当前战斗 |
| --- | --- | --- |
| 点击仓库/携带卡 | 切换详情对象 | 否 |
| 点击已占用编队槽 | 切换详情对象，不改编队 | 否 |
| 点击空编队槽 | 不执行配置；仓库界面显示按钮引导 | 否 |
| 加入携带 | 写入默认编队的第一个空槽 | 已开始战斗不变 |
| 放回仓库 | 从对应编队移除 | 已开始战斗不变 |
| 设为出战 | 更新 Active UID | 已开始战斗不变 |
| 更换意图 | 免费保存 0–3 个不重复意图 | 下一场生效 |
| 更换被动 | 免费保存 1 个已学会被动 | 下一场生效 |
| 升级跨过节点 | 自动学会能力，保留当前装配 | 下一场可配置生效 |

如果把当前出战精灵移出编队，Active 自动清空并要求玩家重新选择；不得静默把另一个携带对象设为出战。关闭面板前允许无出战精灵，但进入下一场战斗时沿用现有“无精灵出战”路径。

## 18. 验收标准

### 18.1 UI

- 仓库在基准分辨率下始终每行 3 张卡，头像水平居中，名称/等级/资质/状态均可见。
- 七个资质边界 `0/39/40/59/60/69/70/79/80/89/90/99/100` 映射正确。
- 资质 100 卡的底色、选中框和出战方印可同时辨认。
- 详情对象与出战对象不是同一只时，玩家无需阅读底部文字即可区分两者。
- 页签没有“·”；当前页签通过背景、文字和下划线共同表达。
- 雷达绘图区宽高一致，四个标签无数字；右侧恰好 5 行战斗属性。
- 界面中原战斗属性“意图”全部改为“魔能”，意图技能/意图槽等能力概念仍称“意图”。
- 经验使用进度条，资质不在经验摘要重复显示。
- 养成页和属性页内容超高时滚动正常，文本列对齐，不出现裁切和互相覆盖。

### 18.2 养成与存档

- 新捕获精灵速度始终在 80–120，确定性测试向量稳定，均匀抽样算法无模偏。
- 新捕获精灵拥有全部合法原生 PVE 意图、1 个初始被动和恰好 5 个持久化隐藏节点。
- 5 个节点满足 3 Intent + 1 Passive + 1 Mixed，等级落在指定区间，能力不重复。
- UI、普通查询 DTO 和默认日志均无法读取未来节点内容。
- 升级跨节点自动学会但不自动装备；多级升级不会漏发或重复发放。
- 配置免费、立即持久化，重新打开面板后保持一致。
- version 3 存档迁移为 version 4 后，重复加载不会改变速度、节点或补发结果。

### 18.3 战斗与联机

- 战斗 AI 只从 3 个已装备意图中选择；全部不可用时等待/恢复魔能。
- 当前战斗中修改配置，不改变已经召唤或尚未召唤的本场部署卡快照。
- Partner 速度排序只改变 Partner 子序列，不改变 Player/Enemy 的相对位置。
- 同速 Partner 保持原顺序；缺少显式速度的 Partner 按 100。
- `SpeedScale=0` 的所有旧意图结算值与改动前一致。
- 服务器和两个客户端在相同队列、速度与 epoch 下得到相同排序、意图和被动结算。
- 重放召唤/被动 RPC 不会重复生成实体、重复触发被动或重复获得收益。

## 22. 归元修订与实施记录

### 22.1 冻结规则

1. 归元值阈值固定为 `1 / 2 / 4 / 8 / 16`，分别对应 1–5 星；有效归元值上限为 16。
2. 每次升星新增的本源点固定为 `2 / 4 / 6 / 8 / 10`，逐星累计预算为 `2 / 6 / 12 / 20 / 30`。
3. 本源点只能分配到魔力、感知、精神、幸运；每项最多 10 点，每点使对应本源 `+1`。
4. 本源可以免费重新分配；档案立即保存，已经开始的战斗继续使用开战快照。
5. 归元材料按 `SpeciesId` 判断同类，允许同种不同形态互相归元；目标自身、锁定精灵、默认编队和当前旅程编队中的精灵不能成为材料。
6. 每只材料贡献 `1 + 材料已有归元值`，因此高星材料保留历史投入；材料在归元事务成功后永久删除。
7. 多选材料允许超过剩余需求，但确认前必须分别显示提供值、生效值和溢出损失；永久删除采用二次确认。
8. 每星为最终生命、攻击、护甲增加 20%，五星共增加 100%；魔能和速度不受星级倍率影响。

### 22.2 UI 契约

- 归元与属性、养成同级；四项本源各使用 10 个固定格子、减号和加号表达分配。
- 仓库材料选择复用左侧三列卡片区：非同类、锁定或在编队中的卡片置灰，可用材料支持批量选择。
- 五枚正五角星使用独立的低饱和金色，不随资质色变化；仓库卡片单独占一行，编队卡片与等级同一行，详情标题位于等级右侧。
- 资质七档同时控制卡片低饱和底色、卡片名称与资质文本、详情名称与资质文本；前景色与背景色分开定义以维持对比度。
- 属性页经验条使用内部纵向布局和上下留白；养成页不再常驻显示免费更换、下一场生效和描边说明文本。

### 22.3 数据、快照与校验

- 精灵档案版本升级为 version 5，新增归元值与四项分配；旧档案归元数据默认归零并在内存中规范化。
- 开战部署快照冻结归元值、星级、四项分配和最终四大本源；协议版本随字段契约升级。
- 远端部署会根据 profile、等级、资质重新计算自然本源，并校验星级阈值、累计点数、单轴 10 点上限和最终本源一致性。
- 归元采用“克隆档案 → 完整校验 → 删除材料并增加目标 → 持久化 → 替换内存档案”的原子事务；持久化失败时目标和材料均不改变。
