# 精灵圣遗物套装效果迭代讨论稿

> 状态：内容讨论稿，未实施。
> 日期：2026-09-18。
> 已讨论方向：保留 12 套与累计两件/四件结构，以四件效果的配装价值为主要迭代对象；倍率、费用和上限尚未定稿。
> 最新约定：计数类内容使用实际 Buff 表示。意图、被动与圣遗物共用该原则，且不得新增额外战斗时点、Hook 或手牌联动。

## 1. 套装要提供什么

两件效果提供简单、容易混搭的收益。四件效果形成专长或取舍，让同一只精灵可以在持续进攻、额外付费爆发、改善循环、保护主人等方向之间选择。

套装按意图能力和本次效果片段判断适用性，不写死某个种族 ID。例如攻击型复合意图含直接治疗时，其治疗片段也可参与海染规则。四件套可以有适用前提，不要求每套对全部精灵同样有效。

种族被动与套装允许复用底层能力，但不把一个种族完整的独有规则直接复制成人人可装的套装。两套两件混搭仍应是稳定、少条件的选择。

## 3. 十二套的候选定位

本表记录讨论方向，不是可直接生成运行时数据的最终规格。新增效果处理器仍须实现，但只在既有规划、执行、提交或等待流程中工作。

| 套装 | 四件效果方向 | 跨行动状态需求 |
| --- | --- | --- |
| 角斗士的终幕礼 | 连续攻击积累凯旋，强化持续进攻；成功使用非攻击意图后清空。 | 实际「凯旋」Buff，沿用候选上限 3 层；等待默认保持，不视为成功执行非攻击意图。 |
| 追忆之注连 | 额外支付精灵魔能，换本次伤害强化与有限即时破盾；不足以追加支付时保留基础行动。 | 无需常驻计数，支付与效果在本次计划内结清。 |
| 黄金剧团 | 长冷却单体意图的一个主要效果，以缩减强度作用于第二个合法目标。 | 优先直接读取本次意图参数；不为“登场”额外造计数。若以后加入周期额度，再用机制 Buff 明确表示。 |
| 逐影猎人 | 当前低生命下强化进攻，并在自己的攻击中获得有限自保盾。 | 读取当前生命即可，不建立新的受伤次数或生命变化历史。 |
| 绝缘之旗印 | 高费意图执行后返还少量实际支付的精灵魔能，返还严格少于支出。 | 本次费用与返还，不必额外积累充能层数。 |
| 饰金之梦 | 按四本源中最低一项补充有限基础效能，鼓励均衡培养。 | 静态属性计算，不需要计数 Buff。 |
| 海染砗磲 | 自己本次意图的实际直接治疗，部分转为同次结算的有限海沫伤害；不统计其他来源与持续治疗跳数。 | 同次结清，不保留当前实现中“下次攻击增伤”的常驻海沫准备态。 |
| 长夜之誓 | 等待或主动回能后，推进一个其他意图的冷却，帮助重新启动。 | 直接推进现有冷却，不把原生冷却复制成 Buff；若以后确定有“累计整备次数”，该内容进度才用 Buff。 |
| 千岩牢固 | 自己执行进攻意图时，按自身最大生命给主人有限护盾。 | 无需新增受击累计，按本次意图结算一次。 |
| 华馆梦醒形骸记 | 攻击可消费部分自身护盾，让护甲参与本次伤害；保留防护与主动进攻之间有成本。 | 使用现有护盾与护甲，不再建一份同义的甲胄层数。 |
| 深林的记忆 | 自己消耗毒素、灼烧等允许消费的负面后，返还少量层数作为种子，严格少于本次实际消耗。 | 本次消耗与返还即可。两件加层需要排除控制与机制计数，不能统一给所有负面加一层。 |
| 翠绿之影 | 自己先支援/干扰、后攻击时，将主目标一种允许传播的普通负面少量复制给另一敌人。 | 一层「风引」准备 Buff；本次传播成功后消费，不按每段攻击重复传播。 |

深林需要与此前讨论的状态消费类意图配套。黄金与翠绿应区分“扩大本次主要效果”与“传播已有普通负面”；追忆与绝缘区分额外付费爆发与高费续航；千岩与华馆区分保护主人与经营自身防护。

海染、黄金、华馆适合作为第一批细化对象，分别检验效果转换、目标范围变化和资源取舍的可读性。

## 4. 计数 Buff 的表达方式

将内容层的可累积、可消费状态直接做成 Buff。对具体种族同样适用，不必为每一套设计一个计数。

| 状态示例 | 表达 | 增减与消费 |
| --- | --- | --- |
| 凯旋 | 0 至 3 层 Buff | 自己成功执行攻击后加层，非攻击意图成功执行后移除；预览只读。 |
| 风引／牵线 | 1 层准备 Buff | 准备动作实际完成后获得；对应传播或协击在自己的意图内兑现后移除。 |
| 礼物包装 | 有限层数进度 Buff | 成功执行规定动作后加层；达到阈值后进入待开盒状态，开盒后留下已完成状态避免重复领取。 |
| 铭记 | 有限层数资源 Buff | 本次主动效果成功获得后加层，主动净化或治疗实际使用后扣层。 |
| 魂壳 | 有限层数额度 Buff | 在自己的支援行动中消费；用尽后保持明确已用尽事实，不因 Buff 归零重新初始化。 |

Buff 是状态载体，现有意图流程是规则的执行者。纯计数 Buff 的 Apply/Clear 不注册监听；默认关闭自动按回合、受击、使用衰减，避免重复扣层。上限、零层移除、初始化、消费条件和战斗结束清理需要逐项确定。

机制计数默认不受普通增益加层、净化、驱散、复制、偷取和转移影响。若将来明确设计某种计数可被干预，应在该状态自己的规则里声明；不能让深林加层、镜像复制等通用处理意外修改套装进度。

只让实际 Buff 层数作为主机上的计数权威，不同时维护相同的 `PassiveState` 数值。客机展示、网络快照与返卡可以保存其只读结果，它们不是第二个可独立写入的计数源。目标 ID、上一意图片段等结构数据保留必要的有界记录，不编码到层数里。

## 5. 当前实现与后续落地的区别

当前凯旋、变奏、追猎、海沫、长誓等主要通过 `CompanionBattleState.PassiveState` 存放数值，再合成为 `ArtifactSet` 可见状态。本次约定是后续改为实际 Buff，尚未发生代码或注册表迁移。

实施时需要一起处理：

1. 对应计数的旧读写与重复展示退场，效果、说明和界面统一读取 Buff。
2. 为计数 Buff 提供 Data/Text、图标、层数上限和机制分类；使用明确的现有 Buff 操作入口增减或移除，不能假设只支持正数的添加接口可以直接拿负数消费。
3. 主机更新真实状态，客机只读展示；换下、返卡、再召唤与新战斗分别验证保留和清理，不凭 Buff 被销毁或重建重发收益。
4. 当前 `VisibleStatuses` 有 24 项上限且被用于返卡恢复。应验证机制状态与原有状态的完整保留，不让显示裁剪静默变成战斗计数丢失，也不为了本次讨论先行改网络协议。
5. 同次意图内尽量合并状态修改与既有同步，不逐层制造独立刷新或广播；不再重复生成同一计数的 `ArtifactSet`/`Mechanic` 伪状态条目。

改为 Buff 的收益是状态可见、控制路径统一，不能据此宣称零成本或已经完成性能优化。计数更新、预览幂等、临时效果消费和多人恢复需要后续实际验证。
