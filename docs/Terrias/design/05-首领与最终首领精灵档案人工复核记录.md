## 1. 复核方法

本轮不是对规则生成结果做目视确认，而是逐档案核对以下事实：

1. `Enemy` 表中的生命、攻击、护甲、行动数和卡池。
2. `Buff` 表中的初始特性、事件触发、复活、减伤、召唤和阶段转换脚本。
3. `EnemyCard` 表中的伤害、防御、异常状态、诅咒、牌库干涉和队伍支援行为。
4. `Level` 表中的实际遭遇组合与阶段顺序。
5. 已确认的“同一物种、不同形态档案”和“捕获形态永久固定”规则。

四轴仍按 `M/S/L/P` 排列：魔力、精神、幸运、感知。原始面板提供身体基线，机制身份决定轴向修正；本源不是敌方生命、攻击、护甲的线性抄写。

## 4. 阶段连续性

固定形态档案必须让阶段差异在仓库、雷达图和战斗派生值中可见。本轮采用以下连续预算：

| 物种 | 形态序列 | 基础总值 | 成长总值 |
| --- | --- | --- | --- |
| 永夜化身 | 派生形态 → 最终形态 | 40 → 54 | 90 → 126 |
| 魔王 | 第一 → 第二 → 第三形态 | 52 → 55 → 58 | 116 → 122 → 128 |
| 卡洛琳 | 第一 → 第二 → 完全天使 | 44 → 46 → 58 | 94 → 101 → 130 |

阶段递增只作用于对应的固定 `profileId`。当前版本不允许低阶段个体转换形态，因此不存在通过无成本切换档案获得最终首领预算的问题。

## 5. 复核结果

- 21/21 个目标档案已标记为 `manual-boss-review-v1`。
- 15 个首领档案均位于基础 40–48、成长 88–108 区间。
- 6 个最终首领档案均位于基础 48–60、成长 108–132 区间。
- 每个档案的基础与成长四轴均满足单轴占比 10%–45%。
- 永夜、魔王和卡洛琳的阶段总预算严格递增。
- `sourceRarity/sourceHp/sourceAttack/sourceArmor/sourceActions` 继续与游戏主体导出表一致。

本轮修改的是未来 schema 2 的设计输入，不会立即改变当前游戏行为。下一阶段将把 55 个正式敌人档案转换为运行时配置，并由注册表校验器强制检查显式命中、形态身份、预算范围和雷达尺度。
