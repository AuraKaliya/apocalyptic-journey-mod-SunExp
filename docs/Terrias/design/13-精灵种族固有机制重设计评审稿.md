# 精灵种族固有机制重设计评审稿

> 状态：**评审初稿，尚未进入代码**  
> 建立日期：2026-08-12  
> 评审对象：51 个 `speciesId`、58 个 `profileId` 的种族固有被动与固有意图  
> 数值状态：本文中的魔能、冷却、百分比和次数均为第一轮建议，用于确认机制方向，不代表最终平衡值。

## 1. 为什么需要重设计

当前精灵固有能力完成了“敌人卡牌可以被友方 AI 使用”的第一阶段目标，但没有完整保留“这个敌人为什么让玩家记住”的身份：

1. 51 个种族固有被动全部由生成器套用 `type-resonance` 模板，只在攻击、防御或干扰类型上不同；
2. 大量形态共享“断脊”“魔力屏障”，默认套组之间差异有限；
3. 游戏主体敌人的 `InitScript`、`AttributeText`、形态规则和部分特殊敌人卡没有进入精灵养成映射；
4. 已映射技能也可能只保留名字和基础效果。例如敌人版“浴火”会根据灼烧强化护盾，当前精灵版只剩固定护盾公式；
5. 55 个游戏主体养成形态中，至少 40 个有显式 `AttributeText` 特性，至少 14 个有原始卡牌没有进入精灵 PVE 映射。

本轮目标不是把敌人脚本原封不动搬给友方，而是保留其战斗幻想、决策节奏和风险收益关系。

## 2. 设计目标

### 2.1 种族区分契约

重设计完成后必须满足：

1. 每个 `speciesId` 有一个独立的固有被动机制，不再使用统一的类型数值模板；
2. 每个 `profileId` 至少有一个专属标志意图，并进入默认装备；
3. 多形态种族共享核心被动身份，但各形态通过参数和标志意图区分；
4. 共享基础意图可以继续保留在已学会库，但不计入“种族区分性”；
5. 任意两个非同族形态不得拥有完全相同的“默认意图集合 + 被动机制签名”；
6. 同族系列可以共享机制关键词，但必须具有不同的触发方式或收益方向；
7. 通用意图继续负责补齐治疗、防御、群体等职能，固有套组不再为了功能齐全而强塞“魔力屏障”。

### 2.2 复杂度预算

| 稀有度 | 建议机制复杂度 |
| --- | --- |
| Normal | 1 个计数器或条件，被动与标志意图形成一个清楚循环 |
| Elite | 1–2 个状态，可包含主人联动、反应或一次性转折 |
| Boss | 可包含衍生物、双阶段、资源转换或濒死效果 |
| FinalBoss | 可包含有限形态变化、复活或三状态循环，但仍受每场次数限制 |

复杂度不等于单纯提高强度。高稀有度精灵可以拥有更丰富的机制，但不能绕过魔能、冷却和行动次数。

## 3. 敌人机制的友方转译规则

| 敌人侧机制 | 精灵侧处理 |
| --- | --- |
| 伤害、护盾、治疗、常规 Buff | 直接使用友方目标和统一数值公式适配 |
| 针对“魔女”的触发 | 改为精灵主人；联机时由主机读取该玩家的权威牌局 |
| 针对敌方队友死亡 | 改为友方战斗单位、精灵衍生物死亡，必要时增加主人低血量兜底条件 |
| 召唤敌人 | 转成精灵所属的有限衍生物，不调用 `AddEnemy`，不占四人角色上限 |
| 自爆、自然死亡 | 转成战斗内牺牲或退场，不删除仓库个体，不触发捕获丢失 |
| 复活、形态切换 | 转成每场有限次数的“濒死拦截 + 形态状态”，由主机权威结算 |
| 偷金币、逃跑 | 转成有上限的战后战利品或战斗内资源；是否允许永久金币收益需单独批准 |
| 塞诅咒、翻牌、弃牌 | 优先转成敌方减益、假牌标记或精灵自身资源，不直接破坏主人的牌组 |
| 即死、直接胜利 | 不原样保留，转成有上限的处决伤害或强减益 |
| 无效果的蓄力卡 | 转成可见的蓄力状态，强化下一次指定意图，而不是继续空过行动 |

禁止直接复用敌人的原始 `UseScript`。这些脚本普遍假设敌方席位、单机 `PlayerInfo`、敌人目标和宿主随机源，无法满足友方目标、伤害归属、联机权威和养成存档要求。

## 4. 建议新增的通用运行时原语

本文 51 个种族不应对应 51 套互不相干的脚本。建议先建设以下可组合原语：

| 原语 | 用途 |
| --- | --- |
| `species.counter` | 倒计时、受击次数、主人出牌数、仪式进度、怒气等有限计数 |
| `species.stance` | 奇偶模式、凤凰模式、命运时刻、形态阶段 |
| `derived.token` | 壮壮、双生影、猫群、操偶人偶、魔剑残影等有上限的衍生物 |
| `intent.charge` | 蓄力并强化指定的下一次意图 |
| `intent.sacrifice` | 主动牺牲精灵并提交伤害、治疗或 Buff，随后安全退场 |
| `life.lethal-guard` | 每场有限次数的濒死拦截、复活、换形态 |
| `owner.card-event` | 主人打出攻击/技能牌、累计出牌、回合末手牌奇偶 |
| `combat.damage-event` | 按来源、伤害类型、单次/累计伤害触发物种机制 |
| `buff.safe-copy` | 只复制白名单正面状态，限制层数和不可复制标签 |
| `buff.dispel-one` | 移除一个合法正面或负面状态，不调用无边界全清除 |
| `reward.battle-loot` | 主机记录有上限的本场战利品，胜利时再提交给对应玩家 |
| `form.transition` | 只同步形态键、剩余次数和视觉，不替换整个角色对象 |

所有原语都需要：主机权威、稳定 revision、明确伤害来源、可序列化状态、AI 可用性判断和可回放的表现事件。

## 6. 共享基础意图的处理

当前“断脊”“魔力屏障”等意图由多个形态共享。重设计不要求立即删除这些能力，而是重新定义其地位：

| 类型 | 处理策略 |
| --- | --- |
| 完全通用的攻击/防御 | 可以留在捕获时已学会库，但不作为种族标志，不优先进入默认装备 |
| 名称独特但效果被扁平化 | 恢复其关键条件或资源关系，例如“浴火”重新读取自身灼烧 |
| 敌方卡牌直接破坏玩家牌组 | 不进入 PVE 友方池，改成种族标记、敌方减益或主人安全联动 |
| 空效果蓄力 | 改成 `intent.charge`，不能继续消耗行动却没有状态结果 |
| 同名但多形态语义不同 | 建立形态专属意图 ID，避免修改共享 ID 后影响其他种族 |

建议新的标志意图 ID 使用：

```text
spirit.inherent.<species-key>.<intent-key>.intent
spirit.inherent.<species-key>.<form-key>.<intent-key>.intent
```

旧的 `spirit.pve.enemycard_*.intent` 继续承载忠实映射的基础敌人卡。只有出现种族机制或形态参数时才建立新的专属 ID。

## 7. AI 设计边界

种族内容定义“能选择什么”，共享选择器决定“当前怎么选择”。每个新意图必须声明：

- `EligibilityPolicy`：例如壮壮未满、存在欲念、处于进攻拍、倒计时仍存在；
- `PriorityBonus`：例如目标低血、主人受伤、当前状态即将浪费、能够击败目标；
- 目标策略：主人、生命最低友方、最近伤害来源、负面状态最多敌人等；
- 自损、自爆、变形和衍生物的预期收益，避免 AI 只看直接伤害；
- 无合法意图时允许等待和回能，不能通过绕过魔能强制执行标志意图。

不得为每个种族写一套独立的完整 AI。特殊选择条件应注册为可复用策略，例如：

| 策略 | 使用种族 |
| --- | --- |
| `derived.count-below-cap` | 普拉提之王、使魔猫猫、操偶师 |
| `counter.at-least` | 欲念魔女、K、三个残片、灾厄祭司 |
| `owner.hand-parity` | 方片舞者 |
| `owner.last-card-type` | 失心魔女、自动机关人偶 |
| `target.debuff-type-count` | 最后一餐、恶意聚合体、K |
| `stance.current` | 腐化主教、熔火圣骸、审判机关 |
| `sacrifice.expected-value` | 惊喜礼物盒 |

## 8. 联机与状态同步

### 8.1 权威原则

1. 所有种族机制状态由主机创建和递增；
2. 客机不能根据动画、手牌或本地事件自行触发被动；
3. 主人牌局相关机制由主机读取该玩家的 RoleTable，只同步判定结果；
4. 随机结果使用稳定种子，主机提交结果后客户端只播放；
5. 伤害、护盾、治疗和 Buff 继续通过 `CompanionEffectCommitService` 提交，保留精灵伤害归属和 DPS 记录。

### 8.2 建议同步的紧凑状态

```text
mechanicId
mechanicRevision
counterValues
stanceKey
derivedTokenCounts / durability
remainingLethalGuards
formState
armedFlags
```

不传输原始脚本、完整 Buff 列表、主人手牌内容或衍生物的独立牌局。虚拟衍生物作为所属精灵效果的一部分结算，可显著降低每回合消息数和对象分配。

## 9. 既有精灵存档迁移

### 9.1 被动

当前 51 个种族被动已经各有稳定 ID。正式实施时优先保留这些 ID，替换 `effectKind` 和参数，因此：

- 已捕获精灵不需要更换 `EquippedPassiveId`；
- 旧的 `type-resonance` 效果会在新版本直接升级为种族机制；
- 协议哈希和被动处理器版本仍必须提升，防止新旧客户端联机。

### 9.2 意图

当前 `LearnedIntentIds` 没有记录“固有/成长/特殊授予”的来源。`Normalize` 只会把新固有意图并入，不会移除已经离开形态池的旧意图。若直接更新注册表，旧精灵会永久保留旧固有能力。

建议增加：

```text
InherentIntentPlanVersion
ResolvedInherentIntentIds
LearnedAbilitySources（后续版本）
```

首轮迁移规则：

1. 重新计算当前 `profileId` 应有的固有意图；
2. 移除旧版本记录的固有意图，但绝不移除 `spirit.common.*` 成长意图；
3. 加入新专属固有意图；
4. 仍然合法的装备保持原槽位；
5. 已移除的装备按新默认意图补齐；
6. 增加 `LoadoutRevision` 并重新生成哈希；
7. 在 UI 中把新增专属能力标记为“种族机制更新”，而不是普通升级新技能。

## 11. 自动化验收建议

### 11.1 静态内容门禁

1. 51 个 `speciesId` 都有非模板固有被动；
2. 58 个 `profileId` 都至少有一个 `spirit.inherent.*` 标志意图；
3. 每个形态默认装备至少包含一个标志意图；
4. 没有两个非同族形态拥有相同默认集合和被动机制签名；
5. 原始敌人每个特性和特殊卡都标注为“保留、转译、拒绝”之一，拒绝项必须有理由；
6. 所有被动触发条件在该精灵的固有/通用成长空间中可达；
7. 所有衍生物、复活、奖励和随机次数都有硬上限。

### 11.2 运行时测试

1. 每种事件只由主机提交一次；
2. 自爆、反击、跟随攻击、延迟治疗都有正确的精灵来源归属；
3. 主动换下、死亡、战斗结束、断线重连会清理计数器和虚拟衍生物；
4. 客机不会因为缺少主人手牌内容而得到不同的意图计划；
5. 复活与变形不会重复注册事件监听器；
6. 旧存档升级后没有遗留的非法固有意图；
7. 自动战斗 1000 回合内不存在无限等待、无限召唤、无限回复或零成本循环。

## 12. 本轮需要审阅的关键决策

| 决策 | 本稿建议 | 可选方向 | 状态 |
| --- | --- | --- | --- |
| 普拉提壮壮等召唤物形态 | 虚拟衍生物，不占角色位、不独立完整行动 | 真实可受击子单位，开发和同步成本显著更高 | 待审 |
| 鼹鼠/吞金兽是否产出永久金币 | 胜利后有硬上限地给予所属玩家 | 全部改为本场魔能、抽牌或数值收益 | 待审 |

| 多形态种族的固有被动 | 同一稳定 ID，按 `profileId` 使用参数/组件 | 每形态独立被动 ID，迁移和 UI 更复杂 | 待审 |
| 主人牌局联动 | 允许主机读取手牌数量、最后牌型、累计出牌数 | 完全取消牌局联动，身份保真度降低 | 待审 |

| 首领持久机制 | 精灵版只保留战斗内语义 | 继续修改保存名字等模式数据，跨模式风险高 | 待审 |

## 13. 本稿的推荐结论

1. 认可“种族身份优先于基础职能齐全”，不再要求每个固有池都自带普通攻击和魔力屏障；
2. 认可“每种族独立被动 + 每形态至少一个标志意图”的最低标准；
3. 认可敌人机制只做语义转译，不复用敌方原始脚本；
4. 首轮以虚拟衍生物为准，避免新建第二套 Partner/位置/回合系统；
5. 先评审机制和身份，再进行数值模拟，不在本稿阶段锁死具体倍率；
6. 评审通过后先完成五个代表性种族的纵向原型，再决定是否批量进入其余 46 个种族。
