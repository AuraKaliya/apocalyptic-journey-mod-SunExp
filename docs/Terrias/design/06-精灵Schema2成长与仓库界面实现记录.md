# 精灵 Schema 2 成长与仓库界面实现记录

> 实现日期：2026-08-10  
> 作用域：物种/形态身份、55 个游戏主体档案、成长查询、雷达图、成长曲线和仓库管理

## 1. 本轮完成范围

- `spirit.growth.registry.json` 升级为 schema 2，并保留 schema 1 内存迁移。
- 以人工复核 CSV 为生成源，导入 55 个游戏主体形态档案和 3 个 Terrias 档案。
- 捕获个体永久保存 `speciesId/profileId`；收藏存档版本升为 3。
- 多阶段敌人共享 `speciesId`、分别保存固定 `profileId`，不提供形态转换。
- 等级、资质抽取、资质修正、经验、战斗换算和雷达尺度均改为有类型配置引用。
- `SpiritGrowthQueryService` 统一生成当前属性、满级潜力、战斗值、雷达轴和三套 1–50 级曲线。
- 冒险背包与精灵仓库加入属性/成长页签、四轴雷达和成长曲线。
- 仓库加入全部/携带/仓库筛选，等级/资质/阶级/捕获时间排序，收藏、锁定、加入携带与移出携带。
- 意图注册表加入相同 `profileId`，Partner 战斗阶段按冻结形态解析意图与成长档案。

## 2. 数据生成链

```text
04-游戏主体精灵种族值表.csv
  -> tools/Generate-SpiritGrowthRegistry.ps1
  -> Terrias/spirit.growth.registry.json
  -> SpiritGrowthRegistry
  -> SpiritGrowthService / SpiritGrowthQueryService
  -> 战斗部署 / 精灵管理界面
```

CSV 是游戏主体数值的审计源，JSON 是运行时发布物。修改游戏主体种族值时应重新运行生成工具，不直接维护两份数值。

## 3. 存档迁移

`SpiritCollectionDocument.Version` 从 2 升至 3。加载旧个体时：

1. 保留 UID、等级、经验、资质、捕获时间、收藏和锁定状态。
2. 使用原捕获快照解析当前显式档案。
3. 写入稳定 `speciesId/profileId`。
4. 按档案的等级上限、经验曲线和资质范围归一化旧值。
5. 配置收藏服务时立即保存迁移结果。

旧卡牌迁移规则不变：等级 1、经验 0、资质 60；本轮同时为其补齐固定身份。

## 4. 本轮采用的默认方案

以下细节在此前讨论中没有单独锁定，本轮按保守默认实现，后续可继续调整：

| 项目 | 当前默认 |
| --- | --- |
| 运行时来源 id | 游戏主体统一为 `base-game`，Terrias 为 `terrias` |
| 单形态身份 | `speciesId` 与 `profileId` 相同 |
| 多形态身份 | 共享语义化 `speciesId`，每个宿主条目使用 `base-game.{enemyId}` 作为固定 `profileId` |
| 雷达尺度 | 四轴均使用全局绝对 cap 80，不随当前仓库动态缩放 |
| 雷达默认图层 | 当前等级值 + 当前资质下的满级潜力 |
| 成长曲线 | 同图显示当前资质、标准资质 60、理论资质 100 |
| 曲线纵轴 | 总值、魔力、精神、幸运、感知；战斗值与累计经验暂不提供切换 |
| 排序 | 收藏个体在四种排序中均优先，其后应用所选主排序 |
| 捕获时间排序 | 使用 UTC ISO-8601 字符串倒序 |
| 外部 MOD 敌人 | 生成确定性稳定身份和后备种族值，不阻断捕获 |
| 配置失效 | 整体回退到有类型默认曲线和确定性后备档案，同时记录诊断 |
| 最终首领经验 | 与既有方案一致，仍按首领档 80 结算 |
| 删除与放生 | 本轮不提供；锁定仅作为保护/筛选基础，不改变战斗规则 |

## 5. 校验边界

加载器会拒绝重复身份、重复匹配、未知曲线引用、非法曲线类型、越界阶级预算、10%–45% 单轴占比违规、雷达轴缺失或 cap 低于理论上限。

`tools/Test-SpiritCapture.ps1` 额外检查 55 个游戏主体档案、五组多形态物种、意图/成长身份对齐和 cap 80。`Terrias-Dev.SpiritTests` 检查 version 2 到 version 3 迁移、确定性后备身份、查询快照、收藏/锁定持久化与战斗部署身份冻结。

## 6. 后续讨论项

- 是否为生命、攻击、护甲和累计经验增加成长曲线纵轴。
- 是否增加两个个体并排对比，以及同物种筛选入口。
- 锁定状态是否应阻止未来的放生、融合或批量操作。
- 收藏优先是否应成为独立开关，而不是所有排序的固定前置规则。
- 大规模收藏后是否按 `registryHash + profileId + aptitude` 缓存曲线。
- 是否为外部 MOD 提供独立的成长注册表扩展协议，而不只使用确定性后备档案。
