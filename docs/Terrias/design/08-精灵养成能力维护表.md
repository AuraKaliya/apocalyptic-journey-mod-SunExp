## 1. 首版能力池结构

首版能力池固定为：

- 15 个通用意图：基础、战术、高级各 5 个；
- 12 个通用被动：核心 8 个、高级 4 个；
- 每个 `speciesId` 一个捕获时获得并默认装备的种族固有被动；
- 每个 `profileId` 捕获时学会全部合法 PVE 固有意图，并人工配置默认 1–3 个。

五阶段隐藏计划从通用池抽取：

| 阶段 | 等级区间 | 抽取内容 |
| --- | --- | --- |
| 1 | Lv.6–10 | 基础通用意图 1 个 |
| 2 | Lv.14–18 | 战术通用意图 1 个 |
| 3 | Lv.23–28 | 核心通用被动 1 个 |
| 4 | Lv.32–38 | 高级通用意图 1 个 |
| 5 | Lv.42–47 | 50% 未获得通用意图 / 50% 高级通用被动 |

## 2. 通用意图设计尺度

### 2.1 参考个体

首轮纸面估值使用接近当前 Lv.1 普通精灵的参考属性：

```text
攻击 9 / 护甲 5 / 最大魔能 4 / 速度 100
```

实际平衡必须再使用 Normal、Elite、Boss、FinalBoss 四档的 Lv.1、Lv.25、Lv.50 快照进行模拟。通用能力使用成长后的战斗属性计算，不使用种族原始四轴直接结算。

### 2.2 统一数值公式

```text
直接数值 = Round(
    FlatValue
    + Attack × AttackScale
    + Armor × ArmorScale
    + MaxMagic × MagicScale
    + Speed × SpeedScale)
```

- 伤害、护盾和治疗最小为 1；
- 中间步骤不取整，只在最终值取整；
- 速度倍率只出现在明确标记的速度能力中；
- 群体效果表内公式为“每个合法目标”的数值；
- 状态层数、命中次数不接受上述倍率；
- 强化下一次意图时只修改伤害、护盾、治疗和主动回能数值，不修改状态层数、目标数、命中数或冷却。

### 2.3 魔能节奏

精灵每次完成行动后恢复 1 点魔能；无法释放意图而等待时同样恢复 1 点。因此：

| 消耗 | 预期节奏 |
| ---: | --- |
| 0 | 只用于主动回能或纯准备动作。 |
| 1 | 可持续使用，不消耗长期净魔能。 |
| 2 | 每次使用净消耗 1，需要与低消耗意图交替。 |
| 3 | 爆发能力，使用后通常需要回能或等待。 |

通用意图和固有意图使用同一尺度，不因“后天解锁”获得数值优惠。

| 高级 | 1 | 1 | 1 | 1 | 1 | 5 |

隐藏计划生成时额外校验：

- 阶段1、2、4各自只能从对应子池抽取；
- 三个固定通用意图不能全部为同一类型；
- 阶段5若抽中意图，从三个子池尚未获得的意图中等概率抽取；
- 同一精灵不能重复学会相同通用意图；
- 所有 ID、表现卡、文本和处理器必须存在后才允许注册表通过发布校验。

## 7. AI 使用规则

除现有类型优先级外，通用意图增加以下确定性可用性和动态优先级：

| 意图 | 规则 |
| --- | --- |
| 集中咏唱 | 已有专注咏唱或余能转化时不可选。 |
| 虚弱咒痕 | 目标已有虚弱时降低优先级，不强制禁用。 |
| 援护结界 | 目标护盾越低、生命比例越低，优先级越高。 |
| 生命涓流 | 无受伤目标不可选；目标已有延迟治疗时降低优先级。 |
| 魔能回流 | 缺少至少2点魔能时才可选；缺失魔能越多优先级越高。 |
| 破甲标记 | 目标易伤层数越低，优先级越高。 |
| 群星护幕 | 存活友方越多、总缺失护盾越高，优先级越高。 |
| 生命回响 | 至少2名友方受伤，或有人生命不高于25%时才可选。 |
| 余能转化 | 满魔能且没有专注/余能状态时才可选。 |
| 封锁刻印 | 存活敌人越多，优先级越高；单目标时降低优先级。 |

AI 随机权重只能在“已经满足可用条件”的意图之间工作，不能用低优先级代替不可用校验。

| 速度倍率 | `CompanionIntentDefinition` 和 effect 增加 `SpeedScale`，纳入统一数值公式。 |
| 群体治疗 | 将当前治疗处理器泛化为 single/all，或新增 `heal.all`。 |
| 主动回能 | 新增 `magic.recover`，只修改权威 `CompanionStats.CurrentMagic` 并同步。 |
| 友方护盾目标 | 新增 `friendly.lowest_block_then_hp`，按护盾、生命比例、稳定ID排序。 |
| 条件可用性 | 增加类型化 eligibility policy，首版支持魔能缺口、满魔能、受伤友方数量。 |
| 意图数值增幅 | 在权威计划解析时应用并消费“下一次意图增幅”，客户端不重复计算。 |
| 延迟治疗 | 服务器权威监听目标下一次行动结束；以状态实例和战斗 epoch 幂等。 |

不为15张意图各写独立处理器。新增能力必须是可被固有意图或后续被动复用的通用原语。

## 9. 首轮平衡验收

在内容进入运行时注册表前，至少验证：

1. 参考个体在满魔能下可以释放任意一张通用意图。
2. 1费意图连续使用时魔能不下降；2费和3费意图符合预期回能节奏。
3. 单目标环境中，群星护幕、生命回响、封锁刻印不压过对应单体能力。
4. 三个通用攻击意图的同属性伤害依次体现“稳定 / 复合 / 爆发”，但不超过高强度种族固有攻击的专项上限。
5. 速度80和120的迅捷穿刺相差约3点，不让速度完全主导伤害。
6. 专注咏唱和余能转化不能叠加造成乘算爆发；若同时因迁移异常存在，只采用较高增幅并按稳定顺序消费。
7. 回能、治疗、状态和群体效果均由服务器执行一次，客户端只应用同步快照。
8. AI不会在满魔能时使用魔能回流、无伤员时使用治疗、已有准备状态时重复准备。

## 10. 通用被动统一规则

### 10.1 功能边界

通用被动是种族固有被动的横向替换项，不是升级后必然更强的上位版本：

- 不直接增加速度；“迅捷演算”只强化能力公式里的速度贡献；
- 不永久修改成长属性、资质或最大魔能；
- 不增加意图装备槽和被动槽；
- 不改变未装备意图的可用性；
- 不把状态层数、目标数或命中次数纳入百分比增幅；
- 所有效果在服务器权威状态中触发，客户端只应用同步结果。

### 10.2 意图数值增幅通道

通用被动与“集中咏唱”“余能转化”使用同一个直接数值增幅通道：

```text
最终直接数值 = Round(基础直接数值 × (100 + 总增幅百分比) / 100)
```

- 各来源使用加算，不使用乘算；
- 首版总增幅上限为 75%；
- 只修改伤害、护盾、治疗、主动回能；
- 多段伤害按每段基础值增幅；
- 增幅状态只有在至少产生一个直接数值效果时才消耗；
- 被取消、无目标或执行失败的意图不消耗次数型被动。

### 10.3 数量和阶段

| 池 | 数量 | 获得阶段 |
| --- | ---: | --- |
| 核心通用被动 | 8 | 阶段3必定获得1个 |
| 高级通用被动 | 4 | 阶段5抽中被动时获得1个 |

同一精灵不能重复获得相同被动。解锁只加入已学会库，不自动替换当前种族固有被动。

发布前必须验证：

## 15. 首版实施结果

1. 58个 `profileId` 已写入养成注册表；除不可捕获测试档 `base-game.99999` 外，每个形态固定默认1–3个固有意图。
2. 51个 `speciesId` 已各生成一个固有被动；多形态共享同一 `speciesId` 与同一被动ID。
3. 15个通用意图与12个通用被动已进入运行时注册表；升级五阶段从这些公共池生成并在捕获时固化。
4. 54个PVE固有意图均已设置1–3魔能与0–2冷却；回能/等待之外不再存在0消耗固有意图。
5. 当前种族被动首版采用“种族本能”模板：按默认配置的主类型提供10%直接数值增幅。每个种族仍有独立稳定ID，后续可逐个替换为专属机制而不迁移精灵存档。
6. 运行时表由生成器覆盖生成，评审时修改生成器与注册表源，不手工维护CSV副本。
