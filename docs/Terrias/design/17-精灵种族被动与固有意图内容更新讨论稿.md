> 状态：第二版讨论稿，未进入运行时实施。
> 日期：2026-09-18。
> 覆盖：当前正式 51 个种族、58 个形态；包含游戏主体种族与 Terrias 自有首领。
> 最新约束：精灵意图、被动、圣遗物等内容不增加额外战斗时点或内容专用 Hook；本轮不采用手牌联动。
> 状态表达约定：内容中的计数、层数、额度和准备态使用实际 Buff 表示，由现有意图流程推进；不是在 Buff 脚本中新增事件监听。本约定同样适用于圣遗物套装。
> 本版替代上一稿中依赖出牌、抽弃牌、死亡救援、伤害分担、全场状态增删等事件的方案。此前认可的是改编方向，不把旧稿的具体触发规则继续视为已确认需求。

## 1. 设计约束

当前同质化来自哈希分配被动、共享适配效果与高度重复的默认装配。解决它仍以“一个种族的被动、固有意图池、默认装配和选招规则”为单位，但差异必须在已有执行流程内表达。

- 种族被动继续占一个可替换的被动位置；意图装备上限三个，不增加常驻种族特性。
- 通用意图与被动主要保证外部精灵可用性，不擅自删除现有正式种族的通用能力资格。
- 同种族共用被动，各形态可以拥有不同意图池；移除种族被动后，默认主动组合仍可正常使用。
- 每位主人同时只有一只出战精灵；同一主人的其他携带精灵不作为必要触发者。
- 不为内容新增宿主 Hook、事件订阅、卡生命周期分发或独立计时器，也不为每个种族、被动、圣遗物注册监听。
- 不通过新增 Buff 脚本、代理事件或全场轮询绕开约束。已有原生状态只能在核实其受支持后复用，不另造隐含事件监听。
- 手牌联动整体退出本轮：不记录主人出牌、抽弃牌、手牌奇偶、诅咒牌数量，不回收或生成精灵工具牌。即使只在规划时读取手牌，也不将其作为替代方案。
- 来源敌人的招牌机制可以改编触发方式；保留镜像、操偶、开盒、金矿等主题，不要求逐字复刻敌人特性。
- 新意图、被动与圣遗物统一遵守这些要求。当前已经实现的功能保持原合同，本稿不扩大为删除现有事件或重构整个战斗框架。

### 表达差异的主要办法

目标选择、当次效果分配、有限资源转换、自己已执行意图的顺序、装备槽位、自己的冷却与魔能、以及规划时读取的当前生命/护盾/白名单状态。

差异可以改变作用对象、单体与群体、进攻与恢复之间的分配、付出和产出。没有新增事件不意味着只能改变伤害百分比。

### 已有外部入口不等于任意信息都可用

- [SpiritRuntime.RetireIfDead](../../../Terrias-Dev/Hooks/SpiritRuntime.cs) 先处理死亡清理，再调用训练与圣遗物的 `OnStatusHit(status)`。该调用只传入目标，不提供攻击者、伤害类型、真实生命损失或致命伤之前的拦截机会。
- 该入口同时由现有 `AfterHit` 和 `AfterStateChanged` 路由调用，不能仅凭函数名推定“每调用一次就是一次独立有效受伤”。
- 现有延迟治疗使用 `OnActorTurnCompleted`；现有出牌路由服务于部署/捕捉门禁。这些都不作为给所有新内容增设出牌反应、死亡救援、每回合反应的借口。
- 本版新增方案统一映射至 P/C/X/E/W，不扩大已有受击和回合完成入口的分发职责，也不为取得缺失数据补建来源监听。
- 因此旧稿的按伤害类型产金、致命伤复活、伤害分担、状态消退追击、全场死亡传播均撤回。当前低血检查只能在精灵活到自身执行机会时生效，不能宣传成即时救援。

### 计数与费用语义

- “一次行动”默认指一次成功提交的非等待意图。等待只有明确列出 W 的规则可以使用。
- 相位、包装次数、准备态随 E 推进，不随主人回合、UI 刷新、再次预览或换下推进。换下保留状态，现有战斗清理负责终结。
- 重算计划可以重新评估当前合法目标，不能重复扣费、付血、产金、重抽祝福或领取一次性收益。
- 复合意图按具体效果片段判断攻击、防护、恢复，而非只看总类型；同一意图最多领取一次声明的附加效果。
- 费用、主动回能、支付后的魔能奇偶必须采用同一份冻结计划与明确顺序，不能把执行前魔能误称为执行后余额。
- 当前状态只能说明“此刻有什么”，不能推断发生了多少次受伤、谁击破了盾、谁施加了状态或某次治疗溢出了多少。

### 计数统一使用机制 Buff

本节是新增设计约定，不表示当前实现已迁移。下文的“层数、计数、准备、铭记、魂壳”等内容状态按本约定落地。

- **以实际 Buff 为唯一计数来源。** 在精灵自身的权威状态上保存层数，名称、图标和说明表达获得、消费与上限；不能仍在 `PassiveState` 保存相同数值，再同步一个仅供显示的 Buff。
- **Buff 承载状态，现有流程负责推进。** P/C 读取层数并生成计划；X/E 在对应效果实际成功后增加、消费或清除；明确使用等待的规则才由 W 更新。不会在新增 Buff 的 Apply/Clear 脚本里注册出牌、受击、回合、死亡等监听。
- **默认不自动衰减。** 纯计数 Buff 的 `ReducePerTurn / ReducePerAttacked / ReducePerUse` 默认为 0，消耗规则由本次设计指定的现有步骤执行，避免宿主自动衰减与内容处理器各扣一次。具体字段行为在实施时按匹配的 Managed 验证。
- **准备态也可以是一层 Buff。** 例如牵线为 0/1，包装为 0 至指定上限，铭记与魂壳为有限层数。相位使用可读的互斥状态或明确的阶段 Buff，避免用多层含义不明的编码冒充玩家说明。
- **一次性完成态不能由“没有 Buff”推断。** 开盒后、魂壳用尽后，需要独立的一层已完成/已用尽机制状态或现有可靠初始化事实；不因计数归零、换下或重新召唤又补满。对有意义的内容完成态优先使用机制 Buff。
- **状态参与规则需要明确。** 机制计数默认不进入普通正面/负面层数加成、驱散、复制、转移或偷取范围。依靠现有分类与明确名单落实，不能只给它起一个“机制”名字便认为已受保护。
- **结构记录不伪装为层数。** 上一个目标 ID、上一意图片段等仍是有限结构数据；进度以 Buff 为准。原生意图冷却、行动游标、计划标识、网络幂等信息继续由现有运行时管理，它们不是新增的内容计数。
- **即时效果不强行 Buff 化。** 同一次意图中完成的消耗、治疗溢出、破盾与换算使用该次局部结果；没有跨行动状态就不为显示而反复创建、删除 Buff。
- **换下与同步仍有验收责任。** 主机保存真实 Buff，客机只读展示；返卡、重新召唤与战斗清理须保持计数。当前可见状态列表上限为 24 且参与返卡恢复，实施前必须保证机制 Buff 与原有状态都不会被裁剪静默丢失，不能直接假定现有展示快照就是完整持久载荷。
- **控制状态更新成本。** 合并同一意图内的增减与已有广播，避免逐层创建、重复刷新或给每个 Buff 独立同步。统一成 Buff 改善表示和控制，不代表已经证明性能更快。

套装层面的候选效果与状态示例见[圣遗物套装效果迭代讨论稿](18-精灵圣遗物套装效果迭代讨论稿.md)。

## 4. 全种族修订草案

每条来源描述指原敌人事实。以下被动、主动与默认组合均为本版候选；新增效果能否用当前 API 在现有调用中完成仍需核实，不能以效果处理器尚缺为由增加 Hook。

### 01 普拉提黏黏：削弱敌人后帮助主人

- speciesId: base-game.10001
- profileIds: base-game.10001
- 来源：无力化、活性化、涣散、看破；原配置没有独立自带特性。以原意图为基础补充种族规则。
- 被动草案：「黏附」：本次意图攻击或干扰的目标当前有无力时，在同一次意图中给主人一份小护盾；每次意图至多一次。无需等待目标之后出手。
- 意图池草案：黏液喷吐（无力）；活性化（自身直接治疗与已有自愈）；裹覆（给主人基础护盾，可转交部分自身现有护盾）；看破（易伤）。
- 默认与选择：黏液喷吐／活性化／裹覆。优先压制高攻击敌人；没有自身护盾仍可使用裹覆的基础部分。
- 选择价值：把先削弱、后保护的组合放在自己的行动链中；换入看破可以转向协助集火。
- 结算步骤：P/C/X/E。不增加内容专用事件订阅。

### 02 红心女仆：整理主人身上的异常

- speciesId: base-game.10002
- profileIds: base-game.10002
- 来源：退行诅咒会塞牌，另有看破与硬质化；原配置没有独立自带特性。把敌对塞牌转译为给主人整理手牌。
- 被动草案：「侍奉」：自己在本次意图中成功净化主人一种允许净化的负面后，给这次净化附加小护盾；不检测主人抽到、打出或弃掉什么牌。
- 意图池草案：整衣（净化主人一项既有负面并少量治疗）；看破（易伤）；硬质化（主人护盾与既有坚毅）；备茶（直接治疗）。
- 默认与选择：整衣／看破／硬质化。主人没有可净化负面且无需治疗时不选整衣；备茶可替换整衣。
- 选择价值：从照顾手牌改为照顾当前状态；与主教的固定轮替净化、乌娜的储备净化不同。
- 结算步骤：P/C/X。不增加内容专用事件订阅。

### 03 鼹鼠：主动掠夺不同目标

- speciesId: base-game.10003
- profileIds: base-game.10003
- 来源：盗贼、偷窃、逃跑、探囊取物与多段攻击。金币来自敌人身份时的受害者钱包，改编后不能假定敌方有玩家钱包。
- 被动草案：「摸金客」：自己本次攻击成功作用于尚未掠夺过的目标时，直接结算一份有上限的金币给主人；仅记录有限目标 ID，达到场次硬上限后停止记录与领取。
- 意图池草案：探囊取物（低伤，优先未掠夺目标）；蝶翼复切（集中输出）；潜掘（护盾并通过现有威胁机制降低自身受击倾向）；掘进突袭（消耗自己的潜掘准备，攻击并削去少量现有护盾）。
- 默认与选择：探囊取物／蝶翼复切／潜掘。金币只依据本次自己的实际攻击结果，不监听全场受击或死亡。
- 选择价值：为不同目标付出进攻机会获得旅程收益；与吞金兽消费自身护盾的经济方式区分。
- 结算步骤：P/C/X/E。不增加内容专用事件订阅。

### 04 灾厄先兆：压制当前最危险的敌人

- speciesId: base-game.10004
- profileIds: base-game.10004
- 来源：原意图主要为普通攻防与活性化，没有鲜明特性。以下威胁预兆属于补充设计。
- 被动草案：「灾兆」：规划时以当前攻击最高敌人为压制对象；本次干扰确实作用于它后，给生命比例最低的友方附加一份护盾。相同意图只附加一次。
- 意图池草案：灾兆凝视（既有无力或失格）；黯光（攻击并施加无力）；活性化（自身恢复）。
- 默认与选择：灾兆凝视／黯光／活性化。同攻击力时按稳定规则选择，不预测未来行动，不记录是谁伤害过主人。
- 选择价值：把压制目标与保护目标分开，面向输出集中在单个敌人的战斗。
- 结算步骤：P/C/X。不增加内容专用事件订阅。

### 05 猎食者：把自己的捕食变成防护

- speciesId: base-game.10005
- profileIds: base-game.10005
- 来源：原生血墙与普通攻防。追猎行为属于补充，不能声称原敌人已有猎物标记。
- 被动草案：「猎血成墙」：自己攻击一个规划时已受伤的目标后，根据本次自己的直接伤害结果形成有限自身护盾；不附带任何全场击杀奖励。
- 意图池草案：追咬（优先受伤目标）；撕裂（多段伤害）；血肉壁垒（基础自身护盾，行动前已有护盾时可用部分旧盾换治疗）。
- 默认与选择：追咬／撕裂／血肉壁垒。每个意图只结算一次捕食护盾；更换被动后血肉壁垒仍独立提供护盾。
- 选择价值：先制造伤口、再靠自己的攻击维持生存；多段不按段重复获得整份收益。
- 结算步骤：P/C/X。不增加内容专用事件订阅。

### 06 失心魔女：复演自己的上一段意图

- speciesId: base-game.10007
- profileIds: base-game.10007

## 6. 圣遗物与通用内容采用相同边界

圣遗物不是规避时点限制的另一条入口。现有静态属性、规划修正、意图提交与等待处理可以继续承担组合效果；已实现的受击效果按原有合同工作，本稿不借此新增伤害来源或事件分发。

本轮可讨论的套装方向包括：改变意图费用与收益分配、让当前护盾参与本次攻击、把本次直接治疗溢出用于防护、让自己的意图类型与冷却形成取舍。所有方案都要指出 P/C/X/E/W 中的实际位置。

本轮不采用“主人出牌时”“抽弃某牌时”“友方死亡时”“受致命伤前”“任意单位状态被移除时”等新触发。也不把这些规则改写为高频扫描来保留其原有效果。具体套装重做尚未展开，此处只确定共同约束。

## 7. 效率与正确性要求

1. **现有入口内也有成本。** 无新增 Hook 只限制架构扩张，不证明新增效果零开销。每次规划仅处理当前精灵的装备与有界目标，复用本次读取结果，不在各效果中重复扫描全场。
2. **事件分发规模不随内容数量增长。** 注册 51 个被动不等于战斗时遍历 51 个定义；只解析当前实际装备的被动和套装。不得逐帧扫描、按种族注册监听或为每个计数设定时器。
3. **局部结果不升级为全局历史。** 自己这次治疗的溢出、付血、破盾、状态移除可以在 X 内形成有限结果；其他来源的行为没有现成事实就不追踪、不推断。
4. **转化是实际支付。** 没有移除足够状态、护盾、生命或魔能，就不能领取完整产出。基础效果与可选转换分开，条件不成立时仍有可用动作。
5. **连击和协击在一个计划内有上限。** 不额外调用精灵行动、不复用任意敌人脚本、不重新触发自己的生成规则；逐段元素与已有套装收益一并计入强度。
6. **计划预览无收益。** 用实际提交标识限制一次性变化；重算、展示、换下、重新水合都不能复制进度和奖励。
7. **状态复用需核实。** 名称相同不代表适合敌方或精灵。复制/移除名单排除剧情、复活、永久属性和未知脚本；恢复抑制、伤害类型、减伤等找不到现有合适操作时，收敛效果而非补新事件。
8. **常量上限保持明确。** 每个个体只保留少量计数、标记或有限记录；没有足够目标就缩小效果，不建立待新敌人出现后无限重试的任务。
9. **验证实际热点。** 后续实施比较规划次数与耗时、效果提交量、状态广播量、分配和目标枚举；只在内容需要时选择检查，不为纯讨论稿构建产品。

| 按列表顺序挑默认组合 | 每个正式 profile 明确可学池与默认三槽，并检查移除种族被动后的可用性 |
| 未使用参数也计入“唯一机制” | 比较真实读取数据、目标、消耗、产出和意图组合；加入人工重复审查 |
| 内容扩张容易扩成 Hook 扩张 | 每项方案先标既有结算步骤和数据来源；所需信息不在现有调用中则改写方案 |
| 内容计数存于字典、再合成展示状态 | 计数与准备态改由实际机制 Buff 作为唯一来源；同步、返卡只保存其结果，实施时移除对应旧计数读写及重复展示 |
| 旧个体冻结能力计划 | 实施时一次迁移被替换能力，保留等级、资质、元素、归元、圣遗物与可保留装配 |

实施仍需同步描述、预览、主机结果与客机展示、内容 hash、存档映射和适当行为验证。新效果处理器不等于新增战斗时点；也不能用“只新增处理器”的说法掩盖处理器内部的新订阅。

本版已将 51 个种族的候选方案映射至既有内部步骤，覆盖关系与引用可做静态检查。数值与效果可用 API 尚未定稿，性能与实战平衡尚未验证。
