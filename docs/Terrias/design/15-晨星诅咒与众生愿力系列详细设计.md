# 晨星：诅咒与众生愿力系列详细设计

> 状态：已实现并进入 Terrias `0.5.2` 基线
> 整理日期：2026-08-18
> 所属卡包：`Terrias_terrias_cardpack_morning_star_overture`  
> 视觉规范：`docs/Terrias/design/14-晨星诅咒与众生愿力卡面主题设计.md`  
> 已批准视觉基准：`tools/previews/card-art/morning-star-curse/morning-star-elegy/04-final-256.png`

## 1. 设计目标

本系列扩展【晨星：序曲】的资源循环，将游戏主体的诅咒从单纯的牌库污染转化为可以保留、承受、焚毁、反转和供养的战斗资源。

完整玩法循环为：

```text
获得或正常抽取诅咒
        |
        +-> 保留在手牌 -> 黑日十字 -> 愿力持续成长 -> 回合结束恢复
        |
        +-> 精准焚毁 -> 逆转术式 / 恶兆转移
        |
        +-> 批量焚毁 -> 众生渡 / 晨星：回光
        |
        +-> 承受抽到效果 -> 晨星：悲歌提供星辉

永久获得众生相祝福 -> 众生愿 -> 愿力 -> 黑日十字恢复
```

本系列必须同时满足：

1. 诅咒的原始负面效果真实发生，不将整个体系改造成无代价抽牌；
2. 玩家能选择将诅咒留在手中供养愿力，或提前焚毁换取当前回合收益；
3. 愿力与星辉分别接入游戏主体和晨星体系，不新建功能重复的资源；
4. 主体、其他启用MOD与Terrias定义的有效诅咒均可参与；
5. 所有运行时状态按玩家隔离，多人联机下不共享手牌、愿力、祝福或诅咒统计；
6. 只在诅咒变化、卡牌使用和回合边界计算，不增加逐帧扫描。

## 2. 已锁定规则

### 2.1 诅咒识别

- 一张卡的有效 `Tag` 包含精确令牌 `Curse` 时，视为诅咒；
- 同时读取基础 `data.Tag`、运行时 `Vars.Tag` 与 `Vars.SpecialTag`；
- 主体诅咒、Terrias诅咒、其他启用MOD诅咒采用相同规则；
- `*` 开头的隐藏技术牌不进入随机诅咒池，但已经实际出现在战斗区域的隐藏诅咒仍可被处理；
- `Unusable`、`Retain`、`Burnout` 等词条不影响诅咒身份；
- 不通过中文名称、文本描述或卡牌类型字符串判断诅咒。

### 2.2 战斗区域

本系列只处理当前玩家拥有的三个区域：

| 区域 | 定义 | 参与内容 |
| --- | --- | --- |
| 手牌 | 当前可见手牌与主体等待队列中仍属于该玩家的牌 | 全部卡牌与黑日十字 |
| 抽牌堆 | 当前战斗抽牌区 | 晨星：回光 |
| 弃牌堆 | 当前战斗已使用/丢弃区 | 晨星：回光 |

同一张运行时卡牌实例只能计数一次。批量效果在结算前先生成区域快照并按实例去重，避免焚毁事件改变区域后造成漏算或重复。

### 2.3 愿力

- 复用游戏主体 `buff_VowPower`；
- 愿力不随回合减少；
- 黑日十字不会消耗愿力；
- 众生愿按不同祝福ID计数，不按祝福实例或来源重复计数；
- 愿力可以继续被游戏主体或其他MOD的愿力相关内容读取；
- Terrias不写入或复用主体【七咒之戒】的 `SevenCursePower` 状态。

### 2.4 星辉

- 复用 `Terrias_terrias_starlight`；
- 每次增加仍通过现有星辉服务处理10/20/30层阈值；
- 批量获得星辉必须一次提交最终增量，避免同一事务中重复扫描或重复刷新HUD；
- 星辉达到30层后的消除、星辰祝福和序曲牌奖励沿用现有晨星规则。

### 2.5 焚毁事务

焚毁类卡牌统一遵守以下顺序：

```text
生成候选快照
-> 玩家完成必要选择
-> 逐张请求主体焚毁
-> 每张成功焚毁后发出一次标准 BurnCard 事件
-> 记录实际成功数量
-> 完成该卡自身的汇总收益
```

- 焚毁失败的卡牌不提供反转、愿力、星辉、抽牌、魔能或目标减益；
- 其他祝福、遗物和MOD可以正常监听每张诅咒的标准焚毁事件；
- 一张卡牌的焚毁事件无论位于哪个区域都只能发布一次；
- 汇总收益按实际成功焚毁数计算，不按选择数或预扫描数计算；
- 批量焚毁期间产生的新诅咒不加入当前事务。

## 3. 遗物：黑日十字

### 3.1 数据定义

| 字段 | 值 |
| --- | --- |
| 建议ID | `black_sun_cross` |
| 稀有度 | 3阶 |
| PackBelong | `Terrias_terrias_cardpack_morning_star_overture` |
| 效果 | 回合开始时，手牌中每有1张诅咒，获得1层愿力；回合结束时，每有1层愿力，恢复1%最大生命值。 |

### 3.2 回合开始

- 在玩家完成本回合基础抽牌后的 `StartRoundEnd` 时点统计；
- 统计当前手牌中具有有效 `Curse` 标签的卡牌实例数量；
- 每张诅咒增加1层愿力；
- 同名复制牌分别计数；
- 本回合后来获得的诅咒不会追补愿力，需留到下一回合；
- 黑日十字自身不生成诅咒。

### 3.3 回合结束恢复

```text
恢复量 = floor(最大生命值 * 当前愿力 / 100)
```

- 不设置恢复比例上限；
- 不消耗愿力；
- 愿力大于0且存在已损生命时，最低恢复1点；
- 恢复量最终不超过已损生命；
- 中间乘法使用 `long` 并饱和，避免高愿力溢出；
- 玩家死亡或状态不可恢复时跳过；
- 多个黑日十字按遗物唯一性只注册一个结算器，避免重复监听。

### 3.4 构筑意义

黑日十字把“暂时不处理诅咒”变成长期收益。玩家需要在以下选择中权衡：

- 将诅咒留到下回合，增加愿力并获得更高的永久回合恢复；
- 立即通过逆转术式或众生渡处理，换取当前战斗节奏；
- 等待晨星：回光一次性清空三个区域，获得愿力和星辉；
- 主动使用晨星：悲歌制造诅咒，提高后续愿力增长，但承受正常抽到效果。

- 自动战斗按反转配方价值从高到低选择，默认选择全部净正收益诅咒。

```text

```

- 等阶从卡牌有效 `Rarity` 读取并限制在1-4；
- 无效或缺失等阶按1阶处理；
- 已登记ID始终优先于兜底；
- 配方以数据驱动注册表保存，后续可以为其他MOD提供可选扩展，而不修改CSV脚本。

### 4.2 晨星：回光

| 字段 | 值 |
| --- | --- |
| 建议ID | `morning_star_afterglow` |
| 稀有度 / 费用 | 3阶 / 3费 |
| 词条 | `Retain,Burnout` |
| BaseScript | `CommonCardItem` |
| 效果 | 焚毁抽牌堆、手牌、弃牌堆中的全部诅咒，获得对应层数的愿力与星辉。 |

### 结算规则

1. 同时快照三个区域并按卡牌实例去重；
2. 快照必须排除正在结算的晨星：回光自身；
3. 按抽牌堆、手牌、弃牌堆的稳定顺序焚毁；
4. 每张诅咒发布标准焚毁事件；
5. 设实际成功焚毁数为 `N`；
6. 一次性获得 `N` 层愿力；
7. 一次性获得 `N` 层星辉。

该卡是全域清算终结牌。它不触发逆转术式的反转配方，但可以触发祈愿者、黑日十字以外的标准焚毁监听。

### 4.3 恶兆转移

| 字段 | 值 |
| --- | --- |
| 建议ID | `omen_transfer` |
| 稀有度 / 费用 | 1阶 / 0费 |
| 词条 | 无额外静态词条 |
| BaseScript | `CommonCardItem`，使用显式任意目标选择 |
| 效果 | 焚毁1张诅咒卡牌，对任意目标施加2层无力与2层易伤。 |

### 交互顺序

1. 选择1张手牌诅咒；
2. 选择任意存活战斗目标，允许自己、友方或敌方；
3. 先焚毁选中诅咒；
4. 仅在焚毁成功后，对目标施加2层无力和2层易伤。

没有手牌诅咒时不可使用。目标死亡、离场或选择失效时取消后半效果，不向其他目标自动转移。

### 4.4 众生相

| 字段 | 值 |
| --- | --- |
| 建议ID | `all_beings_aspect` |
| 稀有度 / 费用 | 3阶 / 2费 |
| 词条 | `Burnout` |
| BaseScript | `CommonCardItem` |
| 效果 | 随机获得1个尚未拥有的众生相祝福，整场冒险有效。 |

### 众生相祝福池

```text
dream_talker       梦呓者
delirious_talker   妄语者
forgotten_one      遗忘者
wisher             祈愿者
unspeakable_one    难言者
withered_one       枯槁者
blind_one          盲目者
```

### 永久性与去重

- 从当前玩家尚未拥有的祝福中等概率抽取；
- 通过主体玩家祝福写入路径加入当前冒险；
- 获得后跨战斗、地图节点和存档恢复保留，冒险结束时随运行局正常结束；
- 不写入账号级永久解锁；
- 多人模式下只修改使用者自己的角色表，并走主体角色同步；
- 祝福脚本在本场战斗中立即生效；若主体无法即时挂载，则在获得后显式初始化一次Fight行为；
- 七种祝福全部拥有时，改为获得3层愿力，卡牌不会空放。

### 4.5 众生愿

| 字段 | 值 |
| --- | --- |
| 建议ID | `all_beings_wish` |
| 稀有度 / 费用 | 2阶 / 1费 |
| 词条 | `Burnout` |
| BaseScript | `CommonCardItem` |
| 效果 | 每有1个不同的众生相祝福，获得1层愿力。 |

- 只统计上节7个稳定祝福ID；
- 相同祝福无论来源和实例数均只计1次；
- 统计使用瞬间的当前冒险祝福；
- 获得量范围为0-7；
- 一次性增加最终愿力层数；
- 0个祝福时允许使用但无收益，卡牌仍焚毁。

### 4.6 众生渡

| 字段 | 值 |
| --- | --- |
| 建议ID | `all_beings_ferry` |
| 稀有度 / 费用 | 2阶 / 2费 |
| 词条 | 无额外静态词条 |
| BaseScript | `CommonCardItem` |
| 效果 | 焚毁手牌中所有诅咒，抽取等量卡牌、获得等量魔能。 |

### 结算规则

1. 在自身离开手牌后快照剩余手牌诅咒；
2. 逐张焚毁并统计实际成功数 `N`；
3. 焚毁全部完成后，按主体规则正常抽取 `N` 张牌；
4. 一次性恢复 `N` 点魔能；
5. 回复允许超过本回合基础魔能上限，沿用主体 `ChangePower` 行为；
6. 新抽到的诅咒正常触发抽到效果，但不加入本次焚毁事务。

没有手牌诅咒时仍可使用，但只支付费用且无后续收益。

### 4.7 晨星：悲歌

| 字段 | 值 |
| --- | --- |
| 建议ID | `morning_star_elegy` |
| 稀有度 / 费用 | 2阶 / 1费 |
| 词条 | 无额外静态词条 |
| BaseScript | `CommonCardItem` |
| 效果 | 流失当前50%生命；每实际流失最大生命值的7%，正常抽取1张随机诅咒并获得2层星辉。 |

### 生命流失与次数

```text
实际流失 = floor(当前生命值 / 2)
触发次数 = floor(实际流失 * 100 / (最大生命值 * 7))
```

- 当前生命为1时实际流失0，不由卡牌本体直接致死；
- 触发次数限制在0-7；
- 使用 `long` 进行乘法，避免高生命值溢出；
- 先完成一次生命流失，再固定本次触发次数；
- 后续诅咒造成的额外生命损失不增加本卡触发次数。

### 正常抽取诅咒

每次触发按以下顺序独立处理：

1. 从当前启用、可物质化、非隐藏的有效诅咒池等概率选择1张；
2. 将该诅咒按主体正常抽牌流程送入手牌；
3. 执行其 `DrawScript`、抽牌事件、卡牌获得压力与UI表现；
4. 成功完成该次抽取后获得2层星辉；
5. 若抽到效果导致使用者死亡，停止后续触发；
6. 手牌已满时遵循主体正常抽牌处理，仍执行主体定义的抽到与溢出流程。

同一张悲歌可以重复抽到相同诅咒。随机池需要缓存并在游戏数据目录版本变化时失效，不在每次触发时全表扫描。

## 5. 众生相祝福迁移

### 5.1 遗忘者

【遗忘者】从【日耀：烬冠天幕】迁移至【晨星：序曲】：

- `Data/Blessing.PackBelong` 改为 `Terrias_terrias_cardpack_morning_star_overture`；
- Text备注从日耀祝福改为晨星祝福；
- Fight行为从 `SolarBlessingService` 移入 `MorningStarBlessingService`或新的众生相祝福服务；
- ID、名称、图标、等阶和当前效果保持不变；
- 旧存档中已持有遗忘者时无需迁移ID；
- 日耀卡包不再将遗忘者加入奖励池，晨星卡包开始提供该祝福。

### 5.2 现有效果边界

本详细设计只锁定新卡牌、黑日十字和遗忘者归属迁移。以下七个祝福的当前战斗效果暂不在本轮改写：

| 祝福 | 当前初始诅咒 | 当前每回合效果 |
| --- | --- | --- |
| 梦呓者 | 幻梦 | 1层自愈 |
| 妄语者 | 思维紊乱 | 2层锋锐 |
| 遗忘者 | 遗忘 | 随机2层锋锐或强韧 |
| 祈愿者 | 幻痛 | 2层愿力 |
| 难言者 | 隐疾、亏空 | 流失5生命并获得1魔能，可致死 |
| 枯槁者 | 腐朽 | 恢复已损生命1%，至少1点 |
| 盲目者 | 恐惧感 | 额外抽1张牌 |

先前关于“压制抽到效果、负面转嫁、主动打出诅咒”等方案保留为后续候选，不随本系列卡牌自动实施。

## 6. 系列组合与数值示例

### 6.1 满血悲歌

玩家最大生命100、当前生命100：

```text
实际流失 = 50
触发次数 = floor(50 * 100 / 700) = 7
结果 = 正常抽取7张随机诅咒，并在各次成功后总计获得14层星辉
```

诅咒的抽到效果逐张发生，玩家可能在全部7次完成前死亡。

### 6.2 众生渡

使用后手牌快照含5张诅咒，其中4张成功焚毁：

```text
实际焚毁数 N = 4
抽4张牌
获得4魔能
```

失败的1张不计入收益。

### 6.3 晨星：回光

抽牌堆3张、手牌2张、弃牌堆4张诅咒，去重后实际焚毁8张：

```text
获得8愿力
获得8星辉
```

若其中一张在事务前已被其他效果移除，则按7张结算。

### 6.4 众生相与众生愿

玩家永久拥有梦呓者、遗忘者、祈愿者，并由本场众生相获得盲目者：

```text
不同众生相祝福数 = 4
众生愿获得4层愿力
```

下一场战斗仍保留4个祝福。

### 6.5 黑日十字无上限恢复

最大生命200、当前愿力135：

```text
理论恢复 = floor(200 * 135 / 100) = 270
实际恢复 = min(270, 已损生命)
```

愿力不消耗，下一回合继续按新的总层数结算。

## 7. 交互优先级

## 9. 代码边界

建议实现结构：

```text
Terrias-Dev/Infrastructure/TerriasIds.cs
  卡牌、遗物、祝福池与运行时字段ID

Terrias-Dev/Mechanics/MorningStarCurseCatalog.cs
  诅咒识别、随机池缓存、逆转配方注册表、众生相祝福池

Terrias-Dev/Mechanics/MorningStarCurseService.cs
  区域快照、批量焚毁事务、悲歌抽取、愿力与星辉汇总

Terrias-Dev/Mechanics/MorningStarCurseFormula.cs
  纯数值公式、次数、恢复、兜底配方

Terrias-Dev/Scripting/CardScripts.cs
  7张卡牌的短入口与处理器注册

Terrias-Dev/Scripting/RelicScripts.cs
  黑日十字Fight入口

Terrias-Dev/Mechanics/MorningStarBlessingService.cs
  遗忘者迁移与众生相祝福当前战斗初始化

Terrias-Dev/Hooks/MorningStarCurseRuntime.cs
  玩家归属、回合生命周期、角色表变更与清理
```

规则：

- `Scripting`不直接引用`Hooks`；
- 区域访问和焚毁调用通过`GameApi`包装；
- 不修改主体卡牌基础`data`，运行时字段写入`Vars`；
- 随机池通过`TerriasConfigIndex`或共享游戏数据目录缓存；
- 祝福永久写入走主体角色表API，不新建平行存档；
- 事件通过现有路由和token注册，战斗重开时旧token失效；
- 不让Endless Abyss专用临时诅咒服务成为通用卡包依赖，应抽取语义中立的诅咒目录能力或在晨星域内独立实现。

## 10. 多人规则

- 卡牌选择、手牌统计、愿力、星辉和祝福获得均属于使用者；
- 不统计队友手牌、抽牌堆和弃牌堆；
- 恶兆转移的目标可以是任意同步战斗状态，但诅咒来源必须属于使用者；
- 众生相永久祝福通过本地玩家角色表提交，并沿用主体角色表同步；
- 非持有者客户端只接收主体卡牌、Buff、状态和角色表同步结果，不独立重算随机祝福或诅咒池；
- 随机选择由拥有者权威路径产生一次结果，不能由每个客户端各自抽取；
- 远端观察到焚毁事件时不得重新发起汇总收益。

## 11. 性能规则

- 黑日十字每回合只扫描一次手牌；
- 晨星：回光只在使用时快照三个区域；
- 众生渡和逆转术式只扫描当前手牌；
- 诅咒随机池按游戏数据目录版本缓存；
- 众生相祝福池固定7个ID，使用HashSet差集；
- 批量Buff和星辉通过一次最终提交刷新；
- 选择、卡面与手牌刷新进入现有帧调度和卡牌刷新队列；
- 禁止`Update()`轮询诅咒数量、愿力、祝福或区域变化。
