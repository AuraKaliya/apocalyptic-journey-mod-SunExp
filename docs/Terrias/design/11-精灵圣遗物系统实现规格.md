# 精灵圣遗物系统实现规格

> 状态：当前实现规格  
> 更新日期：2026-08-29  
> 行为权威：`Terrias/spirit.artifact.registry.json`

## 1. 用户合同

圣遗物属于账号级精灵收藏档案。账号共享一套最多 1000 件的仓库；每只精灵分别保存生之花、
死之羽、时之沙、空之杯、理之冠五个装备槽。一个圣遗物实例最多被一只精灵装备，换装采用
原子转移，当前战斗使用开战时冻结的配置。

圣遗物页与属性、养成、归元同级，但四页都属于当前选中精灵的工作区，不是精灵仓库窗口的
全局导航。仓库左侧精灵列表在切入圣遗物页后保持可见。页面上部展示当前精灵五槽和总词条，
下部提供账号级目标套装、抽取、全部及五部件筛选、虚拟化仓库、强化、锁定、装备和分解。
悬停卡片显示名称、星级、等级、主词条、合并后的副词条、每次投掷值、套装说明和当前装备者。

## 2. 权威数据

`SpiritCollectionDocument` 是唯一持久化聚合根：

- `ArtifactInventory` 保存圣遗物实例、最多20套账号级玩家预设、精粹、目标池、目标套装、星级保底、目标命定、抽取事务和待确认结果；
- `SpiritInstance.ArtifactLoadout` 保存五个实例引用、修订号和哈希；
- 圣遗物实例不反向保存装备者，装备者由精灵槽位索引计算，避免双写；
- 收藏档案 schema 11、圣遗物仓库 schema 2 将旧档案一次迁移到账号级玩家预设模型，不保留精灵级预设或平行旧写入路径。

抽取使用持久化操作令牌。先保存预生成十连，再把令牌写入账号级
`GameRuntimeData.Variables` 并通过 `Truth` 属性把令牌与余额在同一主体存档写入中提交，最后把
十件物品和待展示回执一次提交。该事务不依赖冒险中的 `RoleTable`。中断恢复时，有扣费令牌
就完成入库，没有令牌就取消预生成结果。

## 3. 词条与强化

圣遗物有 1–3 星和 Lv.1–5。Lv.1 只有主词条；升至 Lv.2、3、4、5 时分别投掷一次副词条。
重复副词条允许存在，界面合并总值并保留例如 `魔力 +7（2+3+2）` 的投掷明细。

- 生之花主词条固定为生命；
- 其余四槽在魔力、精神、幸运、感知、速度中各 20% 选择主词条；
- 生命、魔力、精神、幸运、感知、速度副词条各 15%；
- 魔能上限、开局超凡各 5%；
- 每次词条数值在注册表对应星级的闭区间中等概率取整数。

强化消耗依次为 `10 / 20 / 30 / 40` 精粹，总计 100。分解基础返还为 1 星 1、2 星 3、3 星 8，
并返还已投入精粹的 70%，向下取整。锁定或已装备物品不能分解；批量分解为全有或全无事务。

## 4. 抽取与目标套装

十连固定消耗 160 真理之晶，抽取前需要至少 10 个空仓位。星级基础权重为 65% / 30% / 5%；
每个十连至少一件 2 星，连续 30 抽没有 3 星时强制 3 星。

首批为三个固定池、每池四套。目标套装占池内 50%，其余三套平分 50%。3 星未命中目标后，
下一件 3 星强制命中目标；更换目标会清除目标命定，但不重置星级保底。目标选择使用该套生之花图标。

## 5. 首批套装

首批启用角斗士的终幕礼、追忆之注连、黄金剧团、逐影猎人、绝缘之旗印、饰金之梦、海染砗磲、
长夜之誓、千岩牢固、华馆梦醒形骸记、深林的记忆、翠绿之影。每套恰好五个部件并提供累计
2/4 件效果。首批不启用 1 件套，防止强制散件；运行时仍支持未来的 1 件阈值。

套装定义和数值只来自 `spirit.artifact.registry.json`。行为由
`SpiritArtifactEffectHandlerRegistry` 的稳定处理器 id 执行，不接受任意脚本字符串，也不为每套
单独注册宿主事件。

## 5.1 玩家预设与批量清理

玩家账号最多保存20套圣遗物预设，预设属于账号而不属于任何精灵。每套预设必须保存生之花、
死之羽、时之沙、空之杯、理之冠五个不同槽位的具体圣遗物 UID；不复制词条数据，也不保存
精灵 UID。同一实例允许被多套预设引用，保护集合取所有预设引用的并集。

预设引用的圣遗物仍计入1000件仓库容量并继续显示在仓库，但具有派生预设保护：不能分解，
不进入【全选】候选与候选数量。删除或覆盖最后一个引用后保护立即消失。锁定、装备和预设保护
均由后端事务再次校验，批量分解保持全有或全无，不静默跳过失效项。

应用预设不弹出装备冲突确认。事务先验证五个实例和槽位，再自动卸下当前精灵原有五件、从
其他精灵身上卸下预设所需实例并完整装备到当前精灵；当前精灵原装备回到账号仓库。所有变化
只保存一次，任一步失败则没有精灵发生变化。每个实际变化的精灵只递增一次圣遗物配置修订，
最后统一刷新哈希。重复应用当前已生效预设是无修订的幂等操作。

仓库多选是瞬态 UI 状态，只保存实例 UID，不保存格子对象。筛选支持多星级、等级段、套装、
主词条和【仅可清理】；部件继续由六个分类页控制。【全选】作用于完整筛选结果而非可见格子，
并排除锁定、已装备和预设保护实例。批量锁定/解锁使用幂等的设置操作，分解前显示数量与预计
精粹并二次确认。

## 6. 属性与独立伤害乘区

结算顺序为：

1. 等级、资质、归元和圣遗物四本源加成生成本源值；
2. 本源换算生命、攻击、护甲、魔能和速度，并应用归元星级；
3. 圣遗物生命、护甲、魔能上限、速度平值追加；
4. 意图固定值与属性倍率生成基础效果；
5. 精灵养成/固有被动进入现有加法池，最高 75%；
6. 所有适用的圣遗物套装伤害加成在套装内部相加，然后作为独立乘区乘一次，安全上限 50%；
7. 融化、蒸发、超载、激化等主反应倍率；
8. 游戏原生超凡、目标防御、减伤和护盾结算。

套装乘区只增强直接意图伤害。烈绽放、超绽放、扩散传播等独立公式伤害不继承，除非未来效果
明确声明。锁定计划保存套装前数值、乘区基点、贡献效果 id 和套装后数值；多人客户端不重算。

## 7. 战斗与多人

最多五件物品的星级、等级、主副词条、注册表哈希、套装效果和聚合属性进入有界战斗快照。
主机验证部件唯一性、槽位、词条数量、数值范围、套装阈值和哈希。精灵的等待、受击、意图执行、
海沫、凯旋等状态复用 `CompanionBattleState.PassiveState`，撤回并重新召唤时保留，同场战斗结束清理。

开局超凡通过初始 `SpiritCardBattleState.VisibleStatuses` 进入现有精灵 Buff 同步通道，不增加第二条
Buff 或网络快照路径。协议 22 是加入圣遗物战斗快照后的唯一当前协议。

## 8. UI 与资源

仓库使用可见行加 overscan 的行环形对象池，收藏数量只改变 content 高度。滚动在同一逻辑行内不绑定；
跨越一行时只把离开视口的行旋转到另一端并绑定新进入的 9–10 个格子，跳跃超过整个池时才执行一次
有界全量绑定。图标通过
`TerriasResourceCache` 按进入视口的单元加载。祈愿使用独立 `ScreenSpaceOverlay Canvas`、RenderTexture 和
`VideoPlayer`；准备完成后播放，可跳过，播放失败或超时直接展示已经入库的结果。

精灵仓库运行在游戏的原生 `Upper Canvas`（ScreenSpaceCamera）上。该相机平面不支持运行时插入可见的
Override Sorting 子 Canvas；装备、仓库和目标覆盖层必须继续使用原生 Canvas 层级。性能优化依靠行环形
池、持久装备视图、固定字号和增量绑定完成，不保留第二条子 Canvas 渲染路径。

视频阶段右上角显示透明背景、纯白文字的【跳过 ›】，按 Esc 与点击该按钮都只进入结果页。结果页右上角
显示透明背景、纯白文字的【确认并返回 ×】，底部同时显示操作提示；点击按钮或按 Esc 会且只会执行一次
待展示回执确认、释放覆盖层并返回圣遗物页。关闭后覆盖层不再拦截射线，原生 UI 必须立即可点击。

账号仓库使用 `76×88` 固定格子、`72×84` 圆角卡面、6 像素间距和最多 10 列；列数由实际 viewport
宽度在 5–10 之间动态计算，窗口尺寸变化时合并到下一帧更新 content 高度和池化格子位置，剩余不足
一列的宽度平均分配到左右 padding，不拉伸卡面。卡面面积小于旧版
108×126 卡片的一半。卡面以完整白色圆角底板承载 16 像素等级区；上方 68 像素稀有度图像区
左上/右上圆角为 6、左下近方角为 1、右下圆角为 14，因此白底会自然露出而不是额外覆盖一条胶囊。
图像区只保留图标、星级和锁定角标，装备者以右上角圆形精灵头像表示，不在卡片上写入名字。

Hover 描边是卡面顶层固定的 2 像素白色圆角线，只承担瞬时交互反馈。选中反馈改为卡面下方的
`76×88` 金白实心光晕板；中心被不透明的 `72×84` 卡面完全覆盖，因此不会遮住卡面或在抗锯齿边缘
产生缝隙。光晕周期固定为 2 秒，并用 `p(t)=0.5-0.5*cos(2πt/2s)` 把透明度从 0.58 过渡到 0.96、
缩放从 1 过渡到 1.018；同一选中单元的虚拟化重绑不得重置相位。Hover 视觉根节点在 120 毫秒内
放大到 1.03，离开在 90 毫秒内恢复，卡面与底层光晕始终一起缩放。

总词条区只有一个 ScrollRect 和一套复用行模板。无选择时绑定整套总词条；点击仓库卡或非空装备槽
后绑定该圣遗物详情，再次点击同一实例或点击仓库/装备区空白处时取消选择并恢复总词条。Hover 不再
改变详情。点击另一件圣遗物直接切换；详情区和操作栏保持选择；筛选、目标、抽取、精灵或分页上下文
变化会清除选择。强化、锁定后保留仍存在的实例，分解使实例消失时确定性清除。选择变化只重绑可见
卡片的选中态、单一预览和操作栏，不重新查询仓库，也不重建立绘或装备槽。

装备区标题为不占布局高度的左上覆盖文字，运动画布使用装备面板扣除 8 像素内边距后的完整高度，从而
扩大轮盘半径。精灵立绘中心与轮盘中心重合；五个槽位中心始终是一个圆的内接正五边形顶点。圆面绕
屏幕水平 X 轴向用户倾斜 15 度：下方 Z 深度为正、上方为负，左右同高槽位具有相同缩放；绝不再以
屏幕 X 坐标判断远近。图标与文字共用同一个槽位缩放根并保持正向，不随圆周自转。半径按实际画布和
投影后的垂直边界计算，使圆的上下界加半个槽位后各保留约 10 像素。无选择时轮盘采用间歇式平滑轮转：
静止 3.2 秒后，在 0.8 秒内以 ease-in-out 顺时针换位 72 度，再进入下一次静止；五次共 20 秒完成一圈。
静止阶段不写 RectTransform、缩放或透明度，避免低于一个屏幕像素的连续位移导致图文采样错位。点击
非空装备槽后按最短
顺/逆时针路线在 0.28–0.48 秒内 ease-out 到下方用户前景点并暂停，取消选择后继续。立绘与五槽属于
一个统一 `EquipmentMotionRoot`，共享位置、缩放和透明度更新。
五个槽位和立绘在页面创建时一次生成；换装只增量绑定 UID、Sprite 和颜色，不销毁对象，也不重置轮盘
相位。轮盘控制器以固定五槽、零逐帧分配的方式更新位置、统一缩放、透明度和必要的深度顺序；标签关闭
Best Fit 并使用固定字号。紧凑槽位为 `56×56`，使用 42 像素已装备图标
和 36 像素空位图标。目标套装按钮左侧固定 32 像素生之花图标；“目标套装”和粗体套装名在同一行
分列，套装名在右列居中，最右侧为独立箭头且不使用中点连接文本。

目标套装选择器属于圣遗物工作区的独立安全覆盖层，不参与页面 VerticalLayout。遮罩填满工作区但不
覆盖左侧精灵列表；窗口按实际工作区在 `480–680` 宽、`400–480` 高范围内居中，宽度达到 620 时使用
4 列，否则使用 3 列。点击遮罩或关闭按钮释放覆盖层和射线；面板内部点击由独立拦截面保持打开。

装备区右上角提供【我的预设 N/20】。预设管理器是圣遗物工作区内的单一覆盖层，不覆盖左侧精灵
列表，也不创建 Override Sorting 子 Canvas。窗口在标准布局使用 `680×430–500`，紧凑布局宽度
为工作区减40且最小520；左侧是 `180/210` 宽的60像素高可滚动预设行，只显示已创建预设并使用
该预设生之花图标。右侧只绑定当前预设的五个 `50/60×76` 迷你部件、套装效果、总词条、装备
分布和转移提示。当前、其他精灵使用、分散、仓库待用和失效状态均由实例所有者索引派生。

【保存当前搭配】直接写入当前精灵完整五槽；【新建/编辑】在右侧切换五槽编辑器，部件选择复用
现有虚拟化仓库格子与独立池键，不建立第二套仓库查询。覆盖和删除需要二次提交；未保存编辑在
关闭时需要再次确认。应用成功后关闭覆盖层、恢复装备轮盘并增量刷新装备、总词条与仓库保护标记。
预设列表最多20行，全部可常驻且无逐帧更新；只有部件选择器使用行环形池。

运行时资源为：

- `splash-background-runtime.png`；
- `resultcard-bg-runtime.png`；
- `祈愿动画-runtime.mp4`，H.264 + AAC；
- `空素材/生之花.png`、`死之羽.png`、`时之沙.png`、`空之杯.png`、`理之冠.png`；
- 原 WebP 和原视频保留为非运行时来源，唯一运行时路径由 `visual.registry.json` 声明。

关闭过场时停止播放器、解绑事件、释放 RenderTexture、禁用射线并通过共享 UI 安全组件清理
GraphicRegistry。未确认结果保留在账号档案；再次打开圣遗物页可重新查看并确认。

## 9. 验收

自动化覆盖注册表 3 池/12 套/60 部件、资源存在性、词条权重、强化曲线、伤害独立乘区、保底边界、
无活动 `RoleTable` 的账号扣费与回滚、动态 5–10 列及平衡边距、目标选择器响应式边界、轮盘边界、
内接正五边形等边、下方为正的 Z 深度投影、3.2/0.8 秒自动轮转边界、单次 72 度换位、最短焦点路线、
选择切换/取消/实例消失协调、批量 UID 选择/筛选全选/预设保护、20套上限、重复引用、完整五槽校验、
账号预设应用的跨精灵自动转移/幂等/所有受影响修订、schema 10→11与仓库1→2迁移、
预设主从布局紧凑/展开边界、行环形池单行/反向/跨池跳跃边界、
目标命定、哈希顺序稳定、档案迁移、多人快照范围和架构方向。

Unity 实机还需验证：760×620、1080p、2K、超宽；1000 件滚动；双行紧凑卡、白底异形图像区、
头像角标、点击选择驱动的总词条/详情切换、底层余弦呼吸光晕、浅 3D 轮盘焦点、自动旋转流畅度与
图文同步；静置时无仓库刷新、滚动单行绑定上限、换装相位连续；五种空槽图标；单行目标套装；
响应式目标选择覆盖层；账号预设滚动、创建、编辑、覆盖、排序、删除、自动转移和保护解除；
多选跨分类保留、全选候选数量、筛选、批量锁定/解锁、分解确认；9–10 列宽屏仓库；连续十连；视频跳过和
失败回退；装备转移；锁定/分解；连续开关页面；过场关闭后原生 UI 可点击；单机、主机和客机数值一致。
