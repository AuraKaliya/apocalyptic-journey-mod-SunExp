# DPS 伤害归属与精灵专属意图池

> 状态：当前实现合同
> 更新日期：2026-08-26
> 关联：[精灵收集、培养与出战系统](08-精灵球捕获与精灵召唤.md)

## 1. 伤害归属

精灵和投影造成的伤害必须归属于其拥有者玩家和角色。原始战斗账本可以保留召唤物、敌人和未知来源用于审计；伤害结算、MVP 和队伍总伤害只读取真实玩家阵容。

统一事件 CG 不读取本模块的账本、排名或缓存。它从当前冒险队伍独立冻结有序参与角色，并只把角色 ID、布局位置、背景和逻辑资源 ID 等处理后数据交给共享 CG 展示链路。因此关闭或移除 DPT 统计不得影响特殊胜利、失败和冒险结算 CG。

归属解析顺序：

1. 根据来源实例查找当前 `IStatusManager`；
2. 敌人列表或敌人父对象优先判为敌方；
3. 读取召唤物公开的 `OwnerPlayerId/OwnerStatusId`；
4. 映射到冒险开始时冻结的真实玩家身份；
5. 无法解析的来源保持未知，不伪装为玩家。

`TempDataManager.RoleStatusMap` 只用于身份路由和发送者所有权检查，不作为真实友方阵容来源。

## 2. 精灵意图来源

`spirit.intent.registry.json` schema 3 包含：

- 54 个 PvE 复合意图；
- 12 个 PvP 预留意图；
- 每个 profile 的安全攻防后备池。

PvE 复合意图保留原敌人卡的名称、卡面、图标、动作、冷却和优先级信息，但运行时卡牌 ID 固定为 Terrias 适配器。原始敌人 `InitScript/TargetScript/UseScript` 永远不会由精灵执行。

真实效果在计划阶段解析为 `CompanionIntentPlan.ResolvedEffects`，再通过以下白名单族执行：

- `damage.single/multi/all`；
- `block.single/all`；
- `heal.single/all/delayed`；
- `buff.apply`；
- `magic.recover`、`numeric.prepare`；
- `pvp.reserved`，当前 PvE 不产生效果。

## 3. 装备与后备边界

正常战斗只从开战冻结的最多 3 个已装备意图中选择。后备处理分两层：

1. 外部 MOD profile 在永久档案中冻结基础攻击、基础防御和本源分支，不需要战斗临时猜测；
2. 有效装备全部损坏或无法解析时，只临时注入基础攻击和基础防御。

后备层不能恢复完整原生敌人池，也不能因为某一倾向暂时没有目标而绕过冷却、魔能或装备限制。

## 4. 选择与执行

主机按以下过程生成计划：

1. 从装备中分别构造攻击倾向与防御倾向候选；
2. 排除冷却中、魔能不足、无合法目标或 eligibility 不满足的意图；
3. 按 profile 攻防权重和动态优先级选择；
4. 锁定目标、数值、消耗、冷却和被动修正；
5. 提交计划并广播表现；
6. 执行成功后扣除魔能、启动冷却并推进被动状态。

无合法意图时执行等待，恢复魔能并继续推进回合，不能阻塞 Partner 队列。

## 5. Buff 与状态同步

主机对精灵施加 Buff 时，实际 `StatusManager` 和 `BuffDic` 是战斗权威。用于客机 Hover 的 `VisibleStatuses` 是只读表现快照，只同步 Buff ID/层数和种族机制进度，不在客机重新执行 Buff 脚本。

主动换下时，可见 Buff 列表会随 `SpiritCardBattleState` 返回；权威端再次召唤时恢复实际 Buff，客机继续使用只读表现快照。

## 6. 网络顺序

Partner 协议 21 使用：

- `BattleEpoch` 拒绝跨战斗迟到包；
- owner generation 拒绝旧实体覆盖新实体；
- revision 保证状态单调；
- token 保证召唤、换下和返卡幂等；
- intent/training registry hash 拒绝内容不一致；
- 可见状态最多 24 项，卡牌战斗状态和被动字典均有数量与数值上限。

客户端不会执行精灵 AI 或补算伤害。权威帧延迟时，客户端只等待或软释放当前队列调用。

## 7. 当前验证

`spirit` 门禁分别验证内容、注册表和纯行为：

- 每张来源敌人卡进入 PvE、PvP 预留或显式后备分类；
- 每个 PvE 意图都有合法目标、处理器和描述槽；
- 装备上限、冷却、换下状态和 Loadout hash；
- 外部兼容 profile 在 Lv.1 同时具备攻防行动；
- 空损坏配置只使用有界基础后备；
- 51 个种族被动全部使用已登记处理器且机制签名不同。

逐敌人意图事实见自动生成的[游戏主体敌人与精灵专属意图总表](10-游戏主体敌人与精灵专属意图总表.md)。
