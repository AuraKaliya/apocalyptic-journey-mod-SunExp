## 2. 三包视觉语言草案

现有色系备忘：

| 卡包 | 色系短语 | 建议翻译为生成约束 |
| --- | --- | --- |
| 星火 | 晨金 + 清青 | 暗底上使用晨金主体、清青小面积冷光，表现“第一缕光、点燃、保存名字、日耀启动”。 |
| 烬冠 | 骨金 + 绯红 | 暗底上使用骨金轮廓、绯红火核，表现“聚焰、自燃、王冠、轮转、崩塌”。 |
| 天幕 | 灰青 + 灰薰紫 | 暗底上使用灰青大形、偏灰且稍亮的灰薰紫腐蚀/烟雾阴影，表现“场地天幕、烟蚀、日蚀、扩散与净化”。 |

全局卡面约束：

- 每张卡只保留一个居中的符号化主体，不做完整场景。
- 主体颜色限制在卡包色系的 2-3 个对象色，背景保持深色。
- 禁止文字、数字、可读符文、UI 边框、卡牌边框、人物场景、复杂远景。
- 先保证 128x128 可读，再考虑笔触、像素化和去光影。
- 同包内要避免主体重复：例如“日轮”“皇冠”“火焰”需要通过形态差异区分。

## 3. 【日耀：星火】逐卡主体设定

星火包的共同母题是“启动日耀体系”。它应该比另外两包更轻、更清、更有晨光感；即便有燃烧，也偏向白金/晨金的点燃和净化，而不是绯红爆燃。

## 6. 后续生成前需要你优先批注的点

1. 是否认可三包色系继续沿用“晨金+清青 / 骨金+绯红 / 灰青+灰薰紫”。
2. 是否允许在“名字”主题卡中使用无字纸片、封蜡、名签、空白档案等元素。
3. 是否允许“王冠”在三个包中重复出现，但分别用“授冕 / 崩落 / 威光折射”区分。
4. 是否需要把 `*` 开头的 Burnout 或衍生性质卡牌做出统一的“缺口、断边、燃尽痕”。
5. 是否把 30 张正式卡全部重绘，还是先选每包 2-3 张代表牌做样张校准。

## 7. 生成阶段的硬性验收清单

- 输出为 `512x512` PNG。
- 文件模式为 `RGB` 或 `RGBA`。
- 缩到 `128x128` 时主体仍可读。
- 路径必须匹配 `SunExp/Data/Card/sunexp.csv` 的 `Icon` 字段。
- 不允许文字、数字、水印、UI 框、卡牌边框、人物场景。
- 生成后需要制作三包 contact sheet，横向检查同包一致性与跨包辨识度。
