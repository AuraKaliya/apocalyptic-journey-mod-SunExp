# SunExp 同步共识：无尽之渊、卡包、乌娜余烬与洛奈尔

记录日期：2026-07-07

本文记录当前针对 SunExp、AuraToolsExp 与共享层同步模型的具体功能共识。它不是玩家介绍文档，而是后续开发、重构、review 和 skill 蒸馏时的设计依据。

## 2. 无尽之渊

### 2.1 深渊震荡

联机时，【深渊震荡】由主机玩家选择。非主机玩家不需要显示只读选择面板，只需要看到最终结算提示或结果。

理由：

- 深渊震荡会改变注视等级、卡牌焚毁/绝灭、遗物损失等玩法级别状态。
- 这些状态属于共享冒险进程，不应由多个客户端各自计算。
- 当前方向应贴近游戏主体的联机模型：主机/服务端负责权威计算，然后通过已有网络/快照机制让客户端显示结果。

开发含义：

- 主机路径：打开震荡选择面板、校验选项数量、应用结果、广播结算结果和必要状态快照。
- 非主机路径：接收结算结果，显示最终提示/结果，应用或刷新权威状态；不发起震荡选择、不重复计算代价。
- 需要对重复网络包做幂等处理，避免重复提示、重复扣除或重复写入账本。

### 2.2 地图、怪物与玩法级影响

地图、怪物、路线、楼层推进和类似玩法级影响在联机时由主机玩家/服务端权威计算，并全队应用。

【怪物注入】应与游戏主体的战斗初始化/动态加敌思路保持一致：

- 初始战斗敌人：游戏主体在战斗初始化阶段基于 Level/EnemyIds 等数据完成各端构建，服务端登记权威状态。
- 战斗初始化后的动态加敌：只应由主机/服务端发起；客户端通过游戏原生 RPC/同步接收敌人，不应各自计算并主动发起。

开发含义：

- SunExp 的无尽阶段额外敌人注入应放在主机/服务端权威路径。
- 非主机客户端在该 Hook 中应跳过计算和发起，只等待游戏主体同步。
- 去重标记应服务于权威写入侧，避免主机重复注入；客户端不应因为本地标记造成与原生同步冲突。
- SunExp 应维护独立的敌人注入接口和服务，用来承载主机判权、注入计划、日志和去重。具体加入敌人的底层动作贴近游戏主体动态加敌方式，但不能把 `CmdAddEnemy` 等原生细节散落在玩法 Hook 中。

### 2.3 里程碑奖励

【里程碑奖励面板】由个人独立查看和选择，不进行 SunExp 自定义跨玩家同步。

理由：

- 奖励选择属于玩家个人收益与构筑修正，不是共享地图/玩法状态。
- 每个玩家应能独立选择补遗物、拿特殊卡、清除焚毁或主动添加绝灭等个人奖励。

开发含义：

- 奖励 UI、选择和领取记录按玩家作用域处理。
- 不新增“全队同步选择”的协议。
- 奖励最终落地仍应尊重游戏主体已有的个人牌组、遗物和角色状态保存/同步机制。

## 3. 卡包

卡包部分以当前仓库文件为准。后续清理历史对话时，不应把旧对话中的卡包归属、命名或设计描述当成高于当前文件的事实来源。

开发含义：

- 修改卡包时优先读 `SunExp/Data/*`、`SunExp/Text/*`、CSV 调用的 C# 入口和当前文档。
- 若历史讨论与当前文件不一致，以当前文件为基准，再由新的显式设计决策覆盖。

## 4. 乌娜与余烬

【余烬】BUFF 本身不是乌娜专属机制，而是通用玩家状态：

- 它在整场冒险中存在。
- 它不应随单场战斗结束自动重置。
- 联机时必须区分所属玩家，避免 A 玩家余烬覆盖或污染 B 玩家余烬。

【乌娜】只控制乌娜被动收益：

- 余烬的持久化和联机归属是通用玩家状态。
- 乌娜的治疗、最大生命提升等被动收益才由乌娜激活条件控制。

开发含义：

- 余烬保存/读取/同步服务应按“玩家作用域冒险状态”建模，而不是按“乌娜角色私有状态”建模。命名采用 `EmberAdventureState` 方向，旧的 `WunaPersistentEmber` 只作为兼容读取来源。
- `SavePersistentEmber` 不应因为当前角色不是乌娜就拒绝保存余烬。
- `OnEmberConsumed` 这类消耗后收益应拆分为两层：先保存通用余烬变化，再在乌娜激活时应用乌娜被动收益。
- 战斗开始时恢复余烬的路径应从乌娜职业初始化中抽离为通用生命周期动作，乌娜初始化只保留乌娜专属监听和被动逻辑。

## 5. 洛奈尔

当前未发现需要调整的核心同步或设计冲突点。暂不改变洛奈尔现有机制。

开发含义：

- 不主动重构洛奈尔。
- 后续若改动洛奈尔，只按具体问题进入分析，不把乌娜/余烬的通用状态迁移扩大到洛奈尔体系。

## 6. 后续开发原则

- 先分类：共享进程、玩家作用域状态、展示事件、初始化注册、工具配置。
- 再定权威：主机/服务端、绑定发送者的玩家、工具本地配置，或注册者 owner identity。
- 再定时序：启动注册、工具配置覆盖、模式进入、战斗初始化、行动/事件 Hook、战斗结束、模式退出。
- 最后定去重：命令 token、状态 sequence/version、展示 eventId、Hook 标记、生命周期清理。

本轮涉及的首要实现点是：无尽之渊额外敌人注入的主机权威化，以及余烬持久化从乌娜专属状态迁移为通用玩家作用域状态。
