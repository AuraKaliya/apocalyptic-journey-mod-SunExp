# SunExp 后续开发路线图：协作、可读性与乌娜成长

本文记录 2026-06-23 这轮头脑风暴后的取向收束。当前优先方向为：

- 多人协作特化
- 美术与音频 polish
- 危险提示
- 局外成长节点，尤其是乌娜专属成长

核心判断：SunExp 后续不宜继续单纯扩大卡池，而应把“高风险日耀体系”做成一个队伍能读懂、能协商、能共同承担，并且能围绕乌娜长期成长展开的系统。

## 设计主轴

SunExp 现有玩法已经围绕日耀、聚炎、炽灼天幕、圣冕显化、燃烧反噬、名字与 Solar Memory 路线形成了明确气质。后续开发应从“更多日耀牌”转向“更清晰的日耀体验”：

1. 让风险可读：玩家应该知道自己为什么即将出事。
2. 让风险可协作：多人模式下，风险应成为团队资源调度，而不是只让某个玩家独自爆炸。
3. 让风险有情绪重量：视觉、音频、Boss 阶段、终局事件应共同强化白昼压迫感。
4. 让风险有长期回报：乌娜专属局外成长负责承接 Solar Memory、隐藏 Boss、名字记录和协作工具。

一句话方向：

> 日耀从个人高风险爆发体系，升级为团队共同管理的灾厄资源系统。

## 同类游戏与 Mod 启发

本轮外部参照主要提炼机制方向，而不是照搬内容。

- [Downfall](https://store.steampowered.com/app/1865780/Downfall__A_Slay_the_Spire_Fan_Expansion/) 的启发：大型扩展真正有辨识度的部分不是卡牌数量，而是新角色、新路线、新 Boss 与原游戏结构之间的反转。
- [Packmaster](https://steamcommunity.com/sharedfiles/filedetails/?id=2920075378) 的启发：模块化卡包可以堆出巨大内容量，但必须有清晰包身份、性能边界和选择管理，否则玩家很快只感到噪音。
- [Across the Obelisk](https://store.steampowered.com/app/1385380/Across_the_Obelisk/) 的启发：多人卡牌游戏的乐趣来自角色分工、队伍事件选择、道具归属和可预期的团队风险。
- [Monster Train: The Last Divinity](https://news.xbox.com/en-us/2021/04/01/monster-train-the-last-divinity-dlc-available-now/) 的启发：可选压力资源可以让玩家主动换取收益，但压力必须被清楚展示，并且能被玩家规划。
- [Griftlands](https://store.steampowered.com/app/601840/Griftlands/) 与 [Inscryption](https://blog.playstation.com/2022/07/07/psychological-horrors-stack-in-devilish-deck-builder-inscryption/) 的启发：牌、剧情选择、身份记录和氛围反馈可以互相咬合，让机制本身产生叙事感。

对 SunExp 来说，最值得吸收的是：

- 不追求无限扩牌，优先强化路线、身份、风险与反馈。
- 多人内容应制造“协商”，而不是简单全队增益。
- 压力资源必须有清楚的 UI 与音画阈值。
- 局外成长最好解锁玩法解释、路线工具和协作能力，避免变成纯数值膨胀。

## 多人协作特化

多人方向的目标不是给队友加几张强力辅助牌，而是让日耀风险进入团队决策。

建议围绕四种团队职责设计：

- 承灼者：主动接收队友燃烧、反噬或白昼压力，换取护盾、治疗或后续爆发。
- 守名者：保护名字记录、终局资源或 Solar Memory 进度，在隐藏 Boss 与结局线上承担长期价值。
- 引燃者：主动提高全队收益与敌我燃烧，但同步推高危险阈值。
- 收束者：在高危阈值前把燃烧、圣冕、日耀或聚炎转换成防御、抽牌、净化或撤退窗口。

多人机制优先做“工具型小批量”，不要第一版就大规模扩卡。可以先尝试：

- 一张承灼牌：转移一名队友即将结算的部分燃烧到自己，随后获得护盾或日耀。
- 一张守名牌：本场战斗内保护一次关键资源损失，但提高下一轮白昼压力。
- 一件多人遗物：队友触发日耀高危阈值时，乌娜获得一次收束机会。
- 一个 Dusk 协作事件：在 Solar Memory 中让 Dusk 选择偏向“替人承灼”或“保存名字”。

实现边界：

- 共享进度、路线、名字记录和多人结算应由服务端权威推进。
- 客户端只负责本地表现、提示、音画反馈和玩家作用域状态。
- 多人同步相关逻辑应延续当前 Solar Memory runtime 的防御式写法，避免一个玩家的表现错误中断整体流程。

## 危险提示

危险提示是四个方向里最应该优先做的基础体验。SunExp 的问题不一定是“太难”，而是风险链条可能不够透明。玩家可以死于反噬，但不应该死于不知道自己为什么会反噬。

建议先实现四类提示：

1. 燃烧结算预警：显示下回合自己预计承受的燃烧、自燃或真实伤害压力。
2. 圣冕反噬预警：提示当前是否处于安全爆发窗口，以及离高危窗口还有多远。
3. 全队危险预警：多人模式下显示哪名队友即将因 SunExp 机制进入危险阈值。
4. 名字与终局预警：进入隐藏 Boss、Solar Memory 终局或名字焚毁事件前，提示会消耗或改变什么。

原则：

- 核心危险提示不应锁在乌娜成长里；可读性是基础体验。
- 乌娜成长可以解锁更完整的日志、图鉴解释、回放记录或高级摘要，但不能让未解锁玩家看不懂风险。
- 提示要短，优先展示“下一次危险”和“可采取行动”，避免写成长教程。

第一版可以做成轻量层：

- 战斗内 buff/card 描述追加动态危险文本。
- 高危阈值触发短提示、颜色变化或小图标。
- 多人时增加队友危险摘要，不强迫打开大面板。

## 美术与音频 Polish

美术音频 polish 不应泛泛地“全部重做”，而应绑定危险状态和关键体验节点。

优先 polish 的对象：

- Solar Memory 标题、地图节点、Boss 入口与终局界面。
- 圣冕显化、炽灼天幕、聚炎、自燃、名字焚毁等高频高危状态。
- 乌娜与 Dusk 的关键协作时刻。
- 隐藏 Boss、结局、局外成长 UI。

视觉建议：

- 低危：余烬、暗金、黄昏边缘光。
- 中危：日斑、裂纹、白金灼痕、缓慢扩散的天幕纹理。
- 高危：白昼过曝、冠冕尖刺、名字被烧空的负形轮廓。

音频建议：

- 为 Solar Memory 战斗与 Boss 增加 BGM 或 BGM layer。
- 为危险阈值加入短促 sting，而不是长语音刷屏。
- 为乌娜低血量、圣冕高危、名字损失、Dusk 承灼分别预留 cue。
- 控制触发频率：同类危险提示应有冷却，避免多人局中音频拥挤。

当前 `SunExp/audio.registry.json` 已有乌娜若干语音 provider，但还没有形成完整的 BGM 或危险阈值音频体系。后续 polish 可以先从 registry 扩展和触发条件整理开始。

## 乌娜专属局外成长

局外成长应服务 SunExp 的长期目标：让玩家通过反复推进 Solar Memory、击败 Boss、保存名字和完成多人协作，逐步理解并驾驭日耀体系。

不建议把乌娜成长做成纯数值加成树。更推荐四支主题：

### 余烬支

主题：燃烧转化、承灼、风险回收。

示例节点：

- 余烬共鸣：队友因日耀效果获得燃烧时，乌娜获得少量日耀或聚炎相关收益。
- 烬衣预修：每场战斗第一次进入自燃高危时，给出小额护盾或一次减伤。
- 回火练习：解锁一张承灼候选牌或一件承灼遗物进入奖励池。

### 名册支

主题：Solar Memory 记录、名字保存、隐藏 Boss 与结局线。

示例节点：

- 守名祷文：Solar Memory 开局保留一个名字线索，但本轮白昼压力略微提高。
- 残名索引：解锁名字相关图鉴，显示已保存、已焚毁和未知记录。
- 无名者回声：隐藏 Boss 前提供一次额外确认或准备事件。

### 圣冠支

主题：圣冕窗口、爆发控制、反噬警告。

示例节点：

- 圣冠校准：第一次进入圣冕高危阈值时触发明确警告，并提供小额保护。
- 冕下余光：圣冕窗口结束时保留一部分收益，但下一次反噬提示提前出现。
- 崩落演算：解锁更详细的炽冕崩落伤害预估。

### 同行支

主题：多人协作、Dusk、队伍提示。

示例节点：

- 同行誓约：多人模式下显示全队 SunExp 危险摘要。
- 黄昏牵引：每场战斗一次，Dusk 可以替一名队友承受部分燃烧结算。
- 共燃默契：队友触发日耀高危收益时，乌娜获得一次收束或援护选项。

成长资源可以来自：

- Solar Memory 层级推进。
- Boss 或隐藏 Boss 击败记录。
- 保存名字、完成结局、避免名字焚毁。
- 多人模式下完成承灼、援护或守名行为。

## 推荐开发顺序

### 阶段 A：危险提示 MVP

目标：让玩家看懂 SunExp 的主要死亡链条。

交付物：

- 燃烧/自燃/圣冕/炽冕崩落的基础预警。
- 多人队友危险摘要的最小可用版。
- 名字与终局消耗前确认提示。

这是最小成本、最大体验收益的阶段。

### 阶段 B：乌娜成长骨架

目标：先把长期成长入口、状态保存、节点定义和 UI 骨架立起来。

交付物：

- 8-12 个第一版节点。
- 四支主题结构：余烬、名册、圣冠、同行。
- 与 Solar Memory、Boss 记录、名字记录的基础联动。

第一版节点应偏工具、解释、解锁和轻量保险，避免堆永久数值。

### 阶段 C：多人协作第一批机制

目标：验证“承灼 / 守名 / 引燃 / 收束”的团队分工是否好玩。

交付物：

- 2-3 张多人协作候选牌。
- 1-2 件多人协作遗物。
- 1 个 Dusk 或 Solar Memory 协作事件。
- 服务端权威推进的共享进度与同步保护。

### 阶段 D：美术音频第一轮 Polish

目标：让高危状态、Boss、终局和成长 UI 拥有统一反馈。

交付物：

- 高危状态图标/边框/色彩规则。
- Solar Memory 或隐藏 Boss 的 BGM/sting 入口。
- 乌娜与 Dusk 的危险阈值 cue。
- 局外成长 UI 的标题、按钮、节点视觉规范。

## 风险与边界

- 不要把基础危险提示做成成长奖励；否则新玩家仍然看不懂系统。
- 不要第一版大规模扩卡；先验证多人协作模型。
- 不要让局外成长直接抬高过多数值；优先解锁工具、路线、解释和一次性保险。
- 不要让音频 cue 在多人局中过度触发；同类事件需要冷却。
- 不要把多人共享进度交给客户端各自推进；共享 Solar Memory、名字和成长奖励必须有权威来源。
- 不要让美术 polish 脱离机制阈值；每个视觉变化都应回答“它在提示什么风险”。
